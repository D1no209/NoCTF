# AWDP 结束轮次与配置更新审计

日期：2026-09-08。审计基线：`39676044`。

本次只读取本地源码并运行本地隔离测试，没有连接生产或测试服务器，没有推送、部署或操作业务数据。

## 已在本地复现的问题

### 1. 比赛结束后轮次明细缺失，但总分仍有数值

`LeaderboardFactProjectionReader.BuildAwdpWindow` 与 `NormalizedScoreboardProjection` 各自实现有效比赛时钟到实际时间的反向转换。所有 Running 时间段关闭后，两者错误地回退到比赛开始时间，加上扣除累计时长后的剩余量。

例如：每轮 60 秒，在运行 100 秒时结束。第 2 轮理论终点为有效时间 120 秒，旧实现将实际终点算成开始后 20 秒，而不是结束时刻 100 秒。数据库明细查询的结束条件因此提前，30 秒和 70 秒的提交均未进入明细；总分读取走独立汇总路径，仍为两次处罚的 -14 分。

真实 PostgreSQL 回归在修复前失败：最后一轮 EndAt 比正确时间早 80 秒。修复后同时断言最后一轮终点、两条轮次明细、明细合计 -14、窗口外得分 0，全部通过。

整轮结束还有另一处差异：明细查询始终用 `floor(运行时长 / 轮长) + 1` 计算最新轮，而归一化榜单在结束时不增加这一轮。刚好结束于第 50 轮时，读取窗口会从第 2 轮开始，遗漏应在当前 50 轮窗口内的第 1 轮记录。新增 3000 秒结束的数据库回归覆盖该条件。

### 2. 历史轮次窗口可能被前端拒绝

Redis 发布序号允许大于投影时间戳。历史窗口重建使用时间戳作为快照版本，但没有继承当前榜单发布序号。前端的旧响应保护因此可能拒绝合法历史窗口，并持续提示版本尚未同步。

已用发布序号比生成时间高 10 的用例复现。修复后历史窗口继承来源发布版本，保留自己的结构版本；工作人员和选手视图同步修正。

## 源码确认并补测的更新链路缺口

- `CompetitionConfigurationStore` 保存模式配置后没有记录 `CompetitionUpdated`，无法触发现有排行榜失效、合并投影和实时推送链路。
- `ChallengeConfigurationStore` 保存题目规则具有同样问题，涉及默认／覆盖分数、处罚等配置。
- 两处关系数据库分支使用 `ExecuteUpdateAsync`，只在非关系数据库分支调用 `SaveChangesAsync`。因此不能仅凭发送消息就保证事件、AWD 推进消息和 Outbox 一同提交。
- 普通排行榜仅监听推送；AWDP 无新提交、无业务事件时不会主动读取下一轮，匿名查看者也没有 Hub 连接。
- 选手状态接口在恰好整轮结束时仍多报一轮。
- 已结束比赛的旧错误榜单缓存没有时间边界失效条件；仅替换代码可能继续读取错误缓存。

以上是本地源码及测试结论，不冒充具体生产比赛的日志结论。没有访问用户反馈的线上页面，未单独证明“所有题目列标题完全消失”的每一种路径；本次确证的是轮次时间反向、明细漏读以及更新通知缺失。

## 修复行为

1. 使用 `AwdEffectiveRunningClock.ToWallTime` 统一反向转换，封闭的最后时间段不再回退到 StartAt。部分最后一轮收敛到停止／结束边界；暂停中的倒计时保持既有冻结规则。
2. 结束后的明细窗口与排行榜采用相同最新轮计算，仍保留最多 50 轮和历史窗口导航。
3. 比赛模式和题目规则保存均在同一事务中记录现有类型的变更事件，再保存事件与真实 Outbox，提交后调用提交后分发方法。无新事件类型、无新队列、无同步重算塞入 HTTP 请求。
4. 沿用 Worker 现有失效、500 毫秒合并和全量投影链路，发布新的 schemaRevision 与快照版本。
5. 普通排行榜监听生命周期变化，并在 AWDP Live 活跃轮次期间每 10 秒兜底刷新。已结算、冻结或隐藏视图不使用该轮次轮询。中控大屏保留原有全屏刷新，显式关闭新增轮询，避免双重请求。
6. 中控大屏已结算轮次倒计时固定为 0；选手状态整轮结束时不多报下一轮。
7. 添加仅用于榜单缓存包的 AWDP 格式标记。旧缓存缺少标记时自动从事实重建，包括无新事件的已结束比赛。该标记不是数据库列、持久化修订字段或周期调度字段。
8. 历史窗口保留当前发布代次，避免被前端版本保护误拒绝。

没有更改权限、参赛事实、计分公式、比赛结束清理策略或实际 Runtime 生命周期。

## 轮次配置变更的计分影响

现有设计始终用当前配置和原始事实全量重算，没有保存每轮配置快照。比赛中把 60 秒改为 120 秒，会同时改变历史动作所属轮次、完成轮数、累计攻防分、处罚结算时机、排名及题目当前分值，不只是改变前端倒计时。

本次保留这个既有语义。测试明确验证：有效时间 130 秒、首轮已成功攻击时，60 秒轮长有两轮结算共 200 分；改为 120 秒轮长后仅一轮结算共 100 分。如果产品希望“仅对未来轮次生效”，需要另行确定历史配置生效语义，不应在显示修复中暗改规则。
