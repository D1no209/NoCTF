# AWD 规则修正与实施规范

本规范仅适用于 AWD。AWDP 的 Break、Fix、Patch、Runtime、Checker 回执和计分语义不变。共享契约只能增加 AWD 专属分支，不能用 AWD 状态重新解释其他赛制。

## 一 目标与交付顺序

先分离轮次、发行和检测事实，再实现计算与界面。业务事实仍由 GameplayFact、ChallengeFlag 和关系化配置承载；不新增 Submission、ScoringEvent、历史裁定结果表或通用任务表。迁移由 EF CLI 生成。

1. 规则及数据基础：独立比赛轮次、有效配置、规则生效事实、Store、发行身份、执行与结算状态。
2. Flag 链路：安全派生、持久发行、两种投放、历史义务、跨轮验证、接收幂等、暂停及收官。
3. Checker 链路：结构化证据、健康分类、同轮重检、回执期限、待裁定和人工处理。
4. 积分：五种预设、受控自定义组合、预算分摊、结算、解释、规则变更和重投影。
5. 契约及界面：管理配置、选手规则与历史、公开大屏、SDK、Checker 模板。
6. 验证：关系和消息集成测试、其他赛制回归、前端架构与真实浏览器检查。

每阶段以可运行行为及测试验收，不把未接入生产路径的类型或计算器视为完成。AWD 无正式旧赛数据兼容要求；迁移不得删除其他模式数据。本地原子提交，不推送或部署。

## 二 状态的准确含义

健康、任务执行、启用状态、攻击成果和结算状态是不同维度。

| 健康结论 | 必需证据 | 不代表什么 |
|---|---|---|
| OK | 当前连接、规定业务、本轮应执行的 Flag 操作与必需历史读取全部通过 | 无漏洞、未被攻击、漏洞已修复 |
| MUMBLE | 已能正常连接，但目标侧当前业务或当前 Flag 操作失败 | 服务一定离线、攻击一定成功 |
| OFFLINE | 有充分证据证明目标侧无法正常建立连接 | 所有超时、Runner 或平台网络异常 |
| RECOVERING | 当前检查已通过，但仍有应由选手服务保存的历史 Flag 不可读取 | 正在重启、部署、上传 Patch、响应慢或仍受攻击者控制 |
| INTERNAL_ERROR | 平台、Checker、调度或缺失证据使本次结论不可信 | 选手服务故障或最终零分 |

已连接后的请求超时必须根据证据归因，不能仅按异常名称分类。平台漏发、任务从未派发、题目尚未启用时的历史缺失，不产生选手历史保存责任。若上一轮已确认因目标服务故障而写入失败，则该发行仍具有既定历史义务；当前恢复且该义务未满足可以是 RECOVERING。

一次检查保留各项证据。判定不能用枚举大小或固定优先级抹掉已知信息：已知连接失败可以形成目标故障证据，但另一 Store 的平台异常仍须保留，不能据此伪造完整 SLA 结论。RECOVERING 必须先有可信的当前检查通过证据。

任务执行状态为待检测、执行中、完成、无法判定；结算为暂定、最终、待裁定、明确豁免。未启用属于资格/服务启用状态。新轮次不把上一轮健康结论当成本轮结果；上次可信状态仅作为带时间标签的历史信息。

有效目标 Flag 被其他队伍提交，表示规则认可的攻击成果。它不证明持续控制、当前离线或实际窃取时刻。OK 与攻击成果可以同时存在。没有有效提交只能说明未观察到符合条件的成果。

## 三 默认值与配置来源

| 参数 | 默认 |
|---|---|
| 加固 / 轮间间隔 | 0 秒 |
| 轮长 | 180 秒 |
| Flag 接收寿命 | 5 轮，包含发行轮 |
| 历史读取窗口 | 跟随接收窗口，允许解除联动 |
| Store / 每 Store 每轮 Flag | 1 / 1 |
| ATK / DEF 泄露损失 / SLA 题目预算 | 50 / 100 / 100 |
| SLA | OK=1、RECOVERING=0.5、MUMBLE=0、OFFLINE=0、INTERNAL_ERROR=null |
| 额外处罚 / 保密性奖励 | 关闭 / 0 |
| 检查间隔 / 单次超时上限 | 30 秒 / 30 秒 |
| 内部错误重检 | 最多 2 次，间隔 5 秒，受原轮执行预算约束 |
| SLA 结算 | 轮末计划检查及其合法重试 |
| 暂停 | 冻结有效竞赛时钟，暂停发行及新攻击接收，结束时间等长顺延 |
| 结束 | 关闭新接收，完成已可靠接收的提交及未决结算 |
| 规则修改 | 下一轮生效，旧 Flag 保留发行规则 |
| 积分 | 内部高精度，完整分组后向零取整；默认允许负分 |

比赛默认由题目规则按 nullable 字段覆盖，0 是显式值。界面、规则说明和计分解释使用同一有效规则解析器并显示来源。题目定义拥有 Store、投放方式和 Checker 能力；普通主办方继承，不能配置密码学密钥或算法降级。

## 四 三个时间窗口

轮次是独立的比赛事实，不能再从 ChallengeFlag.ValidUntil 推导。其身份在同场比赛所有题目间一致，包含实际起止、有效竞赛时间位置和适用规则。调度接管从关系事实恢复，不持久化 next-run 协议。

Flag 接收和历史读取分别保存发行时策略，支持按轮数或有效竞赛时长。第 10 轮发行、寿命 5 轮，在第 10..14 轮有效，第 15 轮开始失效；边界统一为 [start,end)。改轮长不把旧 Flag 的寿命简单重算为“当前轮长乘旧轮数”。

暂停冻结轮次和两个有效时间窗口。已耐久接收的提交继续处理。轮间间隔启用时同样不发行、不接收并冻结有效时间；网络连接不会因此自动被隔离。比赛时长和总轮数是互斥结束策略；计划的间隔不计入有效比赛时长。最后一个不足完整轮长的轮次保留攻击事实，SLA 显式标为未完成，不伪造完整奖励。

默认结束立即关闭新提交。高级尾期只接收停止发行前的旧 Flag，并受公开的绝对截止时刻限制；它不延长历史读取义务。处理使用服务端可靠接收时间，队列延迟不改变有效性。已关闭窗口后不允许通过客户端时间回填提交。

截止时间由同一个轮次时钟供调度、发行、检测和提交接收使用。总轮数策略忽略计划结束时间的时长预算，最后一轮之后不增加空档；时长策略从计划结束时间扣除已暂停区间得到有效预算，再加入各轮已确定的空档。自动结束即使执行延迟，也记录计算出的实际结束时刻，尾期不从调度器醒来的时间重新起算。每个轮次保存当时的提交尾期策略，终轮创建后或比赛已停止时不再读取可编辑默认值，赛后修改不能重新开放接收。尾期保持停止时的接收轮次和有效时间位置，已到期的 Flag 不重新生效；人工提前结束将被截断的轮次明确标为不完整。

新启用题目、Store 或队伍从实际启用 slot 承担义务。平台漏掉的轮次记录为缺失，不补造当时已投放或检查的事实。轮次变化不重启 Runtime。

## 五 Flag 发行及投放

业务题目、Runtime 命名服务、Flag Store、发行实例和攻击提交是五种对象。多个 Store 不增加大屏服务器数量。

发行唯一键为比赛、CompetitionChallenge、队伍、生成轮次、Store、发行序号；固定时间发行另保留稳定生成 slot。记录内部 FlagId、规则引用、密钥版本、生成协议及窗口。并发、重投和重启必须复用同一发行和值；补发、撤销和数据恢复是独立的明确操作。

AWD 使用专用 HMAC-SHA256 派生器，每场比赛生成独立的 32 字节 CSPRNG 密钥。规范编码包含 NoCTF/AWD/flag/v1 域分隔与完整发行身份，使用固定长度或长度前缀，禁止含糊字符串拼接。默认截取 24 字节，Base64URL 无 padding，外观为 flag{32字符主体}。HMAC 是认证/派生而不是加密。

安全模板允许前后缀、字面文本及受控占位符，但不可预测主体至少 128 位。默认 ASCII、无空白/NUL/换行；精确区分大小写，不隐式 Trim、大小写转换或 Unicode 归一化。随机装饰也必须在发行时固定。全值 Hash 用于查重，不能将碰撞当成合法共享 Flag。

密钥使用现有受保护存储，不能交给题目服务、公开镜像、前端或日志。Runner/Checker 仅取得当前任务必需材料。轮换保留尚有效发行所需旧版本。测试使用独立命名空间及非计分发行。

发行生命周期与投放生命周期独立。先持久化正式发行和秘密材料，再通过 IPostCommitMessagePublisher 派发；pending 状态可重派，覆盖提交/发布崩溃窗口。不得新增通用 Runtime Operation 表或数据库消息 Inbox。

两种题目级方式：Checker 通过合法业务写入，或 Runner 命令注入。题目必须声明历史保存/读取能力，不能宣称多轮有效却每次覆盖唯一文件并删除所有历史。投放成功回执丢失时复查同一 Flag，禁止另发替代秘密。

正式发行、已生效、未过期、未撤销且可计分的 Flag，不能因缺少成功回执拒绝其有效攻击。能通过 HMAC 但未发行、未来发行、测试或撤销值都不可计分。Runtime 重置不改写发行身份，也不自动回填选手丢失的历史数据。

公开攻击定位信息与 Checker 私有读取上下文分开；用户名或记录 ID 可公开，读取密码和秘密不能冒充定位信息。

## 六 接收与结果

每个提交保存 FlagId、生成轮次、接收轮次、接收时间、攻击队、防守队、题目、Store 及计分资格。成功去重为 (CompetitionId, AttackingTeamId, FlagId)，同队跨轮重提仍重复；不同队可以分别得分。

归一化结果区分 ACCEPTED、INVALID、EXPIRED、DUPLICATE、OWN_FLAG、UNKNOWN_FLAG、NOT_SCORABLE、SYSTEM_ERROR。格式非法与未知值分开，暂停/未开始/结束/撤销/未来/限流使用稳定原因码。无效提交不生成攻击成功；系统错误允许重试。

接收、资格判定、去重与结果应用必须并发安全；每次独立提交仍是独立 GameplayFact，成功唯一身份通过关系约束保证。不创建第二套权威提交表。

攻击展示按接收轮统计；Flag 的分值和泄露预算按发行轮归属。Flag 在第 1 轮产生、第 3 轮首次被接受，两种归属都必须可查询。第 1 轮成功不自动延续为第 2 轮成果。

## 七 检查调度及待裁定

Checker 报告连接、当前业务、逐 Flag/Store 读写、稳定原因和观察时间，服务端结合已派发义务验证完整性。未检查项目不是通过；不允许 Checker 自行省略平台已要求的历史项。

每次执行尝试有独立身份，关联同一个计划样本的 GameplayFact。Runner 原子领取待执行尝试，容器 OperationId 使用该尝试身份；旧尝试不能重新申请资源、读取新尝试材料或覆盖新回执。任务令牌绑定 Runtime、GameplayFact 和尝试，Checker 从内部 `GET /api/internal/v1/awd/check-task` 按需读取固定清单；Flag 和私有读取上下文不通过环境变量批量传输，材料响应禁止缓存。命名服务地址单独交给 Checker。`POST /api/internal/v1/awd/check-results` 接收 Connection、Functionality、逐 Flag 的 Write/Read、ObservedAt，以及写入时产生的私有上下文和公开定位信息；接收时间由 API 生成，历史身份、义务和结算资格不能由回调指定。

默认轮末计划任务在结束前 30 秒启动，执行期限为轮末；单次最多 30 秒。失败较快时最多两次重试、相隔 5 秒，剩余预算不足则不启动；30 秒超时可能直接耗尽预算。中间检查每 30 秒一次，与轮末任务重合时合并，不能重复结算。

原轮任务在执行期限内形成的可信结果允许 30 秒回执宽限；更迟回执进入复核。下一轮新执行的检查只证明下一时刻，不能倒填旧轮。回执允许期限不延长 Flag 提交期。

材料读取在当前尝试的执行期限关闭。回执令牌额外保留 24 小时用于接收迟到证据，但这不扩展自动结算宽限；迟到证据保存为 INTERNAL_ERROR / 待裁定，不能自动改写历史 SLA。回执的观察时间必须落在该尝试实际开始与执行期限之间，且不能晚于服务端接收时间。

内部错误默认 hold_and_recheck，耗尽后待裁定；不给正常奖励、不自动扣罚、不按最终零分关闭。管理员依据证据裁定、明确豁免或人工调整，必须保留理由和权限审计。回调重复、乱序、Runner 失联和 Worker 接管不能重复奖励/处罚或覆盖已确认的另一任务结果。

人工处理通过管理端读取检查证据，再执行 `AcceptEvidence` 或 `Exempt`。前者仅按完整服务端清单和原尝试窗口内的已保存证据重新分类，不能凭空指定健康；后者只改变结算资格，不伪造通过、读写成功或历史保管义务。请求携带管理员已查看的 AttemptId 与 ReceivedAt；证据变化或已处理时返回冲突。持久化并发令牌只在服务端使用。裁定时间、操作者、理由、前后健康及结算状态保存在工作人员可见的不可变比赛事件中，迟到回调不能覆盖裁定。人工加减分仍使用规范的 Int32 Value，AWD 必须提供审计理由；理由纳入请求幂等身份。

高级样本平均按本轮计划样本计算，缺失样本保持未决。时间加权按本轮观察区间计算，首个可信观察前、平台异常区间及跨轮空白不继承旧轮状态。不得通过忽略未知区间抬高 SLA。

## 八 计分公式与组合

提供固定、共享池、稀缺度、排名加权和 SLA 乘数预设，并允许高级自定义组合。所有参数有明确基数、单位、边界和结算时机；不提供任意代码执行。

每题每发行周期的 Flag 预算按 Store 权重归一化，再按该 Store 当期发行数拆分。分母在发行时固定，投放重试不改变预算。SLA 以题目/轮次为单位，容器服务数不放大预算。

设某 Flag 分配攻击预算 U、泄露预算 D，有 k 支不同合格攻击队捕获；N 为发行时合格队伍数（含防守队）。

| 攻击策略 | 分值 |
|---|---|
| 固定 | 每攻击队 U |
| 共享池 | 每攻击队 D/k，防守队只损失 D |
| 稀缺度 | U×(L/U)^(((k−1)/max(1,N−2))^α)，默认 L/U=0.1、α=0.705 |
| 排名加权 | U×[1+(M−1)×(N−r)/(N−1)]，默认 M=2 |

没有捕获时不计算攻击奖励。U=0 直接返回 0；稀缺度要求 0<L≤U、α>0。只有一队时不存在合格攻击。排名使用发行时最近完整结算快照；无快照统一倍率 1，不能根据注册先后制造优势。N 和资格基准固定，不读取正在计算的本轮榜单。

默认 DEF 首次有效泄露损失 D，后续攻击队不重复扣。高级 DEF 可按捕获人数扣罚或使用共享池，并显示最大损失。保密性奖励默认 0；启用时在窗口关闭后，按未泄露及可信可读取覆盖比例计算；未知覆盖保持待定。不能通过关服隐藏 Flag 获得保密奖励。

SLA 支持状态倍率或必需 Flag 可读取比例。Store 权重归一化后聚合，平台原因的未知项不算读取失败，也不能从分母静默删除。额外处罚为固定、比例或组合；默认比例基数为本题本轮 SLA 基础预算。连续失败加重以已确定的连续故障轮计数，未决轮中断可确认的连续序列，不猜测持续失败。

默认总分为 ATK+DEF+SLA−额外处罚+人工调整，可为负。自定义权重均非负。SLA 乘数仅缩放正向攻防收益，负向泄露损失、额外处罚和人工调整保持独立，避免关服减少损失。配置的单轮处罚上限先应用，再计算配置的总分下限；下限引入的调整单独解释。

固定分默认即时确认，SLA 默认轮末；共享池和依赖 k 的公式在接收窗口关闭前为暂定。要求立即最终结算与未来依赖的公式不可组合。固定延迟结算可以选择轮末/过期，但不能使晚收到的有效攻击丢失。

配置参数使用 decimal，线性预算分摊与聚合使用约分后的有理数，避免循环小数累积导致整数分丢失；非整数幂只在明确的数值函数边界计算，统一为 12 位小数后转入有理数聚合。按队伍、题目、发行轮、计分分量聚合后向零取整，SLA 使用检测轮。禁止逐 Flag 整数除法。解释返回未取整结果及差额；同分排序使用最终整数分量，不能用界面不可见的小数改变名次。

排名默认总分、ATK、正常完整题轮数、有效攻击数降序，其后最后攻击时间、注册时间、TeamId 升序。高级排序从公开的类型化字段选择，最后始终以 TeamId 保证稳定展示。 高级同分排序由 1–5 个不重复字段组成，各项可选升序或降序；总分降序固定在最前，TeamId 升序固定在最后，没有有效攻击时间的队伍在该项始终排后。比赛默认与已发行轮次分别使用有序关系子表保存，当前排序读取本轮快照；修改默认排序需审计理由并从下一轮生效，冻结榜单保持原排序。题解扣分后的最终榜单使用同一排序器及整数分量，选手规则页公开当前与下一轮顺序。

规则变化默认下一轮生效，旧 Flag 保留规则和有效窗口。已开始比赛的默认配置和题目覆盖修改必须填写理由，事件保存操作者及生效起始轮次；编辑配置不覆盖已有轮次快照。立即变更/追溯重算需要指定范围、预览差额、操作理由和明确应用；不能静默改历史。规则版本属于配置事实，不能为每条 GameplayFact 添加历史裁定版本。

立即变更只作用于当前尚未结束的轮次；追溯操作选择已有轮次的闭区间及单个题目。两者使用独立计分策略，只允许调整攻防/SLA 预算、公式、倍率、结算方式与组合，不改发行身份、资格、Store 分母、Flag 窗口或检测计划，也不改变后续轮次的默认配置。排名权重仍使用发行时保存的已结算名次，无该记录时保持中性倍率。预览由真实榜单投影产生并包含全队差额，令牌有效两分钟，绑定操作者、理由、完整参数、范围与全部可变计分依据；应用前变更任何依据均须重新预览。应用保存带顺序号的不可变规则变更和工作人员审计事件，触发榜单重投影；既有冻结快照不变。

## 九 界面与接口

普通表单只展开比赛时间、轮长、Flag 有效轮数、计分预设、ATK/DEF/SLA 预算和额外处罚开关。高级分组按策略显隐，标明继承/覆盖；预设切换先展示差异，不删除未涉及配置。Store 由题目配置默认一个。

强类型接口提供有效规则、配置来源、双轮次提交历史、分项检测证据、结算状态、分量解释和重算预览。FastEndpoints 使用 ExecuteAsync/TypedResults；OpenAPI、SDK 和 Wolverine 静态 Handler 通过工具重新生成。

大屏保持每队聚合、每题一台服务器、左右窄栏和中央态势。机柜颜色不承担状态；原状态灯表示健康/待检测，独立红色攻击标记表示本轮有效捕获。右侧同时显示健康文字和攻击标记；正常不意味着未被攻陷。上一轮攻击进入历史，不点亮本轮标记。

冻结分数、健康、攻击和可见性必须来自同代不可变快照。公开与选手接口不得泄露隐藏队伍、Flag、密钥、读取凭据或管理员诊断。

## 十 必测与完成条件

- 轮 10/寿命 5 的边界；跨轮首次提交；同队跨轮重复；生成/接收双归属；暂停、尾期与已接收队列。
- 多 Store/多 Flag 发行唯一；并发、重投、重启不增发；全值碰撞拒绝；安全模板低熵拒绝；测试/未来/未发行/撤销不计分。
- 写入成功但回执丢失；Runner 注入保存历史；平台漏发无选手义务；服务故障导致历史缺失可恢复后 RECOVERING。
- 五类健康及未知；当前失败不能 RECOVERING；混合证据不被枚举优先级抹除；跨轮重检不能修复旧轮；重试/回调不重复结算。
- 每种公式、分摊、取整、比例基数、上限/下限、暂定转最终、规则预览及重算都有确定样例；验证预算和共享池守恒（取整差额可解释）。
- 大屏同时 OK+捕获、换轮清除、历史保留、冻结及受众过滤；1366/1920/4K、双语和非颜色可访问提示。
- PostgreSQL/NATS/Redis 行为以真实依赖验证；TUnit 不使用 EF InMemory 证明关系行为。AWDP Break/Fix/Patch/Runtime/计分/契约回归全部通过。
- 前端类型检查、架构审计和行为测试通过；迁移可从现有基线升级，其他模式数据保留；生成产物可重复生成。

## 十一 官方来源与 NoCTF 决策

没有统一的 AWD 国际计分公式。本规范的归一化状态、固定预算、界面默认、自定义组合和仲裁流程属于 NoCTF 决策，不声称复刻赛事。

- [ENOWARS 服务状态](https://enowars.github.io/docs/play/service-status/) 与 [Checker 协议](https://enowars.github.io/docs/service/checker/checker/)：状态含义和 putflag 回执失败后继续读取的依据。
- [FAUST CTF 2026](https://2026.faustctf.net/information/rules/)：3 分钟 tick、5 tick Flag 有效期及其独立攻防/SLA 公式；本规范不直接复制整套公式。
- [ECSC 2026 计分](https://wiki.ad.ecsc2026.de/scoring/)：稀缺度曲线与逐 Flag 可读取计分的参考。NoCTF 的稀缺度模块不是 ECSC 全套 DEF/ATK 奖励公式。
- [FAUST Checker 文档](https://raw.githubusercontent.com/fausecteam/ctf-gameserver/master/docs/checkers/index.md)：合法业务、历史读取与私有上下文。
- [RuCTFE 2020](https://ructfe.org/rules)：历史 CORRUPT/SLA 乘数方案，仅作为历史参考；不将其名称机械映射到 RECOVERING。
- [RFC 2104](https://www.rfc-editor.org/info/rfc2104/) 与 [RFC 4086](https://www.rfc-editor.org/info/rfc4086/)：HMAC 和安全随机性依据。
