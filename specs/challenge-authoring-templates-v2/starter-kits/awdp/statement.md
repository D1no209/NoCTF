# 文件访问控制 · AWDP V2 教学示例

一个文件查询服务允许用户读取公开资料。请检查它的访问控制问题，并在不破坏正常业务的前提下完成修补。

## 服务与正常业务

- 实例地址由平台动态分配，以题目页面显示为准。
- `GET /health`：正常时返回 `ok`。
- `GET /file?name=public.txt`：应返回附件 `public.txt` 中的公开内容。
- 修补后必须保留上述正常功能，不得通过关闭服务或拒绝所有请求规避评测。

## 附件与修补要求

下载公开数据 `public.txt` 和 `patch-template.tar.gz`。解压 Patch 模板后，在 `fix.sh` 中实现自己的修补。
允许修改范围为教学服务目录 `/opt/challenge`；不要依赖当前工作目录，输入文件位于 `/noctf/fix`。
实际赛题若需要更细的白名单、不可修改文件或启动限制，由出题人在本节明确列出。

提交 `.tar.gz` 时，归档根目录必须直接包含 `fix.sh`，不得再套一层目录。空白模板尚未实现修补，
不能直接提交。保留正常业务并使漏洞利用失效，才构成防御成功；脚本执行失败或评测基础设施故障不等于成功。

## 教学范围

本模板用于演示文件访问检查与 Fix 评测流程，使用固定教学哨兵，不是已经配置好真实 Break Flag 的正式题目。
正式出题前，出题人必须替换本题面、完善 Flag 注入与攻击验证、说明允许修改范围，并由负责人确认计分和 Hint。
题面中不要写入标准答案、PoC、私有部署信息或真实 Flag。
