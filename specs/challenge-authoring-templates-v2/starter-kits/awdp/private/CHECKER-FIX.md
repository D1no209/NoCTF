# Checker 如何读取 Fix 输入和修补产物

Fix 由 Runner 在独立目标 Runtime 中执行，Checker 持有回调凭证并验证修补后的靶机。
只有需要检查原始上传文件时，才在模式定义中打开“向 Checker 提供 Fix 包”。该选项提供归档副本，
不会授权 Checker 执行选手内容。这一边界同样适用于 CTF PatchVerification。

| 需要检查的内容 | 读取位置／做法 | 平台是否自动提供 |
| --- | --- | --- |
| 选手随包上传的替换源码、二进制、配置 | `/noctf/fix/<包内相对路径>` | 打开“向 Checker 提供 Fix 包”后提供 |
| `fix.sh` 执行后生成的文件 | 通过题目受控服务协议核对实际靶机；额外回放需采用独立的无凭证隔离环境 | 不自动复制 |
| 真实防御靶机当前的磁盘文件 | 当前契约没有自动复制／挂载／下载接口；通过公开业务行为验证，或另行评审需求 | 不提供 |

原始输入和实际执行后的状态不能互相替代。最终应访问 `TARGET_HOST` 验证真实服务；
Checker 的凭证和敏感文件只属于可信验证环境。

## 方案一：读取选手输入文件

假设选手归档包含 `fix.sh` 与 `policy.txt`，打开上述前端开关后，平台在 Checker
启动前准备好 `/noctf/fix/fix.sh` 和 `/noctf/fix/policy.txt`，无须自行下载、再次解压或寻找原始 tar 路径。

示例工具 [inspect-file.py](checker/inspect-file.py) 只读取固定目录中的普通文件，并输出来源、相对路径、
字节数和 SHA-256，不执行脚本或二进制，不打印原始内容：

```sh
python3 /checker/inspect-file.py --source input --path policy.txt
```

工具默认最多读取 16 MiB，超限、文件缺失、目录、路径越界或符号链接会明确报错并非零退出。
这只是文件结构与来源检查，退出 0 不代表防御成功；出题人仍需实现内容、功能与漏洞判定。
如要检查上传的替换二进制，可将路径改为本题约定的 `bin/service`，并根据题目资源预算审核大小上限。

## 检查执行修补后的靶机

Runner 先把 Fix 注入独立的目标 Runtime，并在该容器中执行约定入口。选手程序只能在这个不持有
Checker 回调凭证的环境执行。Checker 随后通过 `TARGET_HOST` 验证正常业务和漏洞利用结果。

`checkerFixInput=true` 只向 Checker 提供原始上传归档，供普通文件检查使用。Checker 必须将其视为
不可信数据；禁止执行、导入、解释或加载其中的脚本和二进制，也禁止共享回调凭证、进程环境、PID
空间或敏感文件描述符。回调令牌绑定 Fact 与 Runtime，仍有权完成本次判定，不能交给选手代码。

发布时先重建并更新 Checker 镜像，确认其只做外部验证及安全的数据检查，再发布涉及输入准备的
Runtime 可用性变更。已有镜像不会随文档或后端更新自动变更，应使用新的镜像版本或摘要，并重新
运行正常修补、仍可利用和回调伪造回归。自定义 Checker 也需按此边界审阅与更新。

如需检查编译产物或靶机上的执行后状态，应通过题目自己的受控协议验证实际服务。当前接口不提供
靶机磁盘快照；归档中的文件不能代表执行后的产物。额外重放必须采用独立、无回调能力的隔离环境，
并由可信 Checker 独立验证结果。仅清除环境变量、扫描命令名或设置文件不可执行都不构成充分隔离。

## 发给出题 Agent 的约束

```text
为 NoCTF AWDP 编写 Checker 时，先在部署说明登记需要的文件来源：input 或真实靶机。
input 仅指前端打开“向 Checker 提供 Fix 包”后的 /noctf/fix，包含选手包副本，不是靶机快照。
Fix 入口由 Runner 在独立目标 Runtime 执行，Checker 只负责外部验证和读取不可信输入数据。
持有 NOCTF_CALLBACK_TOKEN 的环境不得执行、导入或解释选手内容；自定义 Checker 必须维持此边界。
读取文件时检查相对路径、普通文件类型、链接与大小；不执行上传二进制来“验证文件存在”。
不要假定 Checker 自动获得 FLAG，不要以依赖缺失、写目录失败或连接超时代表 EXP 已被修复。
必须验证真实 TARGET_HOST 的正常业务，再进行漏洞探测，最后按既有回调协议报告结果。
若要求真实靶机执行后的磁盘文件，明确标记当前接口不提供，不能编造共享目录或下载 API。
```

`ServiceAbnormal`、`ExploitSucceeded`、`DefenseSucceeded` 是业务判定；依赖或回调等基础设施故障
应保留非零退出。具体环境变量和超时见 [字段字典](../platform/FIELDS.md)。
