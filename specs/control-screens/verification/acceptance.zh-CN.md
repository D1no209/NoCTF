# AWD / KoH 观战大屏实现与验收

日期：2026-10-13（Asia/Taipei）。分支：`codex/awd-koh-control-screens`。沿用已确认方案和原有实现；全部改动为本地提交，未推送、未部署。

## 交付范围

- `/competitions/:id/awd-live`：固定阵地、2–12 队服务器模型、13–32 队实例化紧凑节点、更多队伍分组；服务轮播每 8 秒切换，支持暂停/锁定、前后队伍和队伍/题目焦点。攻击光带只消费确认事实，最多 12 条活动、30 条排队，积分及结算来自权威投影。
- `/competitions/:id/koh-live`：连续程序化岩石地表、从真实网格截取的等高线、实体旗帜、所属队伍、有限交接动画和变更提示；地形不以得分或控制者驱动。按据点绘制 5/10/30 分钟确认时间线，未知段用斜纹，暂停时间线不停止当前快照刷新。
- 全屏、键盘操作、减少动态、30/60 FPS 档位、DPR 上限 1.5、后台停止绘制、空闲按需绘制、错误/过期提示、WebGL 初始化失败及上下文丢失后的二维列表降级。
- 公开赛事介绍、竞赛工作区及管理侧入口。中文/英文目录按路由加载。CTF / AWDP 的既有页面保留。

## 数据与权限

观战帧与计分投影同代生成。公开 REST 查询始终以匿名身份解析权限，公开题目与赛道过滤同时应用于排行、服务、控制关系及历史。播出页父工作区不请求个人队伍、内部排行榜和公告补偿数据。

`/hubs/v1/spectators` 是独立匿名 Hub，不使用工作人员连接或 bearer token，不加入用户/工作人员分组；通知只包含赛事 ID。现有身份认证和 MFA Hub 继续保留原保护。每条观战连接最多订阅一个赛事；失效通知合并、单飞重取、重连补读及可见页 10 秒兜底共用公开快照接口。

AWD 攻击按轮次、攻击方、受攻方和题目去重，沿用竞技资格；服务失败不从攻击推断。加固期使用扣除暂停后的有效运行时间。题目时间预览覆盖观战投影。

KoH 同时保存观测队伍和当时有效控制者。检测失败保留有效控制；明确无人控制才清除。隐藏控制者以未知表示，不伪造无人控制。控制历史不以浏览器时间产生分数。

封榜读取既有不可变投影，比分、服务、攻击、控制和历史共同冻结；封榜后修正事实不会改变已保存帧。当前公开权限仍可进一步收紧，不能把封榜前的内部赛道扩展到公开画面。缺少兼容观战帧时返回 202 并请求可见性处理；不会从当前可变事实伪造旧封榜内容。这意味着早于本功能的旧封榜记录可能保持不可用，需要由赛事管理流程重新建立可用公开代次。

播出页使用 `limit=2000` 在单个响应中读取完整有界历史（最多 2000 条、30 分钟），避免持续发布新版本时逐页读取反复失效。接口仍支持默认 256 条分页，客户端保留完整版本组装与冲突恢复保护。首次读取和解封重建基线不重播，迟到确认按事实 ID 识别，修订不重复播放；另保留最多 4000 个事实身份，避免撤回后恢复的裁定再次播放。超出历史边界会明确提示截断。

## 持续压力采样与限制

环境：Windows、32 个逻辑处理器，Bun 1.3.14、.NET 10.0.401，Nuxt 开发模式及内置浏览器。没有把开发环境结果当作生产构建或独立显卡性能证明。

AWD 32 队×8 服务，Mock 每秒产生 20 个确认事件。稳定绘制样本从本地 00:16:26 到 00:32:12，跨度约 15 分 45 秒；页面计时从 161 到 1106 秒，期间未重新挂载场景。包含 60 FPS 与 30 FPS 两个档位，数据按 10 秒兜底重取。此轮压力采样在切换最终匿名 Hub 和单响应完整窗口前完成，两者另外做了协议、应用测试及浏览器功能验证；未把这次采样描述成最终高频 SignalR 推送路径的端到端压力测试。

| 指标 | 实测 |
| --- | --- |
| 活动 / 排队上限观察 | 12 / 18，代码硬上限 12 / 30 |
| 空闲 / 动画中 draw calls | 4 / 16 |
| 空闲 / 动画中几何体 | 2 / 14，动画结束回落 |
| 纹理 | 1，无持续增长 |
| 60 FPS 档位 p95 帧间隔 | 24.0–24.2 ms |
| 30 FPS 档位 p95 帧间隔 | 40.7–40.8 ms |
| 单帧 CPU 绘制代码 p95 | 0.4–0.5 ms |
| 绘制代码时间 / 墙钟时间 | 0.73%–1.05% |
| JS 堆采样 | 131–139 MiB，未观察到单调增长 |

帧间隔高于理想的 16.7 / 33.3 ms，**本次没有证明稳定满 60 / 30 FPS**。CPU 绘制计时只覆盖场景绘制回调，不等于整页 CPU 或 GPU 耗时。KoH 12 据点另外进行了短时动态检查，不能称为同样长度的压力测试。

另对桌面应用的全部 19 个 ChatGPT 进程采集了 900.8 秒数据：CPU 合计增加 396.22 秒，约占一个逻辑核 43.99%（32 核总能力的 1.37%）；合计工作集 3252–3466 MiB，首尾为 3362 / 3339 MiB。这包含聊天界面、内置浏览器和其他应用进程，**不能归因于单一观战标签页**。

最终匿名通道还进行了独立短时检查，60 FPS 档位 p95 约 16.8 ms，单帧绘制 CPU p95 约 0.4 ms。它与上面的长测不是同一轮，也不能据此替换长测中的掉帧结论。

原始数据：[场景长测样本](awd-render-samples.json)、[最终路径短测](final-path-samples.json)、[桌面应用进程样本](awd-app-process.csv)。早期热更新/绘制故障的试采样未混入长测数据。
