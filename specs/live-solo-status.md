# LiveSolo 完成状态与验收缺口

核对日期：2026-10-09。代码基线：`2da45b22` 及后续已验证的录像管理阶段，开发分支：`codex/livesolo`。此文件随验证通过的阶段更新，不用没有实测依据的总体百分比。

当前不能由真实选手完成一场完整 LiveSolo 比赛。显式配置媒体后使用真实 LiveKit 网关，未配置默认拒绝；房间、私有授权、周期资格复核及数据库故障退役已有实现与测试。专用大厅、准备、对局及基础裁判界面已有实现，浏览器 Mock 验证了部分交互；这不证明真实屏幕视频或媒体容量。隔离资格由 `RunnerExecutionRuntimeIsolation` 检查真实提供方回执和 fenced Runner；未验证的提供方仍被拒绝。实际视频、Egress、延迟节目、完整工作人员功能与容量验收仍未完成。

## 状态定义

- **已实现且验证**：该行限定的交付已有实际实现，并有与其匹配的验证证据；不代表完整比赛闭环。
- **部分实现**：已有可执行部分，但仍缺规则、接口、界面、适配器或验收。
- **仅有接口／模型**：仅有契约、表、配置、SDK 类型或默认拒绝适配器，没有对应可用能力。
- **尚未实现**：尚无该项实际实现。

## 当前可用流程和阻断项

后端 API 和测试环境可维护独立模板／题组，创建 Match，锁定名单、确认准备，维护赛程，执行基础裁判操作并读取记录。测试通过模拟媒体就绪和无 Runtime 题目验证受理、评测、时限、晋级等内核规则。真实媒体未就绪时正式倒计时被拒绝，不能将上述测试流程解释为真人可用的完整比赛。

主要阻断项是实际网络隔离、真实媒体及全员采集、专用前端。上线前还必须闭环延迟节目及撤销、录像／回放、结果纠正、提示／题解和完整恢复／容量验收。

## 验证证据与架构风险

- 最新后端构建通过；非集成测试 1496 项通过，1 项与本功能无关的隔离集群容量测试按其配置跳过。
- 相关真实 PostgreSQL/NATS、HTTP、迁移和裁判测试通过；容量名额测试 4 项、裁判回归 5 项。具体阶段结果见 [实施记录](live-solo.md)。
- 最近前端回归为 780 项通过，类型检查与架构审计通过。新增断流通知原因、中英文及精确对局跳转检查。Mock 浏览器已检查录像保留、原因确认、赛中公开拒绝及失败反馈；真实合成 Egress 码流在浏览器解码就绪，但播放交互验收尚未确认；不能替代真人采集或端到端验收。
- OpenAPI 331 条已记录路由；EF 迁移、SDK 与需要更新的 Wolverine 静态代码使用工具生成。存在这些产物不代表对应业务链路已经可用。
- 独立能力目录和中立 Runtime 接口的方向正确；`LiveSoloMatchStore` 仍集中承担较多职责，需要持续把决策规则放入 Application，并保持基础设施专注持久化和适配。
- 依赖边界测试只能证明部分引用关系；不能单独证明旧四赛制行为不变，也不能替代真实 Runtime、媒体、浏览器及多节点验收。
- 开发分支目前只有本地阶段提交。没有 LiveSolo 生产部署或真实媒体容量验收证据。
