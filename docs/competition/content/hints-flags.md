# 提示与 Flag 管理

入口：比赛题目详情的提示/Flag 相关区域；Runtime 具体动态 Flag 在实例详情中读取。权限取决于比赛和模板作用域，不因一个列表行可见而拥有全部敏感读取权限。

## 提示管理

1. 打开正确比赛题目的详情，加载提示列表。
2. 点击新增，填写内容、顺序、解锁代价和发布状态。
3. 保存后检查列表和选手权限视图。
4. 编辑时确认针对的是原提示 UUID，不重复创建。
5. 删除后需要恢复时使用已删除提示入口；恢复并再次核对发布。

提示属于比赛题目，其他比赛引用同一模板不会自动得到这些提示。公开未解锁摘要与已解锁正文的访问不同；不要把收费提示全文放进普通公告或 Webhook。

解锁扣分形成队伍行为，修改提示政策后检查当前投影。提示正文更新应说明影响，不能承诺改正文会清掉之前的解锁事实。

## 三类 Flag 作用域

| 类型 | 所属对象 | 管理方式 |
| --- | --- | --- |
| 模板静态 | Challenge | 在题库 Flag 页维护，比赛按配置使用 |
| 比赛专属静态 | CompetitionChallenge | 当前比赛实例专用，与模板作用域互斥 |
| Runtime/队伍动态 | 当前实例/队伍/轮次 | 平台生成、注入，实例详情查看其状态与窗口 |

每队生成、AWD 轮换、KoH 控制内容含义不同。修复包验证是 Fix，不能把上传 archive 当成额外 Flag 配置。

## 生成缺失 Flag

比赛概览提供补齐缺失 Flag 的操作。用它处理当前资格/发布题目缺项，完成后查看每项 failure。它不重写全部已有 Flag，也不会自动重判旧尝试。

AWD 注入与轮次、每队容器启动注入由相应生命周期负责。补缺按钮不能替代 Runner 和注入命令健康验收。

## 读取敏感内容

在实例详情或尝试详情使用明确的原文查看动作，确认目标；当前尝试原文弹窗不要求输入访问理由。比赛 Owner/Manager/Judge 读取受保护内容有对应访问事件；平台管理员读取规则不同。包含受保护 Flag 的归档导出则另有管理员和理由要求，不能混为同一个流程。

优先按 Flag ID、事实 ID、实例 ID 和匹配状态排障，仅在必要时看原文。不要将读取结果写到截图、公告、普通调试日志或公开导出中。

## 常见问题

- 题面可见却不能看原始 Flag：模板共享与敏感技术定义权限不同。
- 模板改 Flag 后旧实例仍旧：已有实例不会自动重置，安排新的启动/重置并验证。
- 补缺失败：依失败 code 核对队伍、定义、存储和执行资源，避免重复批量生成掩盖异常。
- 比赛 Flag 与模板 Flag 混淆：先核对 scope ID，不能同时给同一条记录两个作用域。
