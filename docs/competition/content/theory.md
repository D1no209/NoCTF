# 比赛理论答题与组卷

入口：比赛管理 → 理论答题，`/admin/competitions/比赛ID/theory`。仅 CTF、AWD、AWDP 支持关联；既有比赛默认保持关闭。它为比赛增加独立理论分，不占用实践题目、Runtime 或 Flag 提交入口。

## 准备条件

先在 [理论题库](../../challenge-bank/theory.md)准备可组卷题目及使用授权，再确定参与队伍、活动时间和理论成绩在总分中的权重。工作人员按比赛角色进入；能够读取管理工作区不等于可以发布、看答案键或纠错。

## 配置与发布

1. 在设置与组卷区域创建或编辑草稿，填写活动名称、开放时间、截止时间和每卷时长。界面时长以分钟填写。
2. 设置每队尝试次数及计分方式。最高分、最后一次或累计三选一；累计必须有限次数。比赛理论答题也必须填写有限次数。
3. 添加抽题规则：题型、数量、每题分值，以及可选的难度、知识点、标签限制。规则分值决定整卷满分，从而影响比赛总分，不能用普通题目调分配置替代。
4. 确认是否允许已曝光题源。正式保密试题优先使用未曝光来源；开启允许曝光也不能绕过其他资格或跨卷去重条件。
5. 保存草稿，运行容量验证。若不可行，按具体规则扩充候选、调整筛选或减少数量/次数，再验证。
6. 明确点击发布并检查状态。保存和验证都不等于发布。发布固定候选版本、次数和计分规则，选手到开放时间后按资格开卷。

例如配置 10 道单选、每题 2 分和 5 道多选、每题 4 分，本卷满分为 40。最高分取有效答卷的最高分；最后一次取最后一次有效尝试；累计加总各次有效得分，因此还需按次数核对最大理论贡献。

## 团队共同作答

每队每次共用一份试卷，任何有效成员可以开卷、保存答案和交卷；不要求队长独占。试卷选项次序保持固定，答案修改采用版本检查，避免队友静默覆盖。对选手公布 [答题说明](../../player/theory.md)，提前说明交卷后只看成绩、不能回看题面。

准备正式开赛时至少用一支普通合格队伍验证开卷、两成员同步、交卷、次数和榜单。工作人员预览不替代真实队员授权验收。

## 发布后的运行操作

| 操作 | 何时使用 |
| --- | --- |
| 撤回 | 尚未发过卷时返回草稿，调整后重新验证并发布 |
| 暂停、恢复 | 临时中断答题；时间按暂停区间合并处理 |
| 延期 | 调整允许的截止时间，比赛关联活动受比赛结束上限约束 |
| 停止发卷 | 阻止新增试卷；对已发试卷继续核对其状态和到期处理 |
| 结束 | 完成活动运营，保留答卷与成绩记录 |
| 作废 | 按原因将活动作废并保留审计，不删除历史 |

操作前核对活动状态、已发卷数量、正在作答人数和预期影响。已经发卷后不能通过撤回修改冻结规则；题目错误使用 [答卷审核与纠错](../judging/theory.md)。结束和停止发卷不是同一操作，按页面确认结果逐项检查在途答卷。

## 成绩与封榜

只有正式整卷交卷才形成理论成绩；未交卷与交卷零分分别显示。理论分进入总榜、趋势和导出，并遵守同一封榜截止与隐藏规则。后台处理暂未完成时，查看答卷和重算进度，不连续人工补分。

后台事实使用实际试卷身份 `TheoryPaperId`，不会伪造一道实践题目。调查成绩时从理论答卷入口查起；实践题目重判、Flag 列表和 Runtime 面板不能解释理论答卷结果。
