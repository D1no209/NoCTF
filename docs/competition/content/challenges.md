# 比赛题目管理

入口：比赛管理 → 题目，列表 `/admin/competitions/比赛ID/challenges`，详情 `/admin/competitions/比赛ID/challenges/比赛题目ID`。它管理实例发布、顺序和计分；可复用技术定义在 [题库管理](../../challenge-bank/index.md)。

## 列表筛选

按题目名称、方向和发布/删除状态筛选，再选择页码和每页数量。修改筛选先回第一页；找不到题时核对是否在已删除记录、是否引用了正确模板、是否进入了另一场比赛。

模板 ID 与 CompetitionChallenge ID 分别显示/使用。管理实例时用比赛题目 ID，不把模板 UUID 填到比赛提交或 Runtime 请求里。

## 添加模板

1. 点击添加题目，选择与本比赛模式一致且可引用的模板。
2. 设置比赛内展示标题，可留空使用模板标题。
3. 指定方向目录、标签和排序。
4. 保存实例，进入详情检查单题规则。
5. 配置提示/Flag 策略并完成测试，再发布。

题库模板共享可见不代表当前管理者能修改其原始 Flag 和技术定义。跨模式模板不能通过改显示名称强行引用。

## 详情编辑

| 项目 | 影响范围 |
| --- | --- |
| 展示标题 | 当前比赛，不改题库原始标题 |
| 方向、标签、排序 | 当前题目列表和公开组织 |
| 发布状态 | 选手是否能在符合其他条件时访问 |
| 模式规则 | 当前题目的分值、罚分和继承/覆盖 |
| 题目时间 | 自动开放、计分结束、提交截止；保存前预览历史影响 |
| 提示 | 本比赛的提示文本、发布和扣分 |
| 队伍成绩区 | 当前正确状态、投影分数、人工调整入口 |

基本信息和规则各自保存，确认没有只保存了标题却漏保存曲线。Nullable 继承与显式 0 不同；各配置可独立覆盖，见 [计分规则](../settings/scoring.md)。

前四赛制的时间区单独 [先预览再确认](./timing.md)，不把“计分结束”和“提交截止”合成一个日期。LiveSolo 不使用此绝对时间编辑器，题目由 [Round 题组](../../live-solo/question-groups.md)安排。

## 发布与下架

列表可逐题切换发布。发布不等于比赛已经 Running，也不跳过 Approved、时间、赛道和闯关校验。下架后检查选手列表和访问，不能把它当作撤销历史正确事实或清零。

发布和修改题面/提示可能产生赛事事件与外部播报，正式运行中协调公告。模板定义修改会影响未来启动，已有 Runtime 不会自动重新创建。

## 单题成绩与调分

在详情中查看队伍当前解题结果与权威题目分，选队进行非零 signed Int32 人工调整。受理后等待投影更新，超时先确认事实，勿重复 delta。完整流程见 [人工调分](../judging/adjustments.md)。

## 删除与恢复

删除比赛实例和删除题库模板是不同动作。实例删除前阅读确认中的引用/状态限制；按“包含已删除”查找可恢复项。恢复后重新核对发布与规则，不假定立即公开。

若模板仍被其他比赛引用，实例删除不会授权删除共享模板。Runtime 与文件清理由业务流程处理，不手工删实例对应的数据库行。
