# 工作人员 Webhook

入口为 `/competitions/比赛ID/staff`，订阅也可在现有 Webhook 管理页配置。创建前确认接收端有权接收所选工作人员摘要。

只有平台管理员、赛事所有者或 Manager 可以配置；Judge 与 Observer 可查看名称、状态和投递结果，不能读取目标 URL 或签名密钥。允许草稿和 StaffOnly 比赛。

## 配置

选择疑似作弊、咨询、封禁申诉中的至少一类，填写 HTTPS 接收地址，保存一次显示的密钥。群绑定和聊天凭据由 BOT 保存。启用后先发送当前待办快照，再发送较新增量。

停用、删除或撤销批准人管理权限后，已排队摘要停止发送，系统尽可能发送不含事项的停用事件。密钥轮换后旧密钥保留 24 小时，期间更新接收端。

摘要不含 Flag、提交值、IP、证据、咨询正文或申诉陈述。点击管理链接后，仍按自己的平台身份访问原有回复和裁定流程；BOT 不直接裁决或封禁。

## 测试与诊断

发送测试不会播报事项。页面提供测试状态和投递记录，正式成功要求接收端持久化后返回 204。需要正确配置平台 HTTPS 公开来源和 Worker 的 Webhook 队列。

每 60 秒心跳。持续 180 秒故障后，用完整待办快照恢复，再继续较新增量。首次及重新启用可发合并摘要；故障恢复只对齐状态，不补播历史进展。

[完整工作人员契约](https://github.com/D1no209/NoCTF/blob/HEAD/specs/staff-webhooks.md) 包含 API、Schema 和虚构签名样例。生产工作群在双方验收后手动启用。
