# 公告发布、编辑与撤回

入口：比赛管理 → 公告，`/admin/competitions/比赛ID/announcements`。当前页面以可裁判/管理权限控制写动作，Observer 只读，服务端最终校验操作资格。

## 选择受众

| 受众 | 使用场景 |
| --- | --- |
| Participants | 面向参赛者的官方说明、规则和故障公告 |
| Collaborators | 比赛工作人员内部协调 |

受众是动态授权，不是给每个用户复制一份通知。公开公告 API、个人 Inbox 和工作人员 Feed 有各自读取语义；写内部受众不能假定所有普通选手会看到。

## 发布步骤

1. 确认比赛，填写标题和正文。
2. 选择 Participants 或 Collaborators，检查是否包含应保密材料。
3. 保存，确认列表中为 Published。
4. 打开预览查看 Markdown 和链接，再用目标受众账号检查。
5. 正式规则变更写清生效时间、影响题目和队伍需要采取的动作。

公告支持正文展示，发布前检查图片、代码块和跳转。Flag、Token、内部回调、原始调查证据和个人资料放在授权工作区，不放普通公告。

## 编辑

在 Published 项点击编辑，加载原公告标题/正文后保存。编辑是更新该公告，不为了改错字再次创建同标题消息。保存后重新预览当前版本，并检查相关事件/播报。

未保存草稿与已发布内容不同，切换项目或重置编辑器前先保存需要保留的修改。

## 撤回

对已发布项打开撤回/删除确认并提交。公告进入 Withdrawn，可切“包含已撤回”查看管理记录，不代表彻底抹掉历史事件或已被外部系统阅读的内容。

已撤回项不能按普通 Published 编辑流程继续修改。需要重新说明时发布新的准确公告，并说明取代关系；不承诺平台会从选手截图或外部聊天中召回旧内容。

## 常见问题

- 个人 Inbox 没有每条公开播报：Inbox 按个人相关范围筛选，检查赛事公告页。
- 后台列表存在，选手看不到：检查受众、状态与比赛公开读取策略。
- 撤回后 Webhook/聊天仍有旧消息：外部接收者独立存储，按对接系统纠正。
- 多人同时编辑：保存后重新读取最终内容，不把每个 409 都当成 revision 冲突。
