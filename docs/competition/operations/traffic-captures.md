# 流量抓取、下载与删除

入口：比赛管理 → 流量抓取，`/admin/competitions/比赛ID/traffic-captures`。该页管理 Runtime 流量文件，不是完整宿主网络抓包器。

## 确定捕获范围

先在 [基本设置](../settings/basic.md)开启采集并确定 Runtime 访问方式。Direct 连接或 DirectAndWsrx 中的直连绕过平台代理，不能保证被采集。WsrxOnly 也要用实际题目协议验证捕获结果。

平台和比赛设置限制 capture 字节数；到上限的文件标记 truncated。截断/不经过入口都意味着证据不完整，不能仅从某份文件缺少报文推断选手没有操作。

## 筛选记录

按比赛题目、队伍、Runtime UUID、截断状态筛选，应用后选择页码。更换筛选清空原选中集合，避免导出上一组未注意的记录。

列表核对题目/队伍名称、实例 ID、文件时间、大小和截断标记。重置后的新 Runtime 与旧文件分别对应不同 UUID。

## 单个 PCAPNG 下载

1. 选中准确实例记录。
2. 点击下载，等待浏览器得到 `runtime-实例ID.pcapng`。
3. 保存到受限调查目录，用支持 PCAPNG 的分析工具打开。
4. 同时记录实例、范围、时间和截断状态。

查看权限和删除权限不同；文件内容可能包含题目交互、凭据和 Flag，不能上传到公开分析服务或当成公告附件。

## 批量导出

勾选所需实例，点击导出得到 `runtime-traffic.zip`。当前接口每次选择 1–100 个不同 Runtime ID，数量多时分批并记录清单。

导出是授权同步流式响应，没有后台“完成后通知”的任务。客户端中断时检查下载完整性，重新选择所需范围，不改文件扩展名冒充完整 ZIP。

## 删除文件

拥有写权限时打开删除确认，核对实例后提交。删除移除该 capture 记录对应可下载内容，不是停止 Runtime，也不是撤销其 GameplayFact。

若文件用于尚未结束的调查，先按内部保留政策保存所需证据再删除。删除后列表刷新并移除选中项，不假设平台会自动恢复或重新捕获历史流量。

## 没有文件时

核对采集开关、生效时点、实际访问路径、流量是否已经发生、存储和 Runner 状态。检查旧/新实例 UUID，避免在新实例中找旧抓包。普通 Host 应用日志不包含原始网络包，Loki 不能替代此页。
