# 比赛删除、恢复与永久清理

入口：比赛管理概览的删除区域。删除是数据生命周期操作，和 Finish、题目下架、Runtime 终止分别处理；普通故障优先走相应修复流程。

## 四个操作的区别

| 操作 | 结果 | 常见用途 |
| --- | --- | --- |
| Finish | 正式竞技结束，不可恢复 Running | 正常结束比赛 |
| 软删除 | 比赛标记删除，可按当前规则恢复 | 暂时撤下或归档管理 |
| 恢复 | 清除允许恢复的删除标记 | 重新读取原比赛数据 |
| 硬删除 | 在引用与历史条件允许时永久清理 | 无阻塞资源的清理 |
| 强制删除 | 管理员满足专门门槛后级联删除比赛作用域数据 | 已明确决定的永久清理 |

恢复软删除不把已经 Finished 的比赛重新变为 Running。删除模板、账号或文件还有各自引用限制，不由删除比赛自动授权。

## 删除前查看预览

概览读取硬删除预览，检查是否可删除及每类 references/count。业务历史、通知关联、题目、队伍或外部资源可能阻塞操作。

不要把一个“删除失败”统一视为版本冲突。查看引用种类、数量和资源 ID，判断应保留、先清理还是使用专门管理流程。

## 软删除与恢复

1. 确认当前比赛 UUID 和状态，Running/Paused 先 Finish。
2. 查看删除确认，提交一次软删除。
3. 在管理员竞赛列表的已删除分类检查目标。
4. 恢复时从同一记录进入，点击恢复。
5. 重新检查状态、访问模式、题目发布、队伍与文件，不自动宣布赛事恢复竞技。

## 普通硬删除

先满足预览中的可删除条件，确认永久影响再提交。若引用在点击后发生变化，服务器仍可拒绝并返回更新预览；以新结果为准，不直接删除数据库行绕过门槛。

## 管理员强制删除

仅平台 Administrator 可执行。比赛不能处于 Running/Paused，且不能存在活动或待处理 Runtime 资源。界面要求完整比赛标题原样匹配、填写 8–500 字符理由并进行明确确认。

执行前保留所需导出和一致恢复点，核对历史、文件和消息作用域。强制清理永久删除比赛范围内容，平台审计仍记录操作者、比赛标识、标题、理由和时间。

发生通知引用冲突时界面可能返回 conflictingNotificationIds，读取对应关联再处理。外部 Runtime 清理由幂等业务流程执行，数据库成功不是所有外部资源立即消失的保证。

## 操作后验证

检查管理员列表、关联实例、文件和清理结果；保留操作记录。不要执行全局 Docker prune、清空共享 NATS/Redis 或整个对象 bucket 来完成单场比赛删除。
