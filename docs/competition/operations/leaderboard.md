# 排行榜可见性与成绩管理

入口：比赛管理 → 排行榜，`/admin/competitions/比赛ID/leaderboard`。这里设置公开可见性；实际成绩来自 [计分规则](../settings/scoring.md)与当前有效事实。

## 两个时间字段

| 字段 | 保存后影响 |
| --- | --- |
| Frozen Start At | 到达时公开榜展示冻结投影 |
| Hidden Start At | 到达时公开榜隐藏，Blackout |
| 原因 | 记录此次可见性操作说明 |

正常状态没有已生效冻结/隐藏时间。两者都生效时，按其先后决定有效状态：较晚的隐藏意味着 Blackout，较晚的冻结意味着 Frozen。不要只看哪一栏非空判断结果。

## 配置示例

若希望结束前半小时冻结，把 frozen 设置为对应绝对时间、hidden 留空。若随后要完全隐藏，设置更晚 hidden。恢复正常需要按意图清除已生效字段并保存，不能只填写一个未来时间却忽略另一项仍在生效。

日期输入按浏览器本地时间显示/转换，记录时附时区。比赛延期后显式核对冻结/隐藏时点，不假定它们自动按比例延期。

## 保存与验证

1. 读取当前有效可见性与两个时间。
2. 修改需要的项和原因，保存。
3. 重新加载确认服务器值。
4. 用普通队伍读取公开排行榜、题目报价和播报。
5. 再用管理读取核对实际评测仍被处理。

Frozen/Blackout 不意味着停止计分；它们限制公开观察。管理数据范围可能更广，不把管理截图直接分享给选手。

## 分数排查

按顺序检查当前最终事实、队伍资格、赛道、模式/单题覆盖、血奖/罚分、人工 delta，再检查 Worker 投影与缓存。改规则触发重算，不等于重新运行 Checker。

Live 血榜播报需公开投影就绪；Frozen 使用冻结投影中的题名/队名，之后改名不会改冻结内容；Blackout 不发送血榜。Webhook 同样执行可见性边界。

## 正式公布

解除/改变冻结前完成待判、申诉与题解处理，检查正式窗口和赛后练习排除，记录最终核对时间。导出与公开榜显示范围分别确认，见 [赛事导出](../integrations/exports.md)。
