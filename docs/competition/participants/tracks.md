# 赛道、资格与准入

入口：比赛管理 → 赛道，`/admin/competitions/比赛ID/tracks`。Administrator、Owner、Manager 可编辑，Finished 只读。赛道是队伍资格和历史投影规则，不是题目方向。

## 赛道表单

| 配置 | 含义 |
| --- | --- |
| 稳定 key、名称与顺序 | 队伍归属与展示，命名后保持可识别 |
| 默认赛道 | 恰好一个公开非内部默认赛道 |
| 允许公开选择 | 普通队伍报名时是否能选 |
| 内部赛道 | 工作人员测试范围，关闭全部公开和竞争开关 |
| 计分 | 是否形成队伍得分 |
| CTF 血榜 | 是否争夺一二三血 |
| 影响动态分值 | 是否推动解题价格下降 |
| 公开排行榜 | 是否出现在公开投影 |
| 攻防竞争影响 | 是否影响 AWD/AWDP/KoH 的竞争性结果 |
| 报名邀请码 | 本赛道准入条件，区别于队伍加入 token |
| 所需 SSO Provider | 全体成员提交报名时应绑定的身份源 UUID |

## 新增与开启

1. 读取已保存定义，选择默认赛道。
2. 新增赛道并填名称/key，按赛事规则选择各项资格。
3. 需要准入限制时设置邀请码、选 SSO Provider。
4. 开启赛道功能并保存。
5. 用测试队验证公开可选范围、报名校验和排行榜。

调整每个开关时分别判断。例如允许计分但不推动动态价格的测试/特殊队伍，不能只用一个“正式选手”布尔值表达。内部赛道必须符合全部私有与非竞争约束。

## 邀请码和身份条件

当前流程允许先创建草稿、修改赛道和加入成员，在提交报名时统一校验赛道邀请码和全体成员 SSO。管理员改道同样检查目标赛道的成员条件。

Provider 下拉空时先由平台管理员配置 SSO。引用 Provider UUID，不按名称推断等价。已有资格不因后续新门禁或成员解绑自动追溯剥夺；正式调整需明确已有队伍处理政策。

## 改队伍赛道

在队伍管理中选择目标赛道并保存。历史事实按当前归属重投影，成绩、血榜、衰减和攻防结果可能改变。先用隔离队伍验证规则，再处理正式队；核对成员门禁与报名状态。

关闭赛道功能会把所有队伍原子归并到默认赛道，再开启不恢复旧归属。界面提供单独关闭确认，先保存原队伍归属和导出记录。

## 删除使用中的赛道

选择要删除项，检查引用队伍数。仍有队伍时必须选择保留的目标赛道，由同次保存迁移归属。不要删除默认项后留下空默认，也不要绕开提示改数据库。

## 验收

分别使用正式队、非竞争队、内部队验证：公开列表、题目访问、计分、血榜、衰减、攻防影响和管理员读取。Observer 与普通用户看不到内部队伍，不能把测试队曝光当作合法公开榜。
