# 独立题目、题组与备用组

入口：`/competitions/比赛ID/live-solo/groups`，具体组用 `/groups/题组ID`。有管理权限的工作人员维护，普通参赛者只读取当前 Round 已开放的题目。

## 复制模板

搜索未删除的原生 LiveSolo 模板，或 CTF 的 FlagSubmission 模板，按需要明确选择附件和静态 Flag 的复制选项。CTF PatchVerification、其他赛制和不支持的 Checker/Patch 不能直接转换。

复制会产生独立私有模板和比赛实例，由目的比赛负责人拥有；技术定义独立修改，附件可保留已有合法 File 引用。复制原始 Flag 需要源 Flag 权限，不因能看题面就自动授权。

保存返回的实际复制数量与新 ID，不用选择数量推断每项都成功。重复复制保留规范来源，源模板后来删除不消除该来源和曝光记录。

## 编辑题组

1. 新建组并填写名称，最长 160 字符。
2. 添加 1–64 个不同 CompetitionChallenge，按开放顺序排列。
3. 第一题偏移为 0，后续偏移严格递增，且小于有效 Round 时限。
4. 未填写某题偏移时按序号乘比赛间隔计算；重排后重新核对。
5. 按需覆盖 Round 时限，1–86400 秒。
6. 选择是否备用组，保存并检查服务端结果。

图面顺序不是服务器已经开放题目的证据。正常组与备用组共同用于后续 Round/重赛，但每次实际采用仍由资格、规范来源和运行状态检查决定。

## 草稿和冲突

未保存编辑会保留并在离开时提示。版本冲突后先保留自己的修改，确认主动重载，再合并当前定义；不要用旧 expectedStamp 覆盖新组。

已开放 Round 的材料受作用域保护，遇到使用中拒绝时先调查当前对局，不强改题面、Flag 或附件。

## 防止重复曝光

系统检查双方及锁定成员此前获取的题目。静态内容达到公开可获取时间后，即使没人实际观看，也可能登记曝光并阻止尚未开始的新 Match 再使用；已在运行的对局不会因此强制换题。

再次复制同一规范来源、删旗、改名或删除源模板不会“清洗”曝光。正式赛程准备足够备用组；不足时等待裁判处理，不强行复用。
