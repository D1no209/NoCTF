# LiveSolo 题组与备用组

入口：`/admin/competitions/比赛ID/live-solo/groups`，详情带 `/题组ID`。管理者维护题组，其他工作人员按权限读取；选手只读取本场已开放的题目。

## 从本场题目池选题

先在 [本场题目池](./question-pool.md)新建材料或投放 LiveSolo 模板，再把本场实例加入组。CTF 转换在全局题库的新建 LiveSolo 流程完成，不在比赛题组中直接复制。

编辑中可跳转新建/投放题目，返回后恢复当前浏览器内的组稿并选中新实例。草稿不等于服务端保存，也不是跨浏览器持久备份；关闭或刷新前先保存。

核对题目所属比赛和实际返回 ID。重复投放返回已有实例，不用选择数量推断新增数量。

## 编辑题组

1. 新建组并填写名称，最长 160 字符。
2. 添加 1–64 个不同 CompetitionChallenge，按开放顺序排列。
3. 第一题偏移为 0，后续偏移严格递增，且小于有效 Round 时限。
4. 未填写某题偏移时按序号乘比赛间隔计算；重排后重新核对。
5. 按需覆盖 Round 时限，1–86400 秒。
6. 选择是否备用组，保存并检查服务端结果。

图面顺序不是服务器已经开放题目的证据。正常组与备用组共同用于后续 Round/重赛，但每次实际采用仍由资格、规范来源和运行状态检查决定。

## 草稿和冲突

未保存编辑会保留并在离开时提示。版本冲突后先保留自己的修改，确认主动重载，再合并当前定义；不要用旧 expectedStamp 覆盖新组。

已开放 Round 的材料受作用域保护，遇到使用中拒绝时先调查当前对局，不强改题面、Flag 或附件。

## 候选预览：不可用与复用风险

准备 Round 前查看候选资格及原因。自动选组只使用无复用风险的候选；有权限的工作人员可以明确选择有风险题组并确认，但不能绕过硬性排除。

| 提示 | 处理 |
| --- | --- |
| 硬性排除 | 修复题目、状态或占用冲突，接受风险不能绕过 |
| 看过题、相同规范来源、公开曝光等风险 | 优先换组；确需复用时由授权人员核对影响并明确确认 |

例如同一个本场题目实例不能同时被两个活动 Round 占用。确认风险需基于最新候选和题组版本，并留下不可变审计；候选或题组变化后重新预览，旧确认不覆盖新事实。

自动准备后出现新的曝光风险，可对当前冻结题组明确确认，不必为确认替换已冻结材料。准备失败可以在当前 Round 重试，或取消尚未开放的准备以释放资格占用，见 [工作人员工作区](./workspace.md)。

系统检查双方及锁定成员此前获取的材料。静态内容达到公开可获取时间后，即使没人实际观看也可能登记曝光。复制、删旗、改名或删除来源不会清洗历史；风险确认只授权本次选择，不删除来源记录。正式赛程仍应准备足够无风险备用组。
