# 赛程、种子与手动对局

入口：`/admin/competitions/比赛ID/live-solo/bracket`。工作人员在竞赛管理工作区查看赛程；管理者可配置种子和对阵，裁判、观察员只读。选手在选手大厅查看公开的当前对阵。

## 生成淘汰赛

1. 检查比赛配置中的单败/双败和阶段胜局。
2. 从合格队伍中选择参赛名单，核对队伍 UUID。
3. 调整种子顺序，不只改变屏幕上的显示排序。
4. 预览/确认生成，使用当前赛程版本标记。
5. 读取 Winners、Losers、决赛和条件重置决赛等实际来源关系。

轮空不是一次实际失败。未决来源的 Match 等待上游结果，不需要管理员临时填一个对手冒充晋级。双败按实际失利和条件决赛规则处理，不能把两次任意管理操作当作两次败场。

## 手动 Match

选择左右两支不同有效队伍和 requiredWins，确认后进入新对局。手动对局与淘汰赛的冠军/晋级关系不同，不用手动赢局冒充已生成赛程冠军。

同队同时只能占一个活动 Match；两队淘汰赛中不能用额外手动局绕开赛程。已暂停的首次倒计时仍可能占用并行名额。

## 方向抽签与逐局上场

在对局工作区的“方向抽签 → 配置方向池与预设”维护预设。每个预设绑定方向和一套本场题单，名称选填，留空时使用方向。创建 BO7 时填写 `requiredWins = 4`，通常准备七个预设，例如 Web①、Web②、Pwn①、Pwn②、Crypto、Reverse、Misc。名额数量按赛事需要配置。两个 Web 名额各自绑定题单，两个 Pwn 名额同样独立。

每个可用名额具有相同的抽取概率。裁判抽取一个后，该名额从剩余池中移除；抽签结果持久化，重复点击、刷新或服务重启均保留同一个结果。选手仅看到方向和对应局数，双方队长在方向公布后按赛事原有的上场人数配置选择本局人员，再按原流程准备题目、确认准备和开赛。下一局重新抽签、重新选择上场人员。先取得四胜的一方结束本场。

题单按队伍互斥，检查范围是本竞赛内双方参加过的全部对局。抽签会自动跳过任一队伍已经抽到或已经准备使用过的题单，其余名额继续正常抽取。抽签后尚未开赛的题单也已经占用；同一题单不能通过另建预设再次分配给该队伍。普通标签和方向名称不参与题单身份判断。其他队伍仍可使用该题单，各自的题目资源、附件分配和判题受理顺序由 Round 隔离。作废或超时重赛沿用本局已抽取的名额，不再次消耗方向池。

工作人员可在对局期间编辑剩余名额，保存会保留已抽结果及当前局绑定。清空操作只清空尚未抽取的部分。预设目录可独立维护，修改预设仅影响之后配置的名额。未启用方向池的对局继续使用原有名单和题单选择流程，也可正常申请救场。

## 查看与推进

后台“对局管理”按对局显示当前状态、双方和胜局，进入对局处理名单、准备与局。完成后由权威结果推进赛程；列表刷新失败时先重读，不重复点击生成。

结果有争议时使用 [纠正流程](./corrections.md)，它会分析下游影响。不能直接在普通积分榜补分来修改胜者或晋级来源。

## 删除对局

管理者在“对局管理”选择对局，点击“删除对局”并确认。准备中、进行中和已结束的对局均可删除。若赛程中有后续对局依赖该对局的胜者或败者，后续关联对局一并移除；其他对局保留。

删除会释放队伍占用，取消尚未结束的局，停止相关运行环境和直播，并取消涉及这些对局的待处理赛果纠正。已有判题记录、录像保存期限和题目使用历史保留，队伍无法通过删除重新抽到已经使用过的题单。全部对局删除后可重新生成赛程。

## 验收边界

规则和原子晋级已有对应测试，不等于完整现场赛程、多节点恢复或纠正后真人重赛已经验收。按 [就绪清单](../../../operations/live-solo-readiness.md)验证目标队伍规模及单双败场景。

## 工作区导航

工作人员从竞赛管理侧栏进入对局管理、本场题目池、题单、赛程或赛制与直播设置，操作期间始终保留管理侧栏。比赛基本设置继续负责名称、时间与报名等通用信息。

管理页右上角可明确打开选手大厅或对应的选手对局；选手视图不会因为当前账号有管理角色而自动变成工作人员视图。

从对局返回列表会保留选中对局；录像、题解和结果纠正返回对应对局。题单编辑与题目池之间往返保留草稿和新增题目选择，未保存内容会在离开时提示。
