# 已完成结果纠正与下游重赛

入口：完成 Match 的纠正按钮，`/competitions/比赛ID/live-solo/corrections/对局ID`；具体提案带 `/纠正ID`。由 Administrator、Owner、Manager 处理。

## 提出纠正

选择正确胜者和双方胜局，填写实际原因。胜者必须是左右参赛队之一，且达到本场 requiredWins，另一方少于目标胜局；非负整数不能任意填写成与胜者矛盾的比分。

先点击影响预览，读取来源 Match 的当前版本及所有下游影响。预览只读，不直接改胜局或开始重赛；修改拟议比分后重新预览。

## 冻结提案

确认预览后开始纠正，系统绑定该预览与版本，冻结受影响的运行范围。原有名单、题目、Flag、尝试和结果证据保留，不通过删除历史来“修正”赛程。

查看当前提案和裁定历史，确认哪些下游 Match 已开始、需要重赛、仅待上游重解或不受影响。待纠正期间普通裁判/开赛操作可能被拒绝。

## 下游同意与应用

逐个勾选需要重赛的 Match，同意基于其当前版本。只有所有必须重赛项明确确认、理由完整且提案有效时才能应用。

提交后服务器替换适用的下游 Match、保留旧作用域事实，重新核对胜者、晋级、被取消项及新 Match ID。重赛本身仍要名单、准备、媒体与题组验收，不因应用纠正自动成为已完成比赛。

## 取消

不应用时填写取消理由，确认后按系统恢复受冻结范围的暂停计时/状态。取消不是删除提案记录，也不能让新旧对局同时各自接受有效正式结果。

## 冲突和验收

发现源/下游版本变化时重新读取并预览，保留自己的未保存草稿；不能照搬旧 replay consent。多节点通知、完整双败纠正和真实重赛仍需要独立验收，见 [就绪清单](../../../operations/live-solo-readiness.md)。
