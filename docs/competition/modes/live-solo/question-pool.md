# LiveSolo 本场题目池

入口：比赛管理 → LiveSolo → 本场题目池，`/admin/competitions/比赛ID/live-solo/question-pool`。Owner、Manager 和平台管理员可维护；Judge、Observer 按授权只读。题组从本场题目池选择，不直接从全局题库添加。

## 选择题目来源

| 操作 | 结果 | 与全局题库的关系 |
| --- | --- | --- |
| 本场新建 | 创建只属于本场的材料和比赛题目实例 | 不进入全局题库 |
| 从题库投放 | 引用 LiveSolo 模板，创建或返回本场实例 | 首次实际内容编辑前跟随模板 |
| 保存到题库 | 从本场材料创建独立全局模板 | 本场材料仍归本场，不自动引用新模板 |

本场新建按比赛管理权限执行，不额外要求全局出题资格。“保存到题库”需全局题库资源创建资格；能编辑比赛不自动获得该资格。

## 本场新建与编辑

1. 在题目池中新建，填写标题、题面、方向等资料，配置 Flag、附件和适用的 Runtime。
2. 保存并重新打开详情，核对比赛与本场题目 ID，确认材料出现在本场池中。
3. 将题目加入 [题组](./question-groups.md)，设置顺序和开放偏移。
4. 用隔离测试对局验证附件、Flag 和 Runtime 访问。保存成功不证明完整 Round 能开局。

本场材料不出现在全局题库列表、搜索、详情或题库写入接口中。需要跨赛事复用时明确保存到题库，再按全局模板流程审核和授权。

## 从题库投放与脱离

投放候选只接受 LiveSolo 模板，不能在这里直接转换 CTF。选中模板投放后，检查实际返回实例；重复投放同一来源返回已有本场实例，即使它后来已脱离模板，也不会再创建一份绕过来源检查。

刚投放时题面和定义跟随题库。第一次真正修改题面、技术定义、Flag 或附件时，系统原子地复制并脱离模板，保留本场题目 ID 及题组引用；此后编辑只影响本场材料。原样保存不会脱离，调整排序或标签也不改变引用关系。

编辑前查看是否仍跟随模板。无受保护源内容权限时 Flag 隐藏，相关内容编辑受限；投放或读取权限不自动扩大为敏感材料权限。活动 Round 正在使用的本场材料禁止编辑，先处理使用中的对局，不用旧版本标记强行保存。

## 将 CTF 题目用于 LiveSolo

在**全局题库的新建 LiveSolo 流程**选择由 CTF 转换，再将生成的 LiveSolo 模板投放到本场。也可以直接创建空白 LiveSolo 模板。

转换只接受支持的 CTF FlagSubmission 内容：无 Runtime 或独立容器环境可按规则转换，共享容器转为按队环境；OVA 和其他交互类型不支持。转换受保护材料需要源模板写权限。定义、Flag 和附件关联独立创建，不可变文件对象可复用已有合法引用。

转换和脱离都保留规范来源，不消除曝光，不保证材料符合下一场 Match 的选题条件。正式赛程仍须检查备用题数量和候选预览。
