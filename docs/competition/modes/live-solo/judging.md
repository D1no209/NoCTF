# 裁判操作与媒体故障

入口：Match 工作区的裁判操作。Administrator、Owner、Manager、Judge 按当前能力执行；Observer 不裁定。存在待处理纠正时，普通操作可能被暂时冻结。

## 操作的作用

| 操作 | 结果 |
| --- | --- |
| Pause | 暂停当前 Match 的竞技时间 |
| Resume | 重新检查当前条件并恢复，保留有效时间语义 |
| VoidRound | 作废当前 Round，不增加胜局和有效 BO 局数 |
| ForfeitMatch | 指定弃权一方，按合法结果推进 Match/赛程 |

每项填写原因并确认。界面绑定 Match、Round 和时间线版本，打开弹窗后若状态已改变，应重载再决定，不用旧确认覆盖新 Round。

## 工作流程

核对双方和本场 ID → 读取名单、屏幕、Round、受理记录 → 选择准确动作 → 填原因/弃权队伍 → 确认 → 刷新结果和赛程。

出现断流、房间丢失或资格撤销时，工作人员收到提醒。提醒不是自动裁决：系统不自行判负或暂停。检查是单成员浏览器、全房间、Provider、节目导出还是权限问题，再按赛事规则操作。

暂停期间其他题目/观众的读取边界仍分别执行，不能利用暂停发送原始媒体房间 token 给观众。恢复前检查全员共享、题组和资源；部分停止/过期条件会让 Ready 被撤销。

## 重赛

作废后使用新的 Round 和适合的题组。备用组不足时等待补充和裁判处理，不用旧作用域直接复用素材。记录原决定、原因和新 Round，避免将作废记成某方胜利。

## 终场争议

已经 Completed 的结果用 [结果纠正](./corrections.md)处理。普通题目重判、人工积分调整或修改比赛榜单不能改变 LiveSolo 胜局和晋级。

私有状态推送只给当前有权人员，断线后 REST 重读。媒体、业务时钟和通知分属不同环节，一条推送或播放器可见不证明另两项健康。
