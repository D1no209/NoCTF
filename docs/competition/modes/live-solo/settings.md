# LiveSolo 设置与阶段规则

入口：比赛管理 → LiveSolo → 设置，`/admin/competitions/比赛ID/live-solo/settings`。平台管理员、Owner、Manager 可写；其他角色按服务端授权读取。

## 设置字段

| 字段 | 当前默认 | 含义与范围 |
| --- | --- | --- |
| 功能启用 | 关闭 | 仅配置就绪和验收后允许正式流程 |
| 通过平台直播 | 新比赛关闭 | 关闭时不要求屏幕共享或部署媒体服务；开启时启用屏幕、延迟节目和可选录像 |
| 静态 Flag 获取证据要求 | 关闭 | 开启后按本轮题目要求校验合法获取证据；独立于直播开关，在准备 Round 时固定 |
| 赛程格式 | 单败 | SingleElimination / DoubleElimination / Swiss；配置阶段流程后由各阶段独立决定 |
| Required Wins | 2 | 先到 N 胜；1–1024，2 对应默认 BO3 |
| 上场人数上限 | 2 | 每队本场名单上限，1–64 |
| 并行 Match 上限 | 4 | 1–128；包含当前占用活动名额的对局 |
| 倒计时秒数 | 5 | 1–60 |
| 自动开题间隔秒 | 180 | 1–86400，题组可显式安排每题偏移 |
| Round 时限秒 | 900 | 1–86400，题组可覆盖 |
| 公开延迟秒 | 60 | 0–86400，视频与状态一起遵循延迟 |
| 最大观众数 | 50 | 每比赛名额，1–100000；不是硬件容量保证 |
| 允许看对手屏幕 | 关闭 | 不默认向选手暴露对方原始屏幕 |
| 录像启用 | 关闭 | 正式录像与临时延迟节目是不同用途 |
| 录像保留天数 | 30 | 1–3650；争议保留有独立流程 |

## 保存流程

先读取当前配置，按 Match、计时、媒体分区填写，再保存并重载。离开未保存的页面会提示；不要将本地草稿当成生效配置。

已有赛程后阶段结构、顺序及阶段基础规则锁定，不能靠切换赛制重解释已经产生的结果。降低并行或观众上限先盘点当前占用，对后续入场的约束不代表立即完成全部运行中资源退役。

## 阶段流程

添加阶段后可编辑名称、赛制、先到胜局数和晋级名额，并用上移、下移调整顺序。支持任意多阶段及重复赛制。瑞士轮额外设置累计晋级胜场、淘汰败场，以及晋级关键局、淘汰关键局的先到胜局数。默认门槛为 3 胜、3 负，关键局先到 2 胜（BO3）。

胜局字段表示先到 N 胜，赛程图显示为 BO(2N−1)。瑞士轮晋级名额为 0 表示所有达标队伍；淘汰赛至少晋级一队，完成整阶段后按排名取名额。未添加阶段时按原有单阶段配置执行。

## 阶段覆盖

按流程中的阶段编号、Winners / Losers / GrandFinal / ResetFinal / Swiss 和轮次编号添加 requiredWins 覆盖。同一阶段、lane、轮次不能重复。移动阶段会同步移动其轮次覆盖，删除阶段会删除对应覆盖。

显式轮次覆盖优先级最高；瑞士轮其次使用晋级或淘汰关键局规则，同时满足时取两者较大的胜局数；其余使用阶段默认。淘汰赛没有覆盖时使用阶段默认。已有对局固定其胜局目标，覆盖修改只影响之后生成的对局。

例如常规阶段先到 2 胜、GrandFinal 先到 3 胜，分别配置对应条目。只改阶段或清空阶段也要保存；不要为了清空覆盖把其他配置恢复成旧默认。

## 启用前核对

题组、队伍、名单及所需环境共同决定能否开始。无 Runtime 首题不要求环境隔离回执，容器题须验证隔离。开启“通过平台直播”时，还须媒体服务、全员屏幕共享和节目输出就绪。关闭时不创建媒体房间、不要求共享屏幕、不启动节目或录像，可在未部署媒体服务的环境正常对局。

直播设置在准备 Round 时固定，修改仅影响后续准备的轮次，已经准备或正在进行的轮次保持原要求。既有比赛和轮次升级后保持直播开启，避免改变正在进行的对局；新建比赛默认关闭。关闭后保留历史录像及其原有访问、公开和保密权限，不因关闭而自动公开或删除。

功能开关本身不创建对局、不开始屏幕采集、不启动录像，也不会绕过倒计时前的服务端就绪检查。直播关闭时保留延迟、录像和观众配置，重新开启后可继续使用。

全平台视频尺寸/帧率/码率由 [平台视频策略](../../../platform/video-policy.md)统一维护，比赛不能自行放宽。

静态 Flag 获取证据开关同样只影响后续准备的轮次，关闭它不放宽他队 Flag 归属检查。工作人员下载与历史回看不补记场内获取证据，验证开关时应使用实际上场成员完成正常获取与提交流程。
