# LiveSolo 工作人员对局工作区

工作人员从 `/admin/competitions/比赛ID/live-solo` 选择 Match，进入 `/admin/competitions/比赛ID/live-solo/matches/对局ID`。选手使用 `/competitions/比赛ID/live-solo/...` 下的独立入口。页面按角色返回允许动作，Observer 只读，裁判和管理者各按授权操作。

## 开局前检查

先核对双方、Match、当前 Round、时钟、缺失条件和可用动作。队长锁定名单后，本队任一有效上场成员可确认准备；不要求始终由队长点击。有队伍成员不等于本场名单已锁定或双方已 Ready。

1. 检查 [本场题目池](./question-pool.md)和 [候选题组](./question-groups.md)，处理硬性排除及复用风险。
2. 准备 Round。允许在比赛开始前准备，但开始倒计时仍检查比赛当前状态、版本和双方准备。
3. 检查首题环境。没有 Runtime 的题目应显示无需环境隔离，不要求创建虚假 Runtime 或隔离回执；容器题仍需真实资源与隔离验证。
4. 本轮开启平台直播时，再检查全员 Sharing、媒体和要求的节目/录像输出；关闭直播的轮次不依赖这些服务。
5. 缺失条件消除后开始倒计时，按服务器实际开放时间进入场内，本地时钟不是已开放证据。

直播开关和静态 Flag 获取证据要求在准备时固定。修改比赛设置只影响后续准备的轮次，不能降低本轮已固定要求。

## 准备失败与重试

读取原因，区分 Runtime 类型不支持、配额不足、隔离能力缺失、隔离验证失败和依赖不可用。修复后选择当前 Round 的重试，不必每次失败都新建 Match。

尚未开放的准备可以按允许动作取消，确认状态与占用释放后再准备。后续未开放题目准备失败时，自动流程停止反复重试；工作人员修复后可重试该题，保留当前 Round。重试受理不等于题目已开放，应核对最终状态。

## 运行中与终场

查看当前题、已开放历史、时钟和判定状态。暂停、恢复、作废和弃权见 [裁判操作](./judging.md)。操作时间线位于 `/admin/competitions/比赛ID/live-solo/events`，工作人员任务入口为 `/admin/competitions/比赛ID/live-solo/staff`。

结果以服务器权威记录为准，核对结束原因、实际胜局和修订。弃权不虚构补足到 Required Wins 的比分；超时或作废轮次不凭空产生胜方。无法证明的历史原因或比分显示“未记录”，不能根据当前赛程倒推。

终场结果可手动打开，不必依赖自动弹窗。结果更新不会强行跳离正在编辑的内容，已打开的旧结果不会被新修订静默替换。纠正已完成结果使用 [结果纠正](./corrections.md)，不能用普通 Flag 重判或积分调分替代。

工作人员可按权限预览未来材料；上场成员只可查看已开放历史。复盘及附件证据边界见 [历史题目与结果回看](../../../player/modes/live-solo/review.md)。
