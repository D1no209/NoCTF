# 比赛基本设置

入口：比赛管理 → 配置，路由 `/admin/competitions/比赛ID/configuration`。可编辑者通常为 Administrator、Owner、Manager；当前浏览器入口限制见 [管理手册](../index.md)。

配置页的基本资料与模式规则分别保存，修改其中一块不会自动提交另一块。保存后重新读取并核对，尤其是时间、访问策略和上传大小。

## 时间、报名与访问

| 配置 | 含义与使用场景 |
| --- | --- |
| 标题、说明 | 比赛公开介绍，规则更改应同步公告 |
| 开始/结束 | 绝对起止时间，暂停不延长 EndAt |
| 报名自动审核 | 合法报名直接 Approved；关闭时交给管理者审查 |
| 赛中报名 | Running 中是否开放组织变化；变化后仍需重新报名 |
| 最大成员数 | 每队人数上限 |
| 每队并发 Runtime | 当前模式需要同时运行的实例额度 |
| 仅工作人员 | 使用 StaffOnly 访问，适合内部验证；不等同内部赛道 |
| 赛后练习 | 仅适用 CTF，正式结束后练习不计正式分 |

不要将“公开访问”“比赛 Published”“题目已发布”“队伍 Approved”合成一个开关。它们分别控制比赛发现、生命周期、内容和选手资格。

## Runtime 访问方式

| 模式 | 访问路径 | 对流量采集的影响 |
| --- | --- | --- |
| Direct | 选手使用题目公开主机/端口直连 | 直连不会自动经过 WSRX 采集 |
| DirectAndWsrx | 同时提供直连和 WSRX 路径 | 存在直连绕过，抓包不是全部题目流量 |
| WsrxOnly | 通过平台 WSRX 路径访问 | 适用于需要通过平台入口的连接，仍需验证实际业务支持 |

WSRX 是平台 Runtime 访问通道，不是给 Docker 题目新增 HAProxy。Docker 对外公开映射仍由题目服务自己的随机端口提供。选择策略前用实际题目验证访问入口、连接数量和会话期限。

## 流量采集

开启抓取后按配置记录经过受支持平台代理路径的流量。界面以 MiB 配置上限，后端以字节保存，1 MiB 为 1,048,576 字节。留空使用平台策略；具体平台默认和最大值查看部署配置。

Direct/混合方式的直连部分不会被这项开关凭空捕获。到达上限的截断文件只能作为部分证据。保存策略后用一次已知连接验证 [抓包列表](../operations/traffic-captures.md)，不要因开关开启就宣称完整流量可审计。

## 咨询策略

设置每队活跃问题上限，以及工作人员回复前允许的参赛者消息数量。额度用于控制重复咨询，不会把不同问题合并；达到限制时应处理已有线程，而不是要求队伍开更多账号。

“允许题目负责人处理咨询”扩展相应题目咨询的处理关系，不授予比赛配置、排行榜或其他队伍全部管理权限。见 [咨询处理](../communication/questions.md)。

## 题解策略

可要求队伍提交 PDF，设置比赛结束后允许提交的扩展小时。最终截止为 EndAt + 扩展小时，0 为 EndAt。修改 EndAt 也会改变计算的截止时间，要通知参赛者重新核对。

是否必交和是否允许自愿提交不同；不强制仍可按期限提交。见 [题解审核](../judging/writeups.md)。

## 保存与验证

1. 在对应分区修改值，先检查当前比赛 UUID。
2. 保存基本资料，等待成功并重新打开核对。
3. 另行保存模式配置，检查计分和调度影响。
4. 用选手账号验证访问/报名/WSRX/题解策略。
5. Running 中改变规则时发布准确的生效说明。

出现业务冲突时读取具体 failure code；不要统一解释为并发 revision 冲突。需要换 Provider/Runner Pool 时找运维修改部署，它们不在比赛配置中选择。
