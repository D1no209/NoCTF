# 举办第一场比赛

本教程先创建一场单题静态 CTF，验证报名、Flag 和计分，再扩展到容器题或其他模式。按当前浏览器管理入口使用 Administrator 账号，平台已通过 [安装验收](../installation/verify.md)。后台 Organizer/协作者 API 权限与当前页面入口的区别见 [比赛管理导读](./index.md)。

## 1. 准备赛事规则

先确定模式、UTC 起止时间、人数上限、是否自动审核、是否允许赛中报名、赛道、题解截止与计分规则。第一场测试使用固定分数和简单 Flag，减少环境因素。

正式比赛前准备已审查题目、联系渠道、值守人员和故障处理规则。不要边开赛边决定计分政策。

## 2. 创建 CTF 比赛

在“竞赛”浏览页右上角打开创建弹窗，选择 CTF，填写标题、说明和起止时间。保存后检查列表已选中新比赛，状态为 Draft；再进入该比赛管理。确认 Owner 和页面时区，结束时间在开始之后。

在“配置”设置默认固定计分，例如 100 分、最低分 100，先关闭错误罚分和血奖。测试可选择自动审核；正式比赛按管理需要设置。

## 3. 创建题库模板

进入题库管理，新建 CTF 模板：

1. 设置标题、方向、题面和可见性。
2. 使用静态 Flag，例如仅测试用的 `flag{welcome_to_noctf}`。
3. 不启用 Runtime 或 Checker。
4. 保存，记录模板 ID。

模板只属于一种模式。题库中的技术定义和比赛中的分数/发布规则分别配置，详见 [题库与比赛题目](../challenge-bank/templates.md)。

## 4. 引用为比赛题目

打开比赛管理“题目”，引用刚创建的模板。配置比赛展示名称、排序、CTF 规则和提示，发布题目。比赛 Start Gate 要求至少一个有效已发布题目，单纯保存模板不够。

在预览中检查题面和附件。若选择模板通用 Flag，确认没有意外配置互斥的比赛专属 Flag。

## 5. 准备参赛队伍

用普通测试账号打开赛事。组织者先将比赛从 Draft 变为公开的 Visible/Published，使其处于允许报名窗口。

普通账号建队得到 Unregistered，队长完善资料后提交报名。未开启自动审核时，在管理“队伍”中批准为 Approved。管理员/Owner 自己看到题面不代表普通队伍权限正确，必须用选手账号验证。

## 6. 开始比赛

时间到达会触发合法公开比赛的 Start Gate；也可由 Owner/Manager 手动开始。检查比赛变为 Running。

如果返回错误列表，按具体题目、队伍、配置路径逐项修正，再开始。错误可能包括无已发布题目、Flag 缺失、时间结束、无 Runner、额度不足或模式不匹配。

## 7. 验证提交与排行榜

用 Approved 测试队打开题目，先提交一个错误 Flag，再提交正确 Flag。等待最终结果，检查排行榜分数、解题状态、动态和实时刷新。重复正确提交不应得到第二份解题分。

必要时由裁判查看尝试记录，确认页面显示、事实结果与榜单一致。之后再添加容器题，验证 [Runtime 与 Checker](../challenge-bank/runtime-checkers.md)闭环。

## 8. 结束测试并准备正式赛事

Finish 不可恢复，测试结束后回收实例并保留验收记录。正式比赛使用独立比赛配置和审核题目，不复用测试题的公开 Flag。确认资源容量、备份、公告、队伍资格和所有协作者权限，再开放报名。

进阶阅读 [赛事配置](./settings/scoring.md)、[生命周期](./operations/lifecycle.md)和 [评测与调分](./judging/submissions.md)。
