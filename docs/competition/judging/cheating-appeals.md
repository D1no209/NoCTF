# 作弊调查、封禁与申诉

入口：比赛管理 → 作弊，`/admin/competitions/比赛ID/cheats`；队伍封禁与申诉在队伍管理中处理。线索、裁定、队伍资格和公开纠正是不同层次。

## 阅读作弊线索

按状态、时间和相关题目/队伍筛选，打开详情核对关联 GameplayFact、Flag、队伍与证据。系统线索只能支持调查，不能仅凭一个颜色状态认定作弊。

| 状态 | 理解方式 |
| --- | --- |
| Pending | 待调查/处理 |
| Confirmed | 已确认线索对应的问题 |
| Dismissed | 已驳回 |
| Superseded | 已被其他处理替代 |
| Corrected | 对此前处理进行了纠正 |

读取 Flag 原文使用专门受保护操作并遵循理由/审计规则。抓包证据可能截断，见 [流量抓取](../operations/traffic-captures.md)，不能把没有抓到的直连行为当作不存在。

## 处理线索

1. 记录事实 ID、时间、模式和当前轮次，保留证据。
2. 核对是否为合法同队提交、旧 Runtime、错误作用域或平台问题。
3. 在详情选择允许的裁定动作，填写原因和页面要求的确认。
4. 保存并重新读取线索状态。
5. 分别检查队伍资格、Runtime 回收、榜单和公开播报。

权限只读时不要假设能操作确认/纠正。Judge 的评测权限不自动包含全部队伍封禁裁决；按对应授权动作判断。

## 封禁队伍

队伍管理选择目标、填写原因并确认。Ban 立即拒绝参赛私有数据和新操作，回收适用 CTF/AWD 环境，并将该队及相关攻防事实排除投影。

封禁一个比赛队伍与停用平台账号不同，不因此禁止用户参加所有其他赛事。原始原因和内部证据不自动公开，公开事件只包含允许展示的内容。

## 处理申诉

队长针对对应封禁事件提交一次私密申诉，全队可读。管理者进入队伍申诉列表，读取理由、原始封禁和证据，选择接受/拒绝并说明裁定。

Administrator、Owner、Manager 可裁决，Judge/Observer 按读取权限查阅。接受申诉或主动纠正关联原始封禁，保留公开纠错与私密证据边界，不删除原事件伪造历史。

## 解除之后

历史投影按当前事实恢复。CTF 环境由选手重启，AWD 按系统重新配置；Finished 不重新配置正式 Runtime。赛后仍可以纠正历史资格/成绩，但不能将比赛恢复为 Running。

正式结果交付前逐一核对未处理申诉，避免一边宣布终局榜一边尚未完成资格审查。
