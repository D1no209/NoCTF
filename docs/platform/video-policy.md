# LiveSolo 平台视频资源策略

入口：平台设置 → 实验功能 → LiveSolo 视频资源。仅平台管理员修改；比赛、队伍和选手不能扩大此策略，前四赛制不加载媒体 SDK。

| 字段 | 默认 | 允许范围 |
| --- | --- | --- |
| 最大宽度 | 1280 px | 320–3840，偶数 |
| 最大高度 | 720 px | 180–2160，偶数 |
| 最高帧率 | 10 FPS | 1–30 |
| 每屏最高码率 | 1000 Kbit/s | 128–8000 |

界面 Kbit/s 为十进制，1000 bit/s = 1 Kbit/s；数据库/API 使用 bit/s。宽高限制保持比例，不放大小来源。确认全部整数和偶数约束，保存后重载核对。

## 生效范围

NoCTF 浏览器在下一次媒体刷新调整当前轨道和编码器，无需重启 Match/媒体房间。新共享、重连和替换轨道都重新应用约束；不支持约束时停止共享并报错。

Programme 整路合成用一份相应输出预算，不按屏幕路数相乘；当前任务保留启动参数，新分段/任务读取新策略。单轨录像使用 PASSTHROUGH，来源的实际变化会反映到后续内容。

录像/Programme 保存启动策略标识，旧任务没有快照时显示未知，不推断历史参数。降低码率不减少已有三份容量预留，清理原始副本后才释放。

## 修改流程

1. 查看当前规则、码率单位和预计屏幕内容。
2. 在隔离比赛测试较低策略下代码/终端文字是否可读。
3. 保存平台视频分区，不误改同页 CTF 实验开关。
4. 看实际发送统计、服务端 Sharing 与解码内容，再判断质量。
5. 记录实际网络/存储消耗并按真人负载验收。

目标编码码率不是网络硬上限，RTP 重传与协议开销另计。浏览器约束也不等于已经验证了针对恶意自定义发布器的 SFU 硬限制。

媒体部署、录像和容量分别见 [媒体部署](../installation/live-solo-media.md)、[录像](../competition/modes/live-solo/recordings.md)、[就绪验收](../operations/live-solo-readiness.md)。
