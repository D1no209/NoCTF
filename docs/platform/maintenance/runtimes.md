# 平台跨比赛运行实例

本页重点说明平台跨比赛实例工作区，入口 `/admin/platform/runtimes`；技术日志已经拆到 [日志查询](./logs.md)，操作历史看 [审计](./audit.md)。单场实例的启动/续期见 [比赛 Runtime](../../competition/operations/runtimes.md)。

## 过滤与关联资源

按平台列表提供的状态、作用域和关联资源等筛选，应用后回到第一页；清空筛选回到完整当前查询。此页主要查看活动/当前管理范围，不能保证保留所有停止历史。

点击详情打开嵌入列表的抽屉，读取关联比赛、模板/比赛题目、队伍、purpose、运行地址与资源。TemplateTest 显示模板关系，没有正式队伍；共享环境没有普通队伍归属。通过资源链接进入准确的管理页。

平台列表自动刷新，仍需区分已发起终止与最终 Stopped。普通终止和强制终止各有独立弹窗；强制操作填写原因并确认，受理后查外部回收，不认为立即成功删除。

## 平台 Runtime 管理

从“平台管理 → 运行实例”查看跨比赛的环境，结合比赛、题目、队伍、purpose、状态、Provider 与实例 UUID 筛选。比赛管理的实例页只处理该比赛范围。

| 检查点 | 判断目的 |
| --- | --- |
| Runner 在线与 Pool | 请求能否被正确执行域接收 |
| 实例状态和错误码 | 区分排队、拉镜像、创建失败和回收失败 |
| 实际容器/Pod | 外部资源是否与业务记录一致 |
| 访问入口 | 页面地址是否最新，公开端口是否可达 |
| TTL / 配额 | 到期、额度与资源预留是否合理 |

Runtime reset 创建新 UUID。报障记录旧/新实例和发生时间，不把端口当作永久身份。

## 停止与清理

优先通过授权管理操作停止实例，等待幂等清理完成。业务回收可能涉及容器、Pod、实例专属网络和端口；单服务共享 bridge、callback bridge、共享 namespace 不属于某个实例，不应随手删除。

回收失败先确认 Runner、Provider API、网络和超时，再使用受控维护流程。不要全局 Docker prune、删除整个 Runtime namespace 或改数据库状态假装已回收。

## 平台日志

“平台管理 → 日志”读取私有 Loki 中已脱敏内容。Docker 基础安装默认关闭观测，未安装 Loki 时页面不能凭空显示正常日志；按 [监控](../../operations/monitoring.md)接入。

搜索时组合有限时间窗口、角色/来源、级别、比赛/题目/队伍/Runtime/GameplayFact ID。日志用于定位技术失败，最终业务状态仍读数据库投影。

受保护日志中的 UserId 使用内部加密字段，管理员 reader 解密后支持过滤。所有 Host 角色共享 RunnerScoring key；轮换后保留窗口可能不可读，先制定审计导出计划。不可读文档应报错，不能当作“无日志”。

## 审计与业务事件

平台审计、赛事动态和技术日志用途不同。敏感 Flag 读取、封禁裁定和强制删除等需要对应审计/事件；不要以 Loki 中没查到某行断言不存在业务事实。

强制比赛删除有状态、资源和确认限制，永久删除作用域历史，不用于常规维护。先备份并确认实际目标和业务原因，保留平台审计事实。

## 报障资料

提供部署 digest、发生时间/时区、角色、资源 UUID、稳定 failure code 和少量脱敏日志。不要附原始 Flag、JWT、密码、邀请码、SQL 参数或完整 Secret。分享受限日志前核对接收者授权。
