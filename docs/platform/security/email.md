# 邮件验证、SMTP 与密码找回

入口：平台设置 → 邮件与人机验证，`/admin/platform/email` 的邮件分区。SMTP 普通配置、SMTP 密码替换和人机验证各自保存。

## 字段说明

| 字段 | 作用 |
| --- | --- |
| 邮箱验证启用 | 是否要求新 Human 完成邮箱验证才能登录 |
| Public Base URL | 邮件中的平台链接，使用真实 HTTPS 入口 |
| 验证有效期分钟 | 邮箱验证链接的时间预算 |
| 重发冷却秒 | 同账号请求的间隔 |
| 密码重置有效期分钟 | 找回链接期限，区别于注册验证 |
| 重置冷却秒/每小时上限 | 控制重复申请 |
| SMTP Host/Port | 邮件服务地址，不填网页 URL |
| 安全模式 | None、SslOnConnect、StartTls，匹配邮件服务实际要求 |
| 用户名、发件地址、发件名称 | 邮件服务认证和收件人展示 |
| SMTP 超时秒 | 单次发送执行预算 |

选择 StartTls 与 SslOnConnect 不只是换端口，按自己的 SMTP 服务契约填写。实际默认从已保存配置读取，不用旧教程里的固定限额覆盖当前值。

## 配置步骤

1. 填 Host、Port、安全模式、用户名和发件人。
2. 在单独密码入口替换 SMTP 密码并保存。
3. 保存普通邮件字段，重新加载核对 secret 已配置状态。
4. 点击发送测试邮件，当前测试发送给管理员邮箱。
5. 检查真实收件箱/垃圾邮件，确认公开链接正确。
6. 再决定启用注册邮箱验证，并用新测试账号完成验证和登录。

测试发送已受理不证明收件箱必达；同时检查邮件服务投递、域名策略和网络。Secret 不回显，留空表单不是清除旧密码。

## 密码找回

密码找回独立于注册验证开关，只适用于 Active、邮箱已验证的 Human。合法请求统一 Accepted，不根据响应猜账号是否存在。

用测试账号验证请求、接收、新密码、令牌失效和重新登录。重置不会自动登录，旧 TokenVersion 会失效；最近申请可能让旧链接失效。

## 管理员标记邮箱

用户详情提供设置/撤销邮箱验证状态，见 [账号管理](../users/accounts.md)。它是管理员校验身份后的操作，不等于 SMTP 链路正常，也不应当作邮件故障的默认修复。

## 部署前置与错误

所有相关角色需要稳定的 EmailVerification 加密 key；Kubernetes 还要精确 SMTP egress。域名改变更新邮件 PublicBaseUrl，不能只改反代。

EmailDeliveryNotConfigured 检查配置完整；SmtpPasswordInvalid 检查 secret；SmtpDeliveryFailed 查认证、TLS、DNS/egress和实际日志。启用验证后邮件故障会影响新用户进入，先测试再开启。
