# 平台信息、名称与 Logo

入口：平台设置 → 平台信息，`/admin/platform`。信息读取与品牌表单由两个请求加载，失败时先修复读取，不能靠在空表单保存覆盖旧配置。

## 名称和说明

填写非空平台名称和可选说明，保存后重新载入验证。空说明按空值处理；名称用于站点导航、页面标题和分享信息，不是数据库名或 Docker 项目名。

保存后重新读取当前平台资料。平台名称变更无需重命名持久安装目录，Runtime Provider 仍通过部署配置管理。

## 平台公开地址

在本页填写平台公开地址，例如 `https://ctf.example.com`，保存并重新读取。邮件验证、密码找回、SSO 回调、比赛 Webhook 和工作人员 Webhook 中的平台链接统一使用此地址。邮件和认证页面不再单独维护地址。

首次安装后，先配置实际公开地址，再测试邮件、身份绑定和 Webhook 链接。地址应对应用户实际访问的平台入口，填写前确认域名解析、HTTPS 证书和反代已经就绪。

更换域名时按以下顺序操作：

1. 准备新域名、证书和反向代理，核对平台及文件入口可达。
2. 在部署配置更新精确 CORS、Refresh Origin、人机验证来源和相关 Cookie/Passkey 配置。
3. 在平台信息保存新的公开地址，并同步身份提供方登记的回调 URL。
4. 发出新的验证或找回邮件，完成一次 SSO 测试，检查 Webhook 中的平台链接。
5. 以普通用户验证刷新登录、文件访问和题目连接。

已经发出的邮件、已保存的外部消息和书签仍可能包含旧地址，应按迁移安排保留必要访问。修改平台公开地址不会自动修改 DNS、证书、部署允许来源或对象存储域名。

## 上传 Logo

点击 Logo 上传选择真实受支持图片，等待上传成功和服务器返回的 URL，再检查导航与公开页面。旧对象清理由文件生命周期处理，不手工删除 uploads 中猜测的文件。

文件名正确不代表图像内容有效，格式、尺寸、动画帧和像素等规则由上传端点校验。失败先检查提示，保留原 Logo。

## 公开元数据验证

平台名称、描述和 Logo 会供 API 的 SPA HTML fallback 生成元数据。更新后检查公开页面的标题、分享图与链接 Origin，而不是只看已登录浏览器内存里的标题。

域名变更仍需部署 Origin、SSO、Cookie、文件 HTTPS 和代理同步，不靠名称/说明字段处理。默认前端 ssr:false 不表示分享元数据全部只能由浏览器生成。

## 平台信息区

按实际响应查看当前版本和可用运行信息，用于排障时与部署 digest 对照。此页不替代 Docker/Kubernetes 的角色、存储和镜像状态查询，不从 UI 版本文本推断所有基础依赖已升级。
