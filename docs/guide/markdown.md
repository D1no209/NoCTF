# Markdown 编辑与预览

比赛介绍、题目说明等内容使用实时 Markdown 编辑器。正文在同一编辑区呈现标题、列表、表格和代码块的预览；进入对应内容编辑时显示需要修改的源文本，移开光标或离开编辑区后恢复预览。

## 编写与检查

1. 进入有权限编辑的比赛、题目、公告或题解，确认当前资源。
2. 输入 Markdown；使用标题组织段落，用列表写步骤，用代码围栏保留命令和缩进。
3. 编辑表格或代码块时核对源文本，离开该区域检查预览结果。中文输入法组合输入期间先完成选词，再移动光标。
4. 检查链接目标、图片、代码语言和表格内容；长代码应保持可横向阅读，避免用空格模拟表格。
5. 点击所在页面的保存或提交按钮，重新打开内容确认持久保存，再以目标读者身份检查访问权限。

实时预览只反映编辑内容。公告发布、题目保存、题解送审仍使用各自业务按钮，预览更新不会自动执行这些操作。

## 代码、表格和 HTML

代码围栏可指定语言，例如 `bash`、`python` 或 `json`。需要把 HTML 当作示例展示时，将其放在 `html` 代码围栏内。表格使用 Markdown 的表头和分隔行，编辑后核对每列对应关系。

平台支持经过安全过滤的 HTML 排版，例如右对齐署名：

```html
<div style="text-align: right">出题人：<strong>Example</strong></div>
```

预览与发布内容使用受限的标签、属性和样式。脚本、iframe、表单、事件属性及危险 URL 会被过滤；固定定位、外部样式等内容也不能用于接管页面布局。只使用正文必要的排版，预览缺失时先检查是否使用了受限内容。

## 图片和授权

通过当前内容页面提供的上传入口添加图片，等待上传完成再保存正文。理论题目与试卷图片受独立授权控制，外部图片不会自动加载；切换试卷后，上一份试卷的图片权限不能沿用。

题面预览成功不代表参赛者拥有附件权限。发布前分别检查正文、图片和附件，并用普通参赛账号确认开放时间、队伍资格和读取范围。

## 草稿与多人编辑

留意页面的未保存提示。比赛配置在实时数据刷新时保留已修改字段，未修改字段可继续更新；关闭页面、切换比赛和其他编辑界面的草稿规则仍需按各自提示处理。

遇到版本冲突，保留需要的文本，重新读取服务器内容后协调修改并保存。遇到读取失败先恢复读取，避免用空表单覆盖已有正文。
