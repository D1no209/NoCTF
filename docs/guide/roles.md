# 角色与权限

权限分为平台角色、比赛协作者角色、题库管理关系和队伍关系。仅被授予 Organizer 并不意味着能编辑其他组织者的全部比赛。

## 平台角色

| 角色 | 常见使用场景 |
| --- | --- |
| User | 注册、参赛、查看有权访问的比赛与本队信息 |
| Organizer | 创建比赛和题库，管理自己拥有或被授权的资源 |
| Administrator | 全平台管理、账号授权、配置、资源诊断 |

公开注册只创建普通 Human/User。Organizer 和 Administrator 由平台管理员授予。Bot 是账号种类，和角色独立；Bot 使用管理员签发的访问令牌，不通过密码登录或 Refresh Cookie 登录。

此表说明后台能力。当前 SPA 的比赛管理路由和入口仅对 Administrator 开放；Organizer 或比赛协作者后台授权不等于当前浏览器工作区可进入。比赛创建位于竞赛浏览页弹窗，没有独立管理列表页，详见 [管理入口](../competition/index.md)。

## 比赛协作者

| 角色 | 可操作范围 | 主要限制 |
| --- | --- | --- |
| Owner | 比赛完整管理、权限与所有权管理 | 只有一个所有者 |
| Manager | 配置、题目、团队、生命周期、Runtime、评测 | 不管理所有权及协作者权限 |
| Judge | 评测查询、重判和运行诊断等裁判操作 | 不修改比赛配置、团队或生命周期 |
| Observer | 管理读取 | 没有写权限；内部赛道有额外可见性限制 |
| Player | 公开内容与本队私有内容 | 无法读取其他队的 Flag 和内部诊断 |

Owner/Manager 需要 Organizer 或 Administrator 平台角色；Judge/Observer 需要完成邮箱验证。同一个账号在一场比赛只担任一个协作者角色。所有权转让后，旧 Owner 成为 Manager。

## 为赛事配置人员

1. 管理员为主办账号授予 Organizer。
2. 主办账号创建比赛，成为 Owner。
3. 在比赛管理“权限”中添加 Manager、Judge、Observer。
4. 分别用被授权账号登录，检查可见菜单与实际读写权限。
5. 比赛结束后按需撤销协作权限和自动化账号令牌。

题库模板还有独立的 Owner/Manager。被授权管理比赛不自动获得所有被引用模板的敏感定义编辑权。

## 看到 403 或 404 时

先确认当前登录账号、平台角色、比赛协作者身份和队伍状态。不可见资源可能与不存在资源一样返回 404，不能只凭这个响应断言资源已删除。若刚调整了账号角色，原有访问令牌会失效，需要重新登录。
