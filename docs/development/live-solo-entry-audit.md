# LiveSolo 入口与赛制集成审计（2026-10-10）

本次审计针对合并到 main 后的 LiveSolo 前端入口、题库作者流程、赛制导航和工作人员权限。后端赛制枚举、模板分支、独立 Match/Round 接口已存在；创建入口仍保留四赛制列表，导致这些能力无法从正常界面使用。

## 已修复

| 位置 | 缺口 | 修复 |
|---|---|---|
| 竞赛列表的新建弹窗 | 没有 LiveSolo 选项 | 五赛制共用强类型选项目录；创建请求提交 `LiveSolo`，不携带 CTF 练习开关 |
| 题库新建模板、模板模式定义 | 选项缺失；切换函数拒绝 LiveSolo | 共用选项和类型守卫，切换后使用唯一 `liveSolo` 定义分支 |
| 题库列表及详情徽章 | LiveSolo 显示为破折号 | 正确显示 LiveSolo |
| LiveSolo 模板运行环境 | 没有动态 Flag 开关，提供了 AWD 轮换选项和参赛者共享入口 | 使用静态／队伍动态 Flag 开关，作者控件仅提供本队访问；保留容器及 OVA 定义 |
| 模板模式定义及 Flag 页面 | 动态 Flag 模板和注入提示缺失 | 接入 LiveSolo 动态模板覆盖、系统管理 Flag 提示及静态正则 Flag 能力 |
| 保存运行环境后切到模式定义 | 模式草稿仍使用旧 Runtime，动态配置暂不出现 | 同步已保存 Runtime，保留尚未保存的模式字段 |
| LiveSolo 题组复制 | 前端候选只包含 CTF，后端已支持原生 LiveSolo | 加入未删除的 LiveSolo 模板；仍排除 CTF 补丁题与其他赛制 |
| 竞赛管理导航 | 缺少独立工作区，提供无效的 CTF 大屏及普通积分榜 | 增加大厅、设置、题组、赛程；隐藏 LiveSolo 普通计分板；CTF/AWDP 大屏仅在对应赛制出现 |
| 比赛基础配置中的赛制配置 | 通用编辑器对 LiveSolo 没有字段 | 明确链接到独立 LiveSolo 设置，避免提交空的通用配置 |
| 新建草稿竞赛的工作人员页面 | 公共详情接口始终排除草稿，设置页误判为只读 | 现有工作人员授权允许读取草稿，并返回真实角色；响应为私有、禁止缓存；匿名和非工作人员仍为 404 |
| 首页终端赛制介绍 | LiveSolo 文案域未加载，显示资源键 | 首页按需加载赛制介绍所在语言域 |
| 模板保存前校验 | 未检查 LiveSolo 独立 Runtime 与禁止 Checker／补丁交互 | 对齐现有后端校验，提供中英文错误 |

## 核对后保留的边界

- LiveSolo 使用独立大厅、对阵赛程、Round 时钟、入场顺序结果、延迟节目和赛后题解；普通四赛制题目面板、积分榜、大屏、闯关图和题目绝对时间设置不应直接加入 LiveSolo。
- 题库投放按模板和竞赛赛制精确匹配；跨赛制转换使用题组页面的显式复制流程。
- Judge／Observer 可读不代表可修改赛制设置；写权限继续由 Owner／Manager／平台管理员的服务端授权决定。
- 媒体能力、录制开关和 LiveSolo 开关仍使用已有配置。创建竞赛和模板不会启动录制或采集屏幕。

## 验证

- 前端行为测试覆盖创建请求、定义分支切换、运行环境能力、保存后的跨分区同步、模板校验、徽章、五赛制导航及复制候选。
- PostgreSQL、Redis、NATS Testcontainers 与真实 HTTP 验证 CTF／LiveSolo 草稿详情：平台管理员、所有者、Manager、Judge、Observer 的角色正确；匿名及无协作权限的人类账号不能读取；工作人员响应禁止缓存。保留 StaffOnly 比赛的既有访问测试。
- 浏览器使用本地隔离数据库和合成账号，实际创建 LiveSolo 竞赛、模板，保存 Runtime 与胜场设置；检查选项、语言、主题及窄屏。
- 执行后端构建、相关 TUnit、`bun test`、`bun run typecheck`、`bun run audit:architecture`。

本次未修改数据库模型、OpenAPI 契约或 Wolverine Handler 依赖，不需要迁移或重新生成 SDK／适配器。此审计不是媒体传输、录像泄露或全部赛制端到端流程的重新认证。
