# 页面字段说明：看名称，不看配置代码

这份说明只解释后台中文界面中的输入项。**实际要填的值见 [后台逐项填写表](CONFIGURATION.md)**；
运维不需要换算成字节、纳核，不需要生成 UUID，也不需要编写配置代码。

## 基本信息

| 页面名称 | 是什么意思 | 留空或填错会怎样 |
| --- | --- | --- |
| 标题 | 题目名称，必填，最多 160 字符 | 空白无法保存 |
| 游戏模式 | 题目的玩法；本套是 AWDP | 选错会出现不同配置项；先选模式再填写 |
| 可见性 | 题库模板是否与其他组织者共享 | 不决定选手能否看到比赛题目 |
| 方向 | Web、Pwn 等分类，必填，最多 96 字符 | 不是比赛模式，也不是镜像名 |
| 题面 | 直接展示给选手的说明，支持 Markdown | 不能包含 PoC、标准修补、内部部署资料或真实 Flag |

## 运行环境与启动

| 页面名称 | 是什么意思 | 留空或填错会怎样 |
| --- | --- | --- |
| 选手需要在线运行环境(容器靶机) | 是否为题目启动容器 | AWDP 要开；关掉不是节省资源的正确方式 |
| 分配方式 | 每队使用自己的实例还是共用实例 | AWDP 显示每队独立，无需修改 |
| 运行环境类型 | 单容器或其他运行形式 | AWDP 仅支持单容器 |
| 镜像 | Runner 实际能找到或拉取的完整镜像名称 | 名称、下划线、标签不同都会找不到镜像 |
| 启动命令 | 覆盖镜像的启动参数；每行一个参数 | 本模板留空；不要填写 docker run 或把所有参数挤在一行 |
| Flag 环境变量名 | 靶机接收平台动态 Flag 的变量名字 | 填 FLAG，不填真正的 Flag 内容；程序也必须读取这个变量 |
| 环境变量 | 题目额外需要的“变量名—值” | 本模板留空；不得覆盖平台保留变量 |
| 标签 | 容器附加标识，不是题目方向 | 大多数题目留空，不用于传递密码 |

## 网络与访问入口

| 页面名称 | 是什么意思 | 本套规则 |
| --- | --- | --- |
| 对外端口 | 靶机程序在容器里监听的端口 | 填 8080；不能填主机随机分配的 327xx |
| 内部端口 | Checker 检查靶机时使用的端口 | 恰好一项，与对外端口和服务监听端口一致 |
| 访问入口 | 选手看到的连接地址或连接命令 | 本题添加一条 |
| 显示模板（旧版为 URL 模板） | 平台替换主机地址和随机端口后显示给选手 | HTTP 示例 http://{HOST}:{PORT}；TCP 题可以是 nc {HOST} {PORT} |
| 暴露范围 | 谁能看到这个入口 | AWDP 选“仅队伍自己可见” |
| 容器端口 | 这条访问入口对应哪个服务端口 | 与前面两个端口一致；范围 1–65535 |
| 服务名(Compose) | 多容器中的服务名字 | 本套 AWDP 单容器不会出现，不用寻找或填写 |

显示模板只允许大写 `{HOST}` 和 `{PORT}` 这两个占位符。它允许自定义连接文字，不要求所有文字都是网址。
端口改动后需要重新创建实例，旧实例不会自动改映射。

## 安全选项

| 页面名称 | 是什么意思 | 本教学模板／换镜像时注意 |
| --- | --- | --- |
| 禁止提权(no-new-privileges) | 阻止程序获得额外权限 | 开；不代表自动获得其他所需权限 |
| 只读根文件系统 | 阻止对容器根文件系统写入 | 关；否则修补可能无法落盘 |
| 以非 root 用户运行 | 检查镜像声明的运行用户不是 root | 开；换镜像后必须检查它是否声明数字非零用户，不能单靠开关自动创建用户 |
| 移除的能力(cap-drop) | 移除 Linux 特殊能力 | 保留 ALL |
| 增加的能力(cap-add) | 按需补回个别能力 | 本题留空；xinetd/chroot 等镜像由出题人列出最小需求，不应全部放开 |

这张表针对本教学镜像，不适用于所有镜像。比如镜像启动时必须用 root 创建文件，就要先改造镜像权限，
或由负责人重新审核本题设置；不要盲目照抄“开”。

## 资源与生命周期

| 页面名称 | 页面单位／填写规则 | 本教学模板 |
| --- | --- | --- |
| 内存(MiB) | 大于 0 的 MiB 数，不是字节数 | 256 |
| CPU(核) | 大于 0 的核数，可填小数 | 0.5 |
| 进程数上限 | 正整数，线程也受此类限制影响 | 128 |
| 实例存活时间(秒) | 1–604800 秒，决定实例能保留多久 | 3600 |
| 操作超时(秒) | 1–300 秒，容器操作的等待时间 | 60 |

页面可能显示默认值占位提示，但出题交付应明确填好。单实例资源不是整个 Runner 总配额；
增加实例存活时间不会修复 Checker 超时。

## 模式定义：补丁与 Checker

| 页面名称 | 是什么意思、范围 | 本教学模板 |
| --- | --- | --- |
| 补丁入口 | 选手包内要执行的相对文件路径，最多 256 字符，不得越界 | fix.sh |
| 补丁应用命令 | 每行一个参数，最多 64 项；最多一项独立的 {entrypoint}，非空自定义命令必须含这一项 | 第 1 行 /bin/sh，第 2 行 {entrypoint} |
| 补丁超时(秒) | Patch 执行上限，1–300 秒，留空通常为 60 秒 | 60 |
| 就绪超时(秒) | 应用修补后等待服务就绪，正数且不超过 Checker 超时 | 30 |
| Fix 包上传上限(MiB) | 限制上传的压缩包大小，默认 256、最大 1024 MiB | 256 |
| 启用 Fix 一次性验证 Checker | 是否运行防御验证器 | 开 |
| 镜像（Checker 区域） | 评测镜像，不能误填成 Target 镜像 | noctf-awdp-v2-checker:local，正式交付改成完整可拉取名称 |
| 启动命令（Checker 区域） | Checker 的启动参数，每行一个 | 留空 |
| 环境变量（Checker 区域） | Checker 的额外设置，不继承靶机环境变量 | 留空；平台自动注入靶机地址和回调凭证 |
| 超时(秒)（Checker 区域） | Checker 总执行预算，1–1800 秒 | 120 |
| 向 Checker 提供 Fix 包 | 启动前把选手包副本放入 Checker 的 /noctf/fix | 本题开；不等于复制修补后的靶机磁盘 |
| 允许 Checker 以 root 运行 | 默认关闭，要求 Checker 镜像声明非零数字 USER；开后允许镜像使用 root，不强制切换用户 | 本教学模板关；只对确实需要 root 的可信 Checker 开启，不改变 Target 或 Patch 用户，不解除能力限制、禁止提权或网络隔离 |

不要把 `{entrypoint}` 误写成 `entrypoint`，也不要把它与 `/bin/sh` 放在同一行。
Fix 失败、服务异常、Checker 平台故障是不同结果，基础设施异常不能当成“防御成功”。
读取 Fix 后的文件请看 [Checker 文件读取说明](../private/CHECKER-FIX.md)。

## 附件、测试和比赛题目

| 页面名称 | 填写或操作规则 |
| --- | --- |
| 交付模式 | 本题选“全部附件”；随机附件需要独立设计，不是这里默认开启的选项 |
| 上传普通附件 | 仅上传出题人明确列出的公开文件，绝不能选整个 private 目录 |
| Flags | 本 AWDP 模板由运行环境注入动态 Flag，不维护静态 Flag 列表 |
| 启动测试容器 | 先保存，再启动；只证明启动成功不等于功能和评测全部通过 |
| 重置测试容器 | 修改运行配置后按页面允许操作重置，会得到新实例和可能不同的端口 |
| 本次测试 Flag | 只用于验证真实注入，不放入文档或公开附件 |
| 比赛题目名称 | 只改本场展示名，留空用题库标题 |
| 顺序 | 非负整数，由赛事负责人分配 |
| 发布该题目(对选手可见) | 验收前关，验收后再开 |
| 题目规则中的覆盖开关 | 关表示继承比赛规则；开后才填写本题特殊值 |
| 提示内容 | Hint 正文，不能为空 |
| 扣分 | 解锁 Hint 扣除的分数；0 免费，范围 0–1000000 |
| 发布时间(可选) | 留空为未发布；使用页面日期时间控件填写，不手写后台时间格式 |

创建 Hint 在“比赛管理 → 题目 → 该题目 → 提示”，不是题库模板的附件页。
没有 Hint 就不添加。页面使用当前电脑的本地时间，发布前核对电脑时区。
