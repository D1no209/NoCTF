# 部署交接单：出题人填好，运维按步骤操作

本文件不填写配置代码。**前端每个输入框的最终值都填在 [后台逐项填写表](../platform/CONFIGURATION.md)**；
运维照表录入，不需要猜测或自行换算。

| 交付项 | 出题人填写 |
| --- | --- |
| 题目名称 | 文件访问控制 · AWDP V2 教学示例；正式交付改成自己的题名 |
| 负责人／联系方式 | 待填写 |
| 难度／考察知识点 | 待填写，仅供内部审核，不自动显示给选手 |
| 源码版本 | 待填写审核通过的提交号或交付包版本 |

| 镜像运行架构 | 教学示例按实际 Runner 架构构建，正式交付写清 amd64 或 arm64 |

## 二、构建镜像（有构建环境的人执行）

教学示例在题目目录运行下面两条命令，必须先构建 Target，再构建 Checker。正式镜像由出题人或既有 CI
构建好并推送，平台只拉取和运行，不要求运维现场改代码。

```sh
docker build -t noctf-awdp-v2-target:local private/target
docker build --build-arg TARGET_IMAGE=noctf-awdp-v2-target:local \
  -t noctf-awdp-v2-checker:local private/checker
```

教学标签只在执行这些命令的 Docker 主机存在。若 Runner 在另一台机器，必须交付真实可拉取的镜像，
不能让运维把这两个本地标签直接填到远程生产环境里。

## 三、准备附件

```sh
sh scripts/build-attachments.sh
```

产物在 attachment/dist。运维进入“题库管理 → 该题目 → 附件”，选择“全部附件”，点击“上传普通附件”，
只上传交付信息表中列出的公开文件。private 里的源码、Checker、PoC、Hint 草稿和正确修补不上传。

## 四、前端录入顺序

1. 按 [后台逐项填写表](../platform/CONFIGURATION.md) 创建题库模板，复制 statement.md 到“题面”。
2. 逐项填写“运行环境”“模式定义”，每页点击“保存修改”。
3. 按列表上传公开附件。AWDP 动态 Flag 不需要在 Flags 页新增固定答案。
4. 保存后点击“启动测试容器”，记录页面给出的访问地址，不预先猜测主机端口。
5. 在独立测试比赛验证 Break 和 Fix，再加入正式比赛；正式比赛题目的“发布该题目(对选手可见)”先保持关闭。
6. 按 Hint 填写单创建提示；由赛事负责人确认计分、扣分、发布时间，再发布题目。

## 五、验收时必须看到什么

| 检查 | 出题人提供的预期／运维填写的实际结果 |
| --- | --- |
| 启动容器 | Running，访问入口可用；只有状态正常但无业务响应不算通过 |
| 正常业务 | /health 返回 ok，/file?name=public.txt 返回公开数据 |
| 动态 Flag | 正式题目程序使用平台注入的值；当前教学服务的固定哨兵不能替代正式 Flag |
| 正确修补 | 正常业务保留，Checker 判为防御成功 |
| 未修补或错误修补 | 必须识别漏洞仍可利用，不能误判防御成功 |
| 破坏服务 | 必须识别服务异常 |
| Checker 故障 | 缺依赖、超时、回调失败不能误判为选手修补成功 |
| Fix 文件读取 | 按 [Checker 文件说明](CHECKER-FIX.md) 确认读取的是输入包还是重放产物 |

本地验收工具（仅在可丢弃环境，不用生产 Docker）：

```sh
sh tests/packages.sh
python3 tests/input-contract.py
sh tests/smoke.sh
```

## 六、失败时交回什么信息

请提供：题目名称、发生时间、模板／比赛页面地址、容器状态、镜像完整名、前端填写表和脱敏错误日志。
不要把真实 Flag、登录 Cookie 或 Checker 回调令牌发进文档。

- “配置无效”：先比对前端填值，特别是镜像用户、端口、命令参数。
- 镜像找不到：核对完整名称、下划线、标签和仓库权限。
- nc 无回显：核对实际监听端口、题目进程和输出缓冲。
- Fix 平台错误：核对 Checker 依赖、可写目录和回调，不要直接判选手失败。
- 设置改了没有生效：检查是否保存、是否仍在使用旧实例。
