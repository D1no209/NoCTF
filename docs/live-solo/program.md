# 延迟观赛与节目控制

观众入口：`/competitions/比赛ID/live-solo/program/对局ID`。节目是服务器延迟的媒体和状态，不是裁判原始房间。

## 进入观赛

1. 使用有权读取该比赛的身份打开节目页。
2. 主动进入观赛，服务端分配绑定浏览器的观众租约。
3. 等待已达到延迟边界的片段，开始播放。
4. 离开时释放租约；身份、比赛、Match 改变后重新入场。

达到比赛 maximumViewers 时拒绝新入场，不用多个浏览器重复占名额。租约到期/续约失败时播放器和私有缓存会卸载，再检查资格后重进。

## 视频、状态与结果

计时和比分跟随**实际播放片段**的状态快照；预加载或列表中出现后续片段不让比分提前更新。公开延迟同时约束媒体和业务状态，不允许客户端自行指定未来 asOf。

终场结果有独立延迟发布，原始临时片段清理后仍可按权限读取结果；它不应把正在播放的旧片段比分改成未达到时间边界的新比分。被纠正/取消的结果有相应状态，不冒充原终局继续有效。

StaffOnly 比赛不对外公开节目，资格检查失败可返回不可见/404。裁判的低延迟原始屏幕不得分享给普通观众作为替代。

## 工作人员节目恢复

Match 中的节目控制显示当前导出、导入和停滞状态。管理者在允许状态下可核对 Provider 导出、重试已完成输出的导入，或轮换任务；操作填写原因，检查真实回执。

启动结果未知时先 ReconcileExport，不能自动重复 Start。Completed 且导入未完成时可 RetryImport；需要 Rotate 时核对旧输出和持久导入游标，避免丢弃未导入片段。

## 故障检查

先看观众资格/租约，再看是否真的有片段达到延迟边界、HLS/媒体地址、浏览器解码和 Worker 导入。节目停滞会提醒工作人员，但不自动改变 Match 胜者。

HTTP 并发读取测试不等于同数量浏览器能持续解码。正式容量要求真实播放、状态同步、延迟和撤销测试，见 [验收](./readiness.md)。
