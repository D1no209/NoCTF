# Challenge-bank create JSON discriminator fix

The browser was sending `definition.mode`, but `definitionModelToContract()` inserted it **after** ordinary Definition properties. Nested Container, Compose and Ova Runtime contracts likewise inserted `kind` after ordinary fields. The generated fetch client uses `JSON.stringify` and preserves this insertion order. System.Text.Json treats these polymorphic discriminators as metadata and, by default, requires them before ordinary properties. It therefore rejected a current UI payload as if its discriminator were missing. See the [Microsoft .NET polymorphism documentation](https://learn.microsoft.com/dotnet/standard/serialization/system-text-json/polymorphism).

The current frontend now emits `mode` first in all four Definition branches and `kind` first in all three Runtime branches. Competition mode configuration and challenge rules already emitted `mode` first. The API still returns HTTP 400 for genuinely absent or unknown discriminators; no schema-version inference or legacy contract was added. The global `AllowOutOfOrderMetadataProperties` switch was not enabled because it can buffer large JSON objects during deserialization.

Verification: a new frontend test failed eight cases on the previous ordering, then passed after the change. Tests cover the generated SDK's actual request body, editor re-emission, all game modes and all Runtime variants. The FastEndpoints test host accepted ordered create requests for all four modes. The Release build, 1,205 non-integration .NET tests, 570 Bun tests, typecheck, architecture audit, Docker production build and isolated CTF smoke E2E passed.

Production `noctf-host:0.2.1-alpha.45` was built from the preserved dirty worktree and deployed from the sole `/opt/noctf` Compose root. Before switching, a stopped-Host PostgreSQL dump, upload archive and deployment configuration were saved under root-only `/opt/noctf/data/backups/pre-alpha45-20260925T0449Z`. No EF model or migration changed. The Host is healthy with zero restarts; public readiness is HTTP 200, Prometheus is up, and 70 upload files remain. A production challenge-create write was intentionally not synthesized; a real browser retry is needed to confirm the complete user action.
