# CTF 闯关图与比赛勋章

此功能只作用于 CTF 比赛，默认关闭。旧比赛的已发布题目在没有导入图、或关闭闯关规则时继续按原规则开放。

比赛管理员在“闯关与勋章”中先创建勋章类型，每个类型必须有图片。题目和勋章类型由左侧目录手动导入 Vue Flow 画布；同一题目最多一个节点，同一勋章类型可有多个节点。连接线表达对**来源节点实例**“已完成”或“未完成”的要求；所有入边同时成立才激活目标节点，没有入边的节点无条件激活。不能自连、重复连线、引用不存在的节点或形成环。

点击“保存闯关图”后立即生效。服务端使用预期并发标记校验，冲突返回 409；图、队伍当前节点状态、个人勋章授予与撤销及不可变转移审计在同一数据库事务中提交。正确 CTF FlagAttempt 或 PatchVerification FixAttempt（包括赛后练习）落库时在其事务内重算。题目完成指权威正确事实，即使之后重锁也保留事实和分数。勋章节点激活即完成；同一类型只要任一实例激活，类型就激活。

勋章类型从失活变为激活时，只向**当时**队伍中的有效人类成员颁发；之后加入者不会补发。类型再次失活时撤销该队该类型的所有当前授予，包括已经离队的获奖人。再次激活时按新的成员快照颁发。关闭整个闯关规则会撤销当前勋章并恢复普通题目访问。勋章不加分。

被锁定的已发布题目只在列表展示题名、方向及前驱进度；详情、附件、提示和新提交/新建或续期 Runtime 由服务端拦截。已经得到的直连 Runtime 不被强制终止，但不能因解锁状态变化而续期。管理员可单独开启选手只读闯关图；关闭时选手仍可看题目锁定卡片和本队勋章。公开用户资料仅展示当前有效且所属比赛公开的个人勋章。

迁移由 PostgreSQL provider 中 EF CLI 生成的 `CompetitionProgression` 加法迁移负责；不要手改迁移、旧数据或 PostgreSQL 表。生产发布前先备份数据库、上传目录和配置，发布时保持闯关默认关闭，在隔离测试比赛验证图和勋章流转后再启用真实比赛。生产不可用合成 Flag 改写真实比赛。
