# LiveSolo 启用与验收清单

本页将“有实现”“有局部验证”和“适合正式投产”分开。当前功能可用于管理配置和隔离验收，不能仅凭路由、SDK、迁移或合成视频宣称整套真人比赛已完成验收。

## 本次手册核对范围

2026-10-14 核对了本场题目池、管理/选手双入口、题组风险确认、准备重试、历史回看、权威结果及原有媒体/纠正流程。当前材料归属交付记录已有本地合成账号、无 Runtime 且关闭直播的对局验证；既有记录还包含关系/HTTP/NATS、合成媒体、局部真人选窗和文件预览下载。不同记录证明的范围分别评估。

完整全员真人采集、多节点撤销/恢复、50 个持续解码浏览器、全部赛程纠正重赛和生产媒体部署仍须实测。逐项状态见 [LiveSolo 验收记录](https://github.com/D1no209/NoCTF/blob/HEAD/specs/live-solo-status.md)，以最新版本记录更新结论。

## 功能验收

| 阶段 | 检查 |
| --- | --- |
| 身份与队伍 | Approved/名单/角色/MFA；裁判可允许未上场队友查看已开放题目，提交、重置、就绪仍由上场名单控制 |
| 题目 | 本场新建、投放跟随/脱离、保存到题库、附件/Flag 权限、硬性排除与复用风险审计 |
| 开赛 | 双方锁定/准备、比赛状态和版本；环境异步准备，开始倒计时读取已就绪状态；启用直播再检查 Sharing 与媒体输出 |
| 判胜 | 跨成员/题目共同受理顺序、较早待评记录、时限排空 |
| 时间 | 首题同时开放、后续开题、重叠暂停、重启接管 |
| Runtime | 使用普通 CTF 容器网络与下发流程，连接方式跟随比赛 RuntimeAccessMode；仅 WSRX 按比赛配置启用，不依赖专用执行网络或隔离探针；重置 UUID、历史 Flag 窗口保持有效 |
| 裁判/纠正 | 原因、版本冲突、作废/弃权、下游影响与完整重赛 |
| 节目 | 视频/状态共同延迟、片段比分、终场结果、名额与租约撤销 |
| 录像 | 开关、全员分段、预留、归档、Hold、公开/撤下和失败核对 |
| 历史与结果 | 已开放快照、随机附件既有分配、回看不补证据、实际比分/原因、结果修订与提示去重 |
| 赛后 | Markdown/PDF、版本、审核、免费读取、静态公开曝光 |

## 容量与恢复

先独立验收关闭平台直播的路径：不部署媒体服务，完成名单锁定、双方准备、开题、提交判胜和后续轮次；检查没有媒体房间、节目或录像任务。修改开关不得改变已准备的轮次，从直播轮次切换到关闭的后续轮次时应退役旧房间，历史录像仍遵守原权限。

以下媒体容量和故障验收适用于开启平台直播的比赛，关闭直播的正常对局不依赖这些服务。

录像关闭与开启各测一次：目标可按当前验收计划设 4 并行 Match、每边 2 人共 16 屏和 50 观众。记录实际 CPU、内存、网络、磁盘、样本量和失败，不把输入上限当作测量结果。

当前目标包含裁判视频端到端不超过 2 秒、提交后状态推送 P95 不超过 500 毫秒，公开内容不提前越过配置延迟。这些是验收目标，不能在没有实际测量时写成已达成承诺。

实际测试磁盘满、Provider 不确定启动、停滞导出、消息丢失、Worker 重启、媒体房间撤销和权限变化。恢复点除平台数据库/文件/离线消息/密钥，还需涵盖独立媒体配置与 spool 的持久化恢复策略。

未通过时保留草稿或关闭正式 LiveSolo 功能，修复后针对失败范围复测；前四赛制按自身验收维护，不跟着切换媒体配置。

新增材料与对局流程的证据见 [题目归属与工作区交付记录](https://github.com/D1no209/NoCTF/blob/HEAD/specs/live-solo-material-ownership.md)。无 Runtime、关闭直播的合成验证不证明真实容器隔离、真人媒体、多节点恢复或生产容量。
