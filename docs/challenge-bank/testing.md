# 模板测试运行环境

入口：题库模板详情“测试运行环境”。它创建 TemplateTest purpose 的 Runtime，使用 ChallengeId，不属于正式比赛队伍实例。

## 测试前

先保存基本资料、Runtime 定义和模式技术定义。未保存的技术编辑不会被执行；当前面板发现 dirty 定义时应先保存再测试，避免以错误配置结论影响正式发布。

核对部署 Provider/Runner Pool、题目/Checker 镜像可拉取、命名服务资源和端口完整。静态题没有 Runtime 时无需强行创建测试环境。

## 启动与读取

1. 打开已保存模板的测试区域。
2. 发起创建测试实例，等待 202 后的最终状态。
3. 页面加载当前测试实例、注入状态与访问入口。
4. 从实际网络连接服务，测试题目协议。
5. 有动态 Flag 时检查 Environment/Command 等交付结果，区分 NotRequired/Pending/失败。
6. 独立验证正常逻辑、错误 Flag/Fix 与 Checker。

没有当前测试实例时 404 表示 missing，不一定是模板不存在。API 错误与“实例尚未创建”应分别处理，重试加载后核对 ID。

## 续期与停止

适用实例可输入续期分钟，面板转换成请求预算；过早续期或不支持 purpose 时按校验反馈操作。停止后确认最终回收；UI 超时不证明请求未受理。

重置/重新创建会产生新实例 UUID，重新读取访问地址。测试结束停止实例，不让其与正式环境争夺资源；共有 bridge 和 namespace 不随测试删除。

## 测试不能代替的内容

模板测试可验证技术环境，不替代比赛 Published、Approved、赛道、闯关、正式轮次和排行榜。下一步在隔离比赛执行选手全流程，见 [首次验收](../installation/verify.md)。
