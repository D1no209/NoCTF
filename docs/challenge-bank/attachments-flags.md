# 题库附件与静态 Flag

入口：题库模板详情的附件和 Flag 分区。模板需要已保存、有稳定 ID，才能管理所属对象。

## 上传与检查附件

1. 打开准确模板，确认模式和管理权限。
2. 在附件分区选择文件并提交。
3. 检查文件列表、名称、大小和选择策略。
4. 下载实际内容核对，必要时计算 SHA-256。
5. 在引用比赛的普通队伍权限下再次验证可见和下载。

模板附件选择策略要与题目交互一致，例如所有附件或按规则选择候选。不要用“文件列表存在”代替候选完整性和 Start Gate 验证。

## 替换、删除与恢复

新内容上传新 File，不覆盖旧不可变 metadata 冒充同一文件。删除附件使用授权操作，已删除项按界面能力恢复；恢复后重新检查选择策略和下载。

模板多个引用方都可能读取新附件。正式比赛正在进行时，先评估是否需要独立模板或公告，不无意将赛后答案包替换为公开竞赛附件。

## 维护静态 Flag

新增输入真实受保护值，按大小写、空格和题面约定保存。编辑和删除/恢复针对明确 Flag ID，确认该模板是否被多场比赛使用。

模板作用域只有 ChallengeId，比赛专属只有 CompetitionChallengeId，两者互斥。每队/轮换动态 Flag 来源是模板技术定义和运行生命周期，不在静态列表手工复制所有队伍值。

## 静态与动态的区别

模板静态值可能供所有符合条件的引用实例使用。PerTeam 通过指定服务环境变量注入；AWD 通过轮换命令；KoH 为队伍生成 Control Flag。修改静态列表不会自动重置所有活动容器或重判历史记录。

## 常见失败

- 上传限额：同时检查 HTTP 文件上限、格式及代理，不仅看扩展名。
- 引用模板无 Flag：核对作用域和题目所选策略，静态候选必须真实存在。
- 附件恢复后仍无法开赛：再读 Start Gate 的选择/引用错误，可能还有其他候选缺项。
- 管理权限不足：共享题面可见不授权读原始 Flag；联系模板 Owner/Manager。

## 浏览器下载

选手点击附件后，浏览器直接从平台接收文件流，按浏览器的下载设置保存。平台页面不调用系统文件保存选择器，也不将整份附件读入页面内存；下载进行中可以继续浏览题目。

普通附件及随机附件均先取得仅适用于该附件的短时授权。实际获取文件时仍检查当前账号、令牌版本和 MFA，并按现有规则记录下载证据。只申请授权不会记为已下载；随机附件也在真正获取文件时才完成队伍分配。
