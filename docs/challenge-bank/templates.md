# 题库与比赛题目

## 创建可复用模板

列表入口 `/admin/challenges`，可按模式、可见性、名称和包含已删除等当前过滤项查找。切换筛选回第一页，重新进入列表会先显示最近成功快照并后台刷新；刷新失败时旧行仍可显示，先读错误提示，不把旧快照当作最新服务器状态。

进入题库管理，选择新增模板，并先确定 CTF/AWD/AWDP/KoH 模式。填写题名、方向、说明、附件和可见性，再配置 Flag、Runtime、Checker 或注入定义。

Shared 模板允许其他组织者查看题面并引用，Private 限定可见范围。共享不等于公开原始 Flag、对象键或敏感运行定义。模板编辑由模板 Owner/Manager 控制，比赛 Manager 不自动成为模板 Manager。

建议题面包含：目标、访问方式、附件使用、允许/禁止行为、答案或修复包格式、资源限制和故障反馈方法。用实际选手权限预览，避免在题面写入 Checker secret 或内部地址。

当前基本表单标题最长 160、方向最长 96 字符。默认新模板为 Private，模式选择会切换对应结构化定义分支；不要粘贴旧 schemaVersion JSON 或 Compose YAML 作为新定义。

## 分区保存与模式变化

基本资料、Runtime 技术定义和模式专属技术定义有独立保存操作。修改 Runtime 后只保存基本资料，不会执行未保存的容器配置。先看分区 dirty/错误列表，保存后重载核对，再测试。

模式定义保存会按有效分支校验；有活动引用或 Runtime 时改变模式/技术定义可能被拒绝。先检查 [引用位置](./permissions-placement.md)与当前测试实例，必要时准备独立模板，不靠改模式绕过引用限制。

## 配置 Flag

| 场景 | 配置位置与要求 |
| --- | --- |
| 模板通用静态 Flag | 题库模板，供引用方使用 |
| 比赛专属静态 Flag | 当前比赛题目作用域，与模板作用域互斥 |
| 每队动态 Flag | Runtime 对应的生成/环境变量注入定义 |
| AWD 轮换 Flag | 指定服务和注入命令，随有效轮次更新 |
| KoH Control Flag | 平台为队伍生成，由队伍按题面写入共享目标 |

管理敏感 Flag 前检查访问授权。比赛 Owner/Manager/Judge 成功读取受保护 Flag 会留下访问事件；不要把 Flag 复制到公告、日志或普通 API 集成内容。

## 引用模板到比赛

1. 在赛事管理“题目”选择添加/引用模板。
2. 选择与比赛模式一致的模板。
3. 设置比赛内展示名称、排序和标签。
4. 配置本比赛计分规则覆盖与提示。
5. 保存并检查当前实例 ID。
6. 完成测试后发布题目。

比赛题目 ID 与模板 ID 不同。玩家行为使用 CompetitionChallengeId；自动化系统更新时应保存并使用正确资源 ID。

## 提示与附件

模板拥有附件和技术定义，比赛题目拥有提示与发布策略。提示应写清解锁代价，公开题面更改和提示发布可能产生赛事播报。

替换附件上传新 File，不覆盖旧对象冒充同一文件。验证下载权限与内容；相同文件名不代表内容相同，必要时保留 SHA-256。

## 测试题目

有 Runtime 的模板先用模板测试能力验证镜像、端口、注入和 Checker；模板测试实例属于模板作用域，不与正式比赛队伍实例混用。

然后在隔离比赛使用 Approved 测试队验证实际题面、访问、提交和计分。只用管理员启动环境无法证明选手权限、闯关、TTL 和配额正确。

## 修改已经被引用的模板

模板题面与元数据按当前定义读取。Runtime 技术定义修改用于后续启动/重置，不自动替换现有实例，重置会生成新 UUID。活动 Runtime 对技术定义修改可能有额外限制，按页面的校验结果先停止相关测试/实例。

进行中比赛修改前确认引用范围，必要时克隆独立模板而不是影响多场赛事。模式不匹配或活动引用受限时不能强行绕过校验。

## 下架与删除

下架题目不等于删除模板或历史成绩。模板仍被未删除比赛题目引用时不能直接删除。Running/Paused 比赛先完成合法生命周期，再按拥有的权限清理。删除前核对其他引用、附件和 Runtime，普通排障不使用强制删除。
