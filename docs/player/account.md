# 注册、登录与账号

## 创建账号

1. 打开平台首页，选择“注册”。
2. 填写用户名、真实邮箱和密码，完成页面要求的人机验证。
3. 提交后按提示处理邮箱验证。若平台要求验证，未验证之前不能正常密码登录。
4. 返回登录页，用创建的账号登录。

用户名为 3–64 字符，邮箱最长 320 字符，用户名与邮箱按大小写不敏感规则判唯一。密码支持 8–1024 字符，不会自动去除首尾空格；如果复制密码时多了空格，它可能成为密码的一部分。

公开注册得到普通参赛账号，不自动获得出题或管理权限。需要举办比赛时联系平台管理员授予 Organizer。

## 邮件未收到

先查垃圾邮件、填写地址和冷却提示，再使用验证邮件重发入口。为保护账号隐私，重发受理不代表该地址一定存在。一直收不到时向管理员提供提交时间和邮箱域名，管理员检查 SMTP 与发信策略；不要向别人发送密码或验证链接。

## 登录与 SSO

平台可能同时提供密码登录和 SSO 登录。在登录页选择管理员已启用的身份提供方，完成外部身份认证后回到平台。赛事赛道要求某个 SSO 身份时，只有完成对应绑定才满足条件。

SSO 不自动注册或按邮箱合并账号。首次使用需要先注册/本地登录，在“账户安全”发起绑定；未绑定身份的登录流程被消费后不能靠重放接着绑定，应重新发起一条流程。每个账号最多绑定一个外部身份。

如果登录需要人机验证，等待验证成功再提交。验证码 token 每次请求使用，不反复复用已失效的 token。Cap 故障或 Turnstile 域名错误应由管理员修复，不能通过连续重试绕开。

## 会话恢复与退出

支持配置就绪时的 [通行密钥登录](../platform/security/passkeys.md)。通行密钥属于主认证，需要 MFA 的账号仍进行第二步；密码找回不移除已绑定验证器。验证器、恢复码、强制策略与邮箱恢复见 [双重验证](../platform/security/mfa.md)。

普通 Human 登录的 Access Token 生命周期为 15 分钟，Refresh Cookie 固定 30 天。网页在适当时机刷新会话；Cookie 是 HttpOnly、Secure，生产必须通过 HTTPS。

“退出”清除当前浏览器的刷新 Cookie。平台没有设备会话列表或逐设备撤销模型；改密码或管理员全量撤销通过 TokenVersion 使旧访问和刷新令牌失效。

刚改角色、密码或管理员撤销令牌后，出现重新登录提示是正常现象。不要将浏览器中的 Access Token 复制给其他人。

## 修改密码与找回

已登录时使用账号设置的密码修改流程。忘记密码时在登录页进入找回入口，填写已验证邮箱，再按邮件的限时链接设置新密码。只有可用且已验证邮箱的 Human 账号适用；请求统一受理不会确认账号是否存在。

重置完成后重新登录，旧令牌失效；新申请的重置链接可能使此前链接作废。链接过期或已使用时重新申请，不将链接贴到公共讨论区。

## 用户资料

维护头像和公开资料时注意实际可见范围。CTF 勋章展示当前有效且所属比赛公开的个人授予；队伍赛后变化不会自动为新成员补发之前授予的勋章。
