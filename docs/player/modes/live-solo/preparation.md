# 名单、双方准备与开赛

从 LiveSolo 大厅选中 Match 进入 `/competitions/比赛ID/live-solo/matches/对局ID`。准备前检查本队 Approved、未封禁和当前账号的适用 MFA。

## 锁定上场名单

队长在 Preparing 状态从本队有效成员中选择本场人员，数量不超过比赛上限，提交当前 Match 的名单。锁定后以本场快照为准，不将比赛队伍的后来成员变化当作自动替换上场人。

队长在本队名单已锁定后确认准备。左右两队分别操作，另一队成功不代表本队已经 Ready。未上场成员不能通过复制队员 URL 获得题目/提交资格。

## 建立媒体并主动共享

双方名单锁定后，允许的裁判或名单成员准备媒体。连接房间不会自动申请屏幕；每位上场者主动点击共享，并在浏览器原生选择器确认要分享的窗口。

默认仅屏幕轨道，不开启麦克风或系统声音。确认共享范围没有密码、私人聊天或无关窗口；该媒体可能用于裁判原始查看、延迟节目及启用时的录像。

所有锁定成员必须达到服务器确认的 Sharing 状态，不能只依赖本地预览。浏览器约束失败、权限拒绝、断连或来源停止时按提示重新共享，查看实际发送统计和 [视频策略](../../../platform/video-policy.md)。

## 准备 Round 和开始倒计时

裁判准备 Round，服务器选择合法题组并检查历史曝光、隔离能力与资源。确认双方准备、全员屏幕和媒体输出就绪后开始倒计时。

真实媒体未就绪、录制启用但输出未确认、隔离回执不合格或资源不足时应拒绝正式倒计时。不要把 mock 或合成轨道就绪替换为真实现场条件。

倒计时完成后依据服务器实际开放时间同时开题。暂停/纠正期间就绪可能被重新检查，不能沿用旧页面 Ready 就无条件恢复。

## 离场与故障

有共享或未完成操作时离开页面需阅读确认。断流通知工作人员，但不会自动判负、作废或暂停；裁判按 [裁判操作](../../../competition/modes/live-solo/judging.md)决定。

保存 Match/Round ID、成员、发生时间和安全错误摘要，避免向公开讨论区发媒体凭据、Flag 或浏览器授权 token。
