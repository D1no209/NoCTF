# 题目、附件与运行环境

## 打开题目

进入比赛“题目”，选择对应方向或题目卡片。只有已发布且满足当前访问条件的题目可以打开。查看失败时先检查队伍是否 Approved、是否被封禁、比赛状态和 CTF 前驱条件。

闯关锁定的题目可能只显示题名、方向和前驱进度，不返回完整题面、附件或提示。不要根据其他队伍的截图推断本队有同样的访问权限。

## 附件与提示

附件从题目页的授权入口下载，按题面说明运行或分析。文件替换后重新下载最新版本，不自行修改 FileId 或猜对象存储地址。

提示可以需要解锁并扣分。操作前阅读扣分说明，确认是本队需要的提示；解锁会形成比赛行为事实并影响得分。截图或共享提示前遵守赛事规则。

## 提交 Flag

1. 检查当前题目和模式的输入类型。
2. 完整复制 Flag，包括大小写、花括号、空格等题目实际要求的内容。
3. 提交一次，等待受理和最终结果。
4. 查看本队尝试结果；正确后再等待排行榜刷新。

平台可能设置错误扣分、尝试次数或速率限制。平台/存储故障与答案错误属于不同结果，不能把所有失败都当作“Flag 错误”。重复正确提交不会重复获得解题奖励。

## 启动 Runtime

适用的 CTF 题目在运行环境区域提供启动、停止、重置、续期等动作。AWD/KoH 的环境主要由平台管理，具体依题目和模式显示。

1. 确认题目描述中的环境需求和 TTL。
2. 完成人机验证（平台要求时），点击启动。
3. 等待异步状态变为就绪。
4. 使用平台返回的访问入口，例如 HTTP 地址或 TCP 主机/端口。
5. 在到期前按赛事规则续期，完成后停止环境释放资源。

启动受队伍实例额度、平台资源、镜像拉取、题目访问条件影响。容量不足时等待或联系组织者，不连续创建请求占用队列。

## 重置和到期

重置回收旧 Runtime 并创建新 UUID，访问端口与环境内容可能变化。重新读取地址和凭据，旧连接不要继续复用。题目定义更新一般在下一次启动/重置生效，已有环境不会自动更新。

CTF Runtime TTL 按真实时间计算，比赛暂停不冻结 TTL。服务器已到期或回收时，本地还保留旧连接并不代表能继续正式提交。

## 常见现象

| 现象 | 处理方法 |
| --- | --- |
| 没有启动按钮 | 题目无 Runtime、未开放、被锁、资格不足或模式由平台管理 |
| 一直处理中 | 保存尝试/实例 ID，联系管理者检查 Worker/Runner |
| 环境就绪但连接失败 | 检查最新地址、实际公网端口和本地网络，提供时间与实例 ID |
| 重置后 Flag 不匹配 | 使用新环境中得到的 Flag，避免旧实例内容 |
| 续期被拒绝 | 检查 TTL/额度、比赛状态、封禁和闯关锁定 |
| 返回 429 | 遵循等待时间，不重复并发操作 |

提交报障时给出比赛/题目/Runtime ID、发生时间和非敏感错误摘要，避免公开 Flag、邀请码、访问令牌或内部凭据。
