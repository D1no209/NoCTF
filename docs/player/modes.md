# 五种模式的参赛流程

比赛选择 CTF、AWD、AWDP、KoH 或 LiveSolo。同样的页面动作在不同模式中的目标和计分方式不同，先阅读赛事规则。

| 赛制 | 参赛指南 |
| --- | --- |
| CTF | [解题与提交](./modes/ctf.md) |
| AWD | [攻击与防守](./modes/awd.md) |
| AWDP | [Break 与 Fix](./modes/awdp.md) |
| KoH | [共享目标控制](./modes/koh.md) |
| LiveSolo | [名单、场内解题与观赛](./modes/live-solo/index.md) |

## CTF：解题与提交

1. 报名获批，等待比赛和题目开放。
2. 阅读题面、下载附件，按需启动本队 Runtime。
3. 得到答案后提交 Flag；补丁验证交互题按题面提交修复包。
4. 查看正确结果、解题奖励、血奖、提示扣分和错误扣分。
5. 开启闯关时先完成前驱题或勋章条件，再进入后续题。

CTF 分值可能固定或动态衰减。`DynamicRecalculation` 会随后续解题重算既有基础分，`AtSolve` 按解题位置结算；配置、资格或重判变化仍可能重新计算历史成绩。以当前权威榜单为准。

## AWD：攻击与防守

AWD 每队拥有自己的目标，平台按轮次换 Flag 并持续检查服务健康。加固期先修复本队服务，比赛攻击阶段获取其他队有效 Flag 后提交；自己的 Flag 不当作攻击结果。

重点核对当前轮次、目标信息和服务状态。Flag 只在对应有效窗口计分，过期内容不能跨轮复用。服务可访问不等于 Checker 健康，修复时同时保留题目规定的正常功能。

暂停会停止相应竞技调度，轮次按有效运行时间延后；恢复后跟随平台展示的当前轮次，不按自己计算的墙钟持续攻击。

## AWDP：Break 与 Fix

| 动作 | 提交内容 | 完成标准 |
| --- | --- | --- |
| Break | 目标中正确 Flag | Flag 最终正确 |
| Fix | 按题目要求制作的 archive | 正常功能与漏洞修复检查通过 |

Break 不是上传 exploit 文件，Fix 不是另一种 Flag。赛事可要求先 Break 才 Fix，并分别限制次数、设置分值和失败扣分。

制作修复包时保持指定目录结构、入口文件和依赖约定。平台会检查格式、哈希和解包限制；符号链接、绝对路径、路径穿越或过度展开的包会被拒绝。

提交后若赛事采用手动评测调度，需要等待裁判派发。保存已受理的记录，不因为仍在 Pending 就反复上传相同文件。查看具体结果区分 exploit 仍成功、正常服务异常和平台故障。

## KoH：夺取共享控制权

所有队伍攻击同一共享 Hill。每队读取自己的 Control Flag，并通过题目规定的方法让控制检查端点返回本队 Flag。平台定期轮询，匹配到唯一有效队伍后按间隔给分。

KoH 不通过普通 Flag 提交按钮申报控制权，也不为每队创建一个 Hill。仅本队 Flag 可被读取，不能查询别人 Flag。检查端点的正文应为精确 UTF-8 Flag，不附加 JSON、换行或说明文本。

控制是每次轮询独立判断。超时、错误内容或服务不可用不会延续上一次成功控制计分；暂停停止轮询，不补跑缺失观察。

## LiveSolo：按 Match 胜局竞技

队长锁定本场名单并确认准备，每位上场成员主动共享屏幕。裁判在合法题组、真实媒体和隔离资源就绪后开始倒计时。双方按服务器实际时间同时开题，后续新题不强制切换个人选题或清除未提交输入。

当前 Round 所有题目、双方和成员共用受理顺序，第一条有效正确 Flag 赢局，不按评测返回速度判胜。时限先处理截止前已受理记录，再得出结果。没有普通积分、血奖、付费提示或题解折扣。

详细 [准备](./modes/live-solo/preparation.md)、[场内操作](./modes/live-solo/playing.md)、[观赛](./modes/live-solo/program.md)与 [赛后题解](./modes/live-solo/postgame.md)独立阅读。真实媒体和完整生产验收边界见 [就绪清单](../operations/live-solo-readiness.md)。

## 各模式共同规则

本队必须获批、未封禁且比赛允许动作。页面受理是异步流程起点，最终结果才参与投影。封禁、恢复资格、赛道变化和人工裁决可能改变分数；发现差异先核对事实和规则，再向组织者咨询。
