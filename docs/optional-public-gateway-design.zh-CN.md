## 1. 目标、授权与结论

### 1.1 产品目标

平台部署在内网时，允许管理员选择性启用公网跳板：

1. 公网用户可通过 HTTPS 访问 NoCTF 平台。
2. 公网用户可用普通浏览器、`nc` 等工具连接允许公开的题目服务，不要求安装客户端。
3. 内网直连与公网入口显示各自适用的题目连接地址。
4. 出题人继续使用现有 `{HOST}`、`{PORT}` 和容器端口配置，不填写跳板参数。
5. 功能默认关闭，部署不包含跳板时保持现有行为。
6. 跳板故障不改变 Runtime 判定、Flag 注入、Checker、计分与内网访问路径。
7. 管理员能看见明确的配置错误、发布状态和失败原因，不能出现按钮无反应或显示未就绪地址。

### 1.2 已确认环境与操作边界

| 对象 | 已知信息 | 实施边界 |
| --- | --- | --- |
| 测试平台服务器 | `101.43.46.244`，用户说明已配置 SSH 免密 | 后续验证使用；不能无审查地停止其现有服务 |
| 公网跳板服务器 | `8.156.82.215`，用户说明已配置 SSH 免密、由 1Panel 管理 | 不得破坏或接管任何现有功能 |
| 公网平台域名 | `challenge.fa1lsnow.com` | 用户已建站点、反代和证书；当前上游端口为临时填写 |
| 既有反代 | 由 1Panel 管理 | 当前允许的站点修改仅为纠正上游地址；不更换证书、不重建站点 |
| 生产服务器 | `172.26.106.246` | 不在本次测试、部署、网络调整范围 |
| `1panel-network` | 既有基础设施 | 不删除、不重建、不改网段、驱动、既有 aliases 或成员连接 |

这些信息来自用户说明，不是本轮对服务器的实测结果。SSH 免密不等于允许任意配置变更。

新增 FRP 服务、绑定新端口、增加网络成员、调整安全组或反代请求头，均应在主 agent 的实施清单中单独列明；不能把这些操作包装成“只修改反代地址”。现有配置若不满足安全前提，应停在该前提处说明问题。

### 1.3 推荐方案

采用“平台管理策略 + 独立 FRP 转发组件 + 按访问入口投影地址”的可选适配层：

- 固定的网站隧道与动态的题目隧道分别管理。
- 不替换全局 `Runtime:Docker:PublicHost`，不覆盖现有 Runtime 的直连地址。
- 不改变 Docker 以 host port `0` 分配端口的机制。
- 不让 API、Worker、Runner 承载选手 TCP 数据转发。
- 不引入通用内网代理、任意目标转发、全端口映射或新的平台生产角色。
- 动态端口上线前，必须证明停止、故障和端口复用不会把旧题目的入口转给其他服务。

必须区分两类承诺：可以设计“核心业务不依赖跳板”，但无法凭设计承诺共享 CPU、网卡与带宽绝对零影响。性能要求应通过第 13 节的测试门槛兑现。

## 2. 当前代码事实与设计依据

以下文件均已在本轮只读检查。路径相对于仓库根目录；方法名比可能移动的行号更适合作为实施定位依据。

| 已核实事实 | 代码位置 | 对设计的影响 |

| 平台设置是固定字段实体，不是任意 KV 存储 | `backend/src/NoCTF.Domain/Platform/PlatformSettings.cs` | 管理员持久配置需要正规 EF migration |
| 平台读取已有 FusionCache 接入 | `backend/src/NoCTF.Infrastructure/Administration/PlatformConfigurationStore.cs` | 复用缓存模式，但不能把敏感设置混入匿名品牌配置 |

## 3. 首期范围与明确不做的内容

### 3.1 首期必须支持

- 一个公网跳板绑定一个已配对的 Docker Runner。
- 平台 HTTPS、登录、API、附件、Patch 上传、SignalR。
- CTF 选手动态容器、AWDP 攻击容器的 TCP 入口。
- 已有练习实例在授权允许时使用同样的连接投影。
- 内外网入口分别显示对应连接文案。
- 管理员配置、连接状态、诊断结果和关闭操作。
- 启用、关闭、停止、重置、到期、组件重启的幂等处理。

### 3.2 不能顺带宣称支持

- 多 Runner 共用同一公网 IP 的同端口冲突分配。
- UDP、Kubernetes、OVA/Libvirt 的公网转发。
- 任意内网服务代理、SOCKS、HTTP CONNECT 或远程命令执行。
- 自动登录不同站点、绕过平台登录访问其他队伍地址。
- 为每个题目配置 HTTPS 证书或共享 443 的题目域名路由。
- 公网 DDoS 防护能力；此能力取决于云网络与独立运维方案。

Compose 多服务、AWD 参与者目标列表、KoH 共享入口必须分别补全权限与端口测试后开放。未完成的模式保持原有内网功能；公网入口显示“不支持当前运行类型”，不返回不可达内网 IP 冒充可用公网连接。

题库测试容器默认不公开。若后续需要公网题目测试，应单独增加管理员/题目权限下的显式授权，不能因为页面位于管理后台就自动发布。

## 4. 访问架构与信任边界

### 4.1 网站访问：固定链路

```text
公网浏览器
  -> challenge.fa1lsnow.com:443
  -> 跳板上既有 1Panel/OpenResty（现有证书）
  -> 仅供该反代访问的网站隧道落点
  -> FRP 加密隧道
  -> 测试服务器上的固定 NoCTF HTTP 上游
  -> 同一 NoCTF API / SPA
```

网站隧道只允许一个部署时确认的 NoCTF 上游。管理界面不能把它改成数据库、Docker API、1Panel 或任意内网地址。

平台网关配置开关主要管理动态题目发布与地址展示；网站固定隧道作为独立部署配置保留。关闭题目公网发布不应把管理员当前的网站会话一起切断。

### 4.2 题目连接：动态链路

```text
公网 nc / 题目浏览器
  -> 公网跳板的获准 TCP 端口
  -> 独立 FRP 题目隧道
  -> 本地实例身份约束与撤销边界
  -> Runner 宿主上该题目实际发布的 Docker 端口
  -> 题目服务

内网选手
  -> Runner 的直连地址 + 同一 Docker 发布端口
  -> 题目服务（不经过公网跳板）

Checker / 一次性验证 Target
  -> 原有隔离网络与内部地址（不经过上述公网链路）
```

“实例身份约束与撤销边界”是需要先验证的安全机制，不是声称 FRP 原生已能识别 NoCTF Runtime。详见第 10 节。

### 4.3 控制面与数据面职责

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| NoCTF API | 管理员设置、授权后的地址投影、返回连接状态 | 代理选手 TCP 流量、执行 SSH、修改 1Panel |
| Worker | 按现有事实触发可合并的公网同步通知 | 等待公网连接成功后才继续计分/评测 |
| Runner | 核对本机真实 Runtime/端口、参与资源销毁前的本地撤销 | 在消息 Handler 中转发连接字节 |
| 本地 Connector | 维护允许发布的实例映射、调用专属 frpc、回报状态 | 自行扫描并公开所有容器、持有数据库管理员权限 |
| frpc/frps | 独立承载隧道流量 | 判断比赛资格、取得 Flag/Checker 配置 |
| 1Panel/OpenResty | 保留既有 HTTPS 入口 | 跟随每次题目启动新增或重载站点配置 |

Connector 是可选部署组件，不增加 `NoCTF.Host` 的第四个业务角色。实现可用现有进程管理机制承载专属组件；不要为本功能建设通用代理平台。

## 5. 管理员配置设计

### 5.1 管理入口

在 `/admin/platform` 增加“公网访问”配置入口，使用现有管理页的表单与提示样式，不改版整个后台。

分成三个区块：

1. 发布设置：开关、入口、题目主机、绑定节点。
2. 当前状态：连接情况、已发布/待发布/失败数量、最后一次成功对账时间。
3. 诊断与风险：端口冲突、证书/配对失败、安全前提未通过、受影响实例清单。

### 5.2 表单字段

| 中文字段 | 建议契约字段 | 默认值/规则 | 权限边界 |
| --- | --- | --- | --- |
| 启用题目公网访问 | `Enabled` | `false` | 仅平台管理员 |
| 已配对连接器 | `ConnectorId` | 必须从部署批准的节点中选择 | 不接受任意控制 API URL |
| 对应 Runner | `RunnerId` | 来自配对关系，单 Runner | 不在题目数据中选择 Runner |
| 公网平台入口 | `PublicOrigin` | HTTPS origin；本次拟为 `https://challenge.fa1lsnow.com` | 需属于部署许可的入口集合 |
| 内网平台入口 | `DirectOrigins` | 精确 origin 列表，不使用 `*` | 不能扩大代理网络信任范围 |
| 题目公网主机 | `PublicRuntimeHost` | 本次可选择 `8.156.82.215`，或经确认解析到它的域名 | 仅主机，不带路径或端口 |
| 内网显示主机覆盖 | `DirectRuntimeHostOverride` | 空：继续使用原配置 | 只影响显示，不改变 Docker 绑定 |
| 最大公开端口数 | `MaxPublishedPorts` | 不高于运维给配对节点设置的上限 | 按端口计数，不按题目数计数 |
| 公网端口范围 | 只读部署能力 | 展示允许区间及被保留端口 | 平台不得自行改防火墙或申请占用端口 |
| 公网端口策略 | 只读部署能力 | 首期同端口映射 | 不提供尚未实现的自动分配选项 |
| 配置生效状态 | 只读 | 已保存、应用中、已应用、失败 | 不将“保存成功”写成“公网已可用” |

Web HTTPS 入口和题目连接主机是不同概念。使用 `challenge.fa1lsnow.com` 作为题目主机前，应验证其 DNS 直指跳板，未被只能代理标准 HTTP 端口的服务接管。现有网站证书不会自动让任意题目端口支持 TLS。

### 5.3 配置校验与反馈

- 启用时要求 Connector 配对有效、安全预检通过、支持当前 Provider。
- 不允许以 URL 文本调用任意地址做“连通性测试”；诊断只能针对已配对节点和受控固定探针。
- `PublicOrigin` 不允许用户名、密码、路径、查询、片段，端口如有则明确保存。
- `PublicRuntimeHost` 不接受 shell 字符串、HTML、带认证 URL；IPv6 若首期未完整测试则明确拒绝，不假装支持。
- `DirectOrigins` 与 `PublicOrigin` 不允许重复归类。
- 表单字段错误就地显示；保存错误附可追踪编号，不能只显示“请求与当前状态冲突”。
- 启用/修改可能中断现有公网连接时，先展示受影响数量和操作语义；不自动重启题目。
- 修改公网域名只重新投影显示；修改跳板配对/Runner/端口能力需要先撤销旧发布再应用新发布，不原地挪动旧代理目标。
- 关闭：停止接受新发布并撤销已发布题目入口；内网 Runtime 保持运行，固定平台网站隧道保留。

### 5.4 平台配置与运维配置分开

日常开关、显示主机、入口选择可在 UI 管理，不要求管理员进入 Runner 容器修改环境变量。

节点配对根信任、FRP 控制目标、TLS CA/密钥、固定 Web 上游、监听地址和允许端口集合属于运维启动配置。平台 UI 只能选择已批准能力，不能通过编辑字段突破其范围。首次部署配置由主 agent 在独立部署清单中交付，不写入题目模板。

## 6. 数据、缓存与契约

### 6.1 持久化

推荐只在 `platform_settings` 扩展本功能所需的强类型配置字段/集合，不新增业务表。

- 简单标量优先普通列；集合或结构确需 JSONB 时说明映射理由。
- `Enabled` 默认 `false`，旧部署升级后不自动发布。
- 实际迁移通过 `dotnet ef migrations ...` 生成，不手写 migration 或 snapshot。
- 不批量重写 `runtime_instances.urls`、不新增 Runtime 定义快照、端口表、operation 表、generation 或持久化 Revision。
- 连接器配对密钥不进入匿名平台配置响应；首期优先由部署凭据存储持有，数据库仅保存已配对 Connector 标识。
- FRP 动态映射是可重建的外部运行状态，不作为第二份权威业务数据库。

因此本方案不承诺“完全不需要 Migration”：平台管理员设置需要迁移；Runtime 地址生成优先不改变数据库结构。

### 6.2 管理契约

建议以现有平台配置能力为归属，提供最小的管理契约：

| 操作 | 内容 | 行为 |
| --- | --- | --- |
| 获取公网设置 | 当前设置 + 已配对节点能力 | 管理员只读，不返回密钥 |
| 保存公网设置 | 上述表单字段 | 持久化并触发异步应用，返回明确应用状态 |
| 获取公网状态 | 聚合状态 + 分页失败项 | 读取缓存快照，不同步访问所有容器 |
| 执行受限诊断 | 已配对 Connector 标识 | 限流、短时预算，只检查固定能力，不扫描任意端口 |

这四项是用例，不要求机械新增四个路由。主 agent 应先检查最新接口再决定复用/扩展方式；不得把 frpc 管理 API 原样反向代理给浏览器。

新增或修改的 HTTP endpoint 必须遵守仓库和 `fastendpoints-stronglytyped` 规范：强类型 DTO、`ExecuteAsync`、`Results<...>`、`TypedResults`，传输层薄、业务规则位于 Application。请求、响应与 Validator 放在所属 endpoint 文件中，不增加通用 Models 文件夹。

### 6.3 玩家响应

保持原有 Runtime 状态与 `Urls` 读取方式；新增独立的可选连接信息，命名建议如下：

- `AccessRoute`：`Direct` / `Gateway`。
- `PublicAccessState`：`Disabled` / `Pending` / `Ready` / `Unavailable` / `Revoking` / `Unsupported`。
- `PublicAccessFailure`：明确失败枚举，可空。

只把当前入口下、已授权且可用的连接文案放入 `Urls`。多端口实例可以部分就绪，状态应按逻辑端点表达，不因一个端口失败就谎称全部可用。公网状态不写入 `RuntimeFailureCode`。

### 6.4 缓存原则

- 设置读取复用 FusionCache 模式，但使用独立且不泄密的读模型。
- 状态缓存可丢失，丢失后由权威 Runtime 与 Connector 状态重建；未知公网状态按不可用处理。
- 授权前不能从共享缓存直接返回队伍地址。
- 缓存复用必须区分 Runtime、逻辑端点、访问路线和授权范围；不能把公网渲染结果覆盖直连结果。
- 设置变化主动失效相关显示缓存，不依靠长期 TTL 等待“最终看起来正确”。
- 缓存/心跳过期只能让 UI 隐藏地址，不能充当真正的数据面撤销机制。
- 新增缓存必须有容量上限与停止实例淘汰逻辑，不按任意请求 Host 无限扩张。

## 7. 内外网入口识别与认证

### 7.1 首期选择：不同入口域名，精确匹配

处理顺序：

1. 按已验证的代理链处理 Forwarded Headers。
2. 校验请求有效 Host/Scheme 是否为部署认可入口。
3. 完成原有登录、队伍、比赛、题目和目标可见性授权。
4. 按有效 origin 选择 `Direct` 或 `Gateway`。
5. 生成当前路线的连接文案。

通过 `challenge.fa1lsnow.com` 的入口默认选择 Gateway；配置中的内网入口选择 Direct。未知入口按现有 Host 策略拒绝，不能因为源 IP 是私网就自动授予“内网”身份。

若已保存公网入口但管理员关闭了公网发布，该入口的题目连接应显示“公网访问已关闭”，不悄悄返回内网地址。没有安装/配置本功能的原部署仍执行原来的直连行为。

### 7.2 安全含义

入口识别是连接地址的选择，不是新的用户身份、权限或网络认证。Host 可以被客户端提交；必须结合受信代理、部署允许的入口和已有授权使用，不能据此给予管理员/其他队伍权限。

若未来要求相同域名下自动区分直连与跳板，需可靠的入口绑定或受信代理标记。自定义请求头只有在入口清除客户端值并重新设置、后端验证来源时才可信；该模式不作为首期默认方案。

### 7.3 当前反代的特殊约束

现有代码 `ForwardLimit = 1`、`RequireHeaderSymmetry = true`。FRP TCP 隧道本身不等于一层写入 HTTP forwarded headers 的代理；必须按实际 HTTP 代理数核对链路。

主 agent 要验证：Host、Scheme、X-Forwarded-*、重定向、HTTPS Cookie、刷新请求 Origin、WebSocket 升级是否保持正确。不能设置“信任全部私网/全部代理”来消除错误。ASP.NET Core 官方说明了受信代理与 forwarded headers 的边界：[代理部署文档](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer?view=aspnetcore-10.0)。

如果仅修改当前站点上游不足以通过上述检查，应报告所需的站点级附加改动，不能越过用户“只改正反代地址”的边界。

### 7.4 登录与实时通信验收

- 两个域名默认各自拥有 Cookie；不扩大 Cookie Domain、不降低 SameSite/Secure 以实现所谓无感共享。
- 在每个入口分别验证登录、浏览器刷新、令牌刷新、登出和禁用用户。
- 同源 API 路径优先，不新增宽泛 CORS 许可。
- 邮箱验证/密码重置链接仍使用明确配置的公开地址，不从任意 Host 生成邮件链接。
- SignalR 通知尽量发送状态失效信号，由客户端通过当前 origin 重读；不要把某一路线地址广播给另一条路线。
- 上传和下载流式传输，检查超时、最大体积与断连处理，不为跳板把整个 Patch 包额外缓冲进 API 内存。
- WebSocket 所需请求头要实测；一般反代不会自动传递全部升级头：[Nginx WebSocket 代理说明](https://nginx.org/en/docs/http/websocket.html)。

## 8. 地址生成与题目兼容

### 8.1 不改题目模板的产品约定

现有题目继续填写：

- `nc {HOST} {PORT}`。
- `http://{HOST}:{PORT}`。
- 包含这两个占位符的自定义显示文案。

内网示例为 `nc <Runner直连主机> 32777`，公网示例为 `nc 8.156.82.215 32777`。`32777` 只是说明相同端口的例子，不是实际预留或部署端口。

不重新加入“模板必须是合法 URL”的限制；非 URL 文案按文本显示，链接化仍按安全协议白名单处理。

### 8.2 从权威绑定生成，禁止文本替换

推荐新增一个窄职责的 Application 地址投影能力：

1. 获取已授权的 Runtime 与当前有效的技术定义。
2. 获取其真实 `PublishedPorts` 与 Runner 归属。
3. 用 `(ServiceName, ContainerPort)` 等稳定逻辑键关联绑定；Container 单服务按其容器端口关联。
4. 对需要显示的每个端点，用选择后的 Host 和确认成功的公开端口展开模板。
5. 再按当前授权范围输出。

禁止：

- 正则替换已经展开文案中的内网 IP。
- 用全局 `PublicHost` 覆盖 Docker receipt。
- 用显示文案的列表下标作为 FRP 目标身份。
- 仅从模板的端口号推测宿主映射端口。
- 把所有已映射端口都发布，而不检查其是否属于允许的访问绑定。

### 8.3 不新增 Runtime 快照的前提

复用当前 `ActiveRuntimeDefinitionConflict` 规则，并在真实 PostgreSQL 测试中证明：

- 模板技术更新与 Player/Practice/AWDP/管理员/TemplateTest 的 Start、Reset 使用一致的临界区规则。
- 不会出现更新检查完“无活动实例”后，旧定义实例并发落库、随后新定义提交的窗口。
- GitOps 等其他入口不能绕过该规则。

如果前提不成立，先对齐现有锁与事务，而不是持久化一份定义快照绕过项目规范。此项为实施门禁，不是本轮已经完成的全路径证明。

### 8.4 历史与特殊数据

- 历史 Running 实例只有在 Runner 归属、receipt、PublishedPorts、当前绑定与真实容器一致时才可纳入发布。
- 不能证明一致的实例保留直连；公网返回 `RuntimeBindingUnavailable`，管理员可在合适时机主动重置，不自动打断题目。
- 模板硬编码 IP、完全没有可替换主机且该文案依赖直连地址时，显示“当前访问文案不支持公网转换”，不改题面内容。
- 多个文案引用同一逻辑端口，只创建一个转发。
- 返回范围继续服从 Team/Participants 等业务权限；未知类型拒绝发布。
- 当前参与者 URL 过滤仍有按索引处理的代码。公网发布不能复制这种索引假设，应按实际绑定建立对应并补测试，避免接口返回了不该公开的目标。

## 9. 发布控制与生命周期

### 9.1 公开资格：全部满足才允许

运行态至少同时满足：

1. 网关策略启用，Connector 已配对并通过预检。
2. Runtime 属于配置的 Runner 和受支持的 Provider/Kind。
3. State 为 Running，且未处于逻辑过期、停止或撤销范围。
4. Purpose 明确在允许集合内；未知值默认拒绝。
5. 不是 AWDP 验证 Target、Checker、内部 Callback、后台作业或默认排除的 TemplateTest。
6. 真实 provider resource 身份与 Runtime UUID、receipt、Runner 匹配。
7. 服务端口确实由该资源发布，且属于允许输出的技术绑定。
8. 公网端口位于部署批准集合，未与既有服务冲突，未超过限额。
9. 本地撤销边界已建立，不能只建立远端 FRP 代理。

第一版固定公开端口等于 Docker HostPort，以减少状态和端口分配器复杂度。发生冲突时该端点标记不可用；不抢占跳板端口，不重启容器碰运气，不改变 Docker 随机端口规则。

同端口方案有明确前提：跳板可使用的端口集合足够覆盖预期 Docker 随机端口。若测试环境无法满足而导致高比例失败，应另行设计独立公网端口分配，不把这种限制隐藏成偶发错误。

### 9.2 创建流程

1. 原有 Runtime 启动、Flag 注入、receipt 写回流程照常执行。
2. 权威 Running 事实提交后发出轻量的公网同步通知。
3. Connector/本机协调逻辑重读当前事实，校验实际身份与公开资格。
4. 先建立本地身份约束，再注册该实例的 FRP 代理。
5. 注册确认及本地规则均有效后回报 Ready；在此之前 UI 显示“公网连接准备中”。
6. 失败仅影响公网连接状态，不能回写 `RuntimeState.Failed` 或 `GameplayFact.PlatformFailed`。

不能由浏览器打开页面触发创建代理。页面访问只能读取状态。

### 9.3 停止、重置和关闭

必须遵循：先禁止该发布继续建立连接，再释放其本机端口，最后完成远端清理。

```text
请求停止/撤销
  -> 本地停止接受该发布的新连接，并按策略关闭旧连接
  -> 确认其不可能再拨到可被复用的宿主端口
  -> 允许原有 Docker 销毁/端口释放流程继续
  -> 幂等删除远端代理并回收公网发布状态
```

不得等比赛 GameplayFact 完成后才撤销，不得把前端隐藏地址当成撤销成功。

Reset 的新实例使用新 UUID；旧消息只能删除旧发布，不能覆盖新实例。关闭整个功能时遍历并撤销本功能拥有的发布，不停止题目、不删除非 NoCTF 代理。

### 9.4 事件、幂等与恢复

- 沿用现有 Wolverine/PostgreSQL durable inbox/outbox；不为该功能恢复旧的 NATS 业务队列模型。
- 公网同步使用独立、有界的处理能力，不能排在 Fix 长任务队列里相互阻塞。
- 不给 `RuntimeProvisioned` 等核心消息新增会抢走原消息的竞争消费者；必要时由原处理流程发显式 fan-out 通知。
- 通知携带身份，不携带“必须无条件创建”的过期指令；执行时重读最新事实。
- 可重复创建/删除的单位是实例与逻辑端点。若同一实例重建发布，可用外部发布唯一 ID 区分新旧资源；它是外部资源身份，不是数据库并发版本。
- 设置更新、Runtime 变化、Connector 重连触发对账；合并同一实例的重复请求。
- 对账只处理配对 Runner 的活动 Runtime，分页且有上限。补偿周期采用现有调度规范，不新增持久化 next-run 或全表频繁轮询。
- 配置失效、无法确认当前权限或进程启动初期时，不自动信任旧磁盘映射。
- 日常关闭后的幂等清理可继续短暂执行；清理完成后停止所有该功能的扫描和刷新任务。

FRP 官方动态 Store 支持运行时变更，也会在重启后自动恢复持久化条目。因此必须在重启策略中主动解决旧条目恢复问题，不能把它当成平台事实：[FRP 动态管理说明](https://gofrp.org/en/docs/features/common/ui/)。具体版本和 API 在实施时固定并验证。

## 10. P0 安全门禁：端口复用与撤销

### 10.1 必须防住的失败序列

1. Runtime A 占用宿主端口 P，跳板公开端口 P 转给 A。
2. A 被停止或清理，宿主端口 P 被释放。
3. Runtime B 或非 NoCTF 服务取得 P。
4. A 的旧代理因延迟、断线或重启恢复仍存在。
5. 访问旧地址时实际连到了 B。

只把刷新周期改成 1 秒仍有错误窗口；仅验证注册时的 Docker 标签也不够。公网显示地址已删除，同样不能阻止知道旧地址的人连接。

### 10.2 必须满足的不变量

- 旧发布不能因目标宿主端口重新分配而自动获得新目标。
- 销毁与撤销之间存在本地可验证的顺序，不依赖公网 ACK 才能保护本机端口。
- 组件重启默认拒绝旧发布，确认真实身份后才能恢复。
- 删除操作按发布身份而非裸端口删除，迟到删除不能误删新发布。
- Connector 失联时，只有其自身拥有的题目公网数据面允许被隔离；不能杀掉既有共享 FRP/反代进程。
- 所有可能释放端口的正常路径都经过同一安全边界：Stop、Reset、TTL、比赛清理、强制终止、孤儿清理、失败回滚。

### 10.3 推荐的验证路线，而非未经验证的保证

先验证“本地撤销 + 端口释放协同”能否用所选 FRP 版本和独立进程监督可靠实现。对远端网络故障不得无限等待；对本地组件不可控也不得假报撤销完成。

若普通 `frpc -> localIP:HostPort` 方案无法满足上述不变量，可验证实例专属、不复用的本地连接入口，例如：

- 为每个发布建立只属于其唯一身份的本地 Unix socket；
- FRP 连接该入口，独立的本地数据面组件才可连接已批准的 Docker HostPort；
- 撤销时关闭入口与关联连接，新 Runtime 永不继承旧 socket 路径；
- 该组件不嵌入 API/Worker/Runner 的消息处理或 HTTP 请求，不取得通用 Docker 管理权限。

FRP 支持 Unix socket 转发，但不提供上述 NoCTF 身份与撤销语义；这只是一个需要测量额外开销并验证的候选实现：[FRP Unix socket 能力](https://gofrp.org/en/docs/examples/unix-domain-socket/)。绝对禁止把 Docker 管理 socket 当作转发目标。

实例专属入口本身仍不能自动解决目标被绕过平台删除的竞态；必须结合受控生命周期。不得据此宣称拥有容器身份级加密绑定。

### 10.4 管理外销毁与不可同时保证的条件

人工 `docker rm`、宿主重启、Docker daemon 重启和其他管理员直接修改网络，可能绕过平台撤销流程。测试必须覆盖这些情况。

若无法证明这类情况下旧连接入口及时失效且不会拨到复用端口，则只能选择：

1. 完成可自动失效的、身份绑定的数据面机制；或
2. 将公网 Runtime 的管理外销毁明确列为必须先关闭该 Connector 公网数据面的运维前置操作。

第二种选择必须由用户确认其适用性，不能静默缩小安全承诺。若用户要求任意管理外销毁都安全、平台停止绝不受阻、又不允许增加本地隔离机制，这些条件不能靠普通 FRP 配置同时保证，应报告设计阻塞。

在此门禁通过前，允许完成固定网站访问、UI、契约与离线测试，但禁止把动态题目发布标为生产可用。

## 11. 其他安全边界

### 11.1 传输与凭据

- 隧道使用 TLS 并校验对端身份，优先独立配对凭据和双向认证。
- 不能把“FRP 默认开启 TLS”当成已经校验证书；官方说明默认客户端并不验证服务端证书：[FRP TLS 说明](https://gofrp.org/en/docs/features/common/network/network-tls/)。
- 不复用 1Panel 网站私钥作为通用 Connector 身份，不读取或输出其私钥内容。
- FRP 管理界面仅本地/受限管理网络可达，不挂到公网网站路径，不启用公开匿名 Dashboard。
- 跳板不持有平台数据库、Redis、对象存储、Flag、注册邮件或 Runner Docker 凭据。
- Connector 配对权限只允许自己的 Runner 与批准端口；平台管理员 UI 不允许配置任意 SSH 命令、脚本或网络扫描目标。

### 11.2 端口与内网访问

- FRP 配置使用允许端口集合和连接/端口上限；不能开放 `1–65535` 并依赖“大家不去访问”。相关能力需按固定版本配置：[FRP 服务端配置](https://gofrp.org/en/docs/reference/server-configures/)。
- 目标只来自平台确认的实际发布端口，不接受调用方传入任意 localIP/localPort。
- 不对公网开放 PostgreSQL、Redis、1Panel、Docker API、Runner 内部回调、FRP 控制台或 Registry 管理接口。
- 不给跳板提供通向整个内网的默认路由，也不部署通用代理插件。
- 仅挂载 `docker.sock:ro` 并不使 Docker API 变成只读；FRP 和普通 Connector 不挂载该 socket。
- Docker 端口发布有独立网络可达性语义，不能只凭 UFW/表面监听判断暴露范围：[Docker 端口发布说明](https://docs.docker.com/engine/network/port-publishing/)。不修改共享 Docker 防火墙链来“快速修好”。

### 11.3 公开端口不是队伍级认证

平台鉴权能限制“谁可获得地址”，但普通公开 TCP 端口不能识别 NoCTF 登录用户。其他人知道地址后可能连接，这是公开比赛题目服务的固有边界。

如需严格保证只有所属队伍可建立 TCP 连接，必须另行设计客户端认证、VPN 或应用层凭据；不能声称 Team 可见性等于网络隔离。本期保留平台现有语义，不秘密引入客户端要求。

公网到跳板的原始 `nc` 流量不因 FRP 内部 TLS 而自动端到端加密。题目协议如需公网段保密，应由题目服务提供 TLS 或单独协商传输要求。

## 12. 失败状态与前端文案

| 稳定失败码建议 | 玩家提示 | 管理员诊断信息 |
| --- | --- | --- |
| `GatewayDisabled` | 公网访问已关闭 | 当前策略关闭，内网实例不受影响 |
| `ConnectorOffline` | 公网连接暂不可用 | 已配对节点失联、最后确认时间 |
| `PublicPortUnavailable` | 此端口暂时无法通过公网连接 | 端口冲突或不在允许集合，不能泄露其他服务配置 |
| `RuntimeBindingUnavailable` | 当前实例无法生成公网连接 | 缺失/不匹配的逻辑绑定及 Runtime ID |
| `UnsupportedRuntimeKind` | 当前运行类型尚不支持公网连接 | 未通过验证的 Provider/Kind |
| `AccessDisplayUnsupported` | 当前连接文案不支持公网转换 | 硬编码地址或无法识别的绑定 |
| `GatewayCapacityExceeded` | 公网连接容量已满 | 已发布端口数、批准上限 |
| `GatewayIdentityRejected` | 公网连接暂不可用 | 配对/身份校验失败，不输出密钥 |
| `GatewaySafetyCheckFailed` | 公网连接未启用，请联系管理员 | 撤销/端口归属门禁未通过 |
| `GatewayReconciliationPending` | 公网连接准备中 | 当前等待阶段、下次手动诊断入口 |

前端继续显示 Runtime 的真实状态。例如“容器运行中；公网连接暂不可用”，不能把一个状态覆盖另一个状态。

现有刷新机制应在公网就绪/失败时自动重读并更新地址；不要要求用户必须手动刷新整页，也不要在浏览器中轮询 frpc。

操作结果需明确区分：保存失败、保存成功待应用、应用失败、应用成功。状态变化在管理页可见，日常成功事件不重复弹窗轰炸。

## 13. 性能预算与验收方法

以下是实施目标和建议初始预算，不是本轮实测数据，也不是必须直接照抄的生产参数。

### 13.1 热路径约束

| 场景 | 必须满足 |
| --- | --- |
| 未配置/关闭且清理完成 | 不启动题目发布相关的 FRP 组件、网关扫描或定时刷新；独立的网站固定隧道不受此开关影响；现有 API 不增加网关网络请求 |
| 内网访问 | 不经过公网数据面；不等待 Connector；不新增逐实例外部调用 |
| 公网读取已就绪地址 | 同一次已授权读取取得所需事实，使用本地缓存/快照投影；不访问 Docker/FRP/DNS |
| 启动题目 | 原有 Running 写回不等待远端隧道；公网同步独立且有界 |
| 停止已公开题目 | 必要的本地撤销遵守短时预算；不得因公网网络超时阻塞评测队列 |
| 选手 TCP 数据 | 不进入 API/Worker/Runner 的 HTTP/消息处理和数据库 |
| 管理状态页 | 读聚合状态和分页失败项；不把 Dashboard 全量查询放入页面请求 |

### 13.2 建议初始预算

- 同步通知按 Runtime 合并，初始合并窗口可用 500 ms；这不是安全撤销延迟。
- 专属控制面初始并发建议 2，队列必须有明确上限；积压时报告降级，不能无限分配任务。
- 健康网络下，从 Running 事实提交到公网 Ready 的目标 P95 不超过 3 秒。
- 本地撤销确认目标不超过 1 秒；超时进入明确的安全降级路径，不能“超时后默认继续公开”。
- 对账使用启动/重连事件和低频补偿，补偿周期可从 30 秒验证；安全正确性不得依赖该周期。
- 每个进程的 CPU、RSS、连接数、带宽上限由只读盘点后的空闲资源决定；不得直接套用较大固定额度抢占跳板原业务。

### 13.3 测量与通过条件

测试前固定代码版本、测试数据、并发模型和资源限制，分别采集：

1. 功能关闭基线。
2. 功能启用但没有公网流量。
3. 预计比赛并发量的公网连接与平台流量。
4. 受控的短时双倍连接量；不能在共享跳板直接打满带宽或制造 DDoS。
5. Connector 断线、重连、状态积压和端口快速创建/删除。

每组至少重复 3 次，比较 API P50/P95/P99、错误率、Flag/Fix 队列延迟、CPU、RSS、GC、网卡带宽与原有服务探针。吞吐测试应使用专属无业务副作用的测试题目，不写入真实赛事分数。

建议验收线：关闭/启用空闲两组的 API P95 与核心队列延迟不得出现超过测量噪声的持续退化，初始审查阈值为 5%；负载组不得出现原有服务错误、超时明显增加或资源上限失控。阈值应在基线测量后记录，不能事后为通过而任意放宽。

不满足时先限制公网数据面负载或安排独立资源，不能通过提高 Fix 超时、放宽队列健康条件掩盖影响。若用户要求物理资源意义的零干扰，需要专属资源，不能仅靠进程分离保证。

不部署 Prometheus/exporter 来满足本功能验收；使用现有日志、受限状态接口与临时采样，采样结束后停止。

## 14. 跳板与测试服务器部署计划

### 14.1 第一步仅做只读盘点

主 agent 应记录：

- 两台服务器身份、现有服务和监听端口。
- `challenge.fa1lsnow.com` 实际 DNS、TLS 证书状态和站点配置归属。
- OpenResty 是宿主进程、host-network 容器还是 bridge-network 容器。
- 当前站点上游、有效 Host/forwarded headers/WebSocket 设置。
- `1panel-network` 的 ID、网段、已连接容器和既有 aliases。
- 是否已有 FRP 及其归属；不得接管他人使用的 FRP 配置。
- 两端可用于本功能的资源、端口、目录以及云安全组限制。

只记录与本功能相关的元数据，不导出其他站点密钥、环境变量、数据库密码或完整敏感配置。

### 14.2 上游选择规则

当前不能给出最终 `proxy_pass` 数值，因为尚未核实部署拓扑。

| 实际拓扑 | 合理上游候选 | 前提 |
| --- | --- | --- |
| OpenResty 可直接访问宿主回环 | 绑定回环的网站隧道端口 | 确认不是容器自己的 loopback |
| OpenResty 与隧道组件已有共同网络 | 经批准的专属 alias + 内部网站端口 | 不修改既有 aliases；新增成员需列入实施范围 |
| OpenResty 处于不同网络 | 已验证的受限可达地址 | 不能为图方便让网站落点公开监听所有接口 |

禁止直接把上游填成“猜测的 localhost:端口”。网站隧道使用独立的 HTTP/受限监听能力，题目 TCP 使用批准的公开监听能力；不能因 FRP 的统一监听默认值误把网站落点公开。

网站测试不能简单把跳板反代到测试服务器的现有公网 URL，然后宣称已验证内网穿透；应真实经过计划中的隧道上游。

### 14.3 部署产物边界

- 以独立、默认不启动的部署清单交付，不改现有默认 Compose 使全部部署强制依赖跳板。
- 使用 CI 构建的 NoCTF 镜像；FRP 固定审核过的版本与 digest，不使用漂移的 latest。
- 如需持久文件，采用专属目录 bind mount，环境参数在专属 `.env`，不覆盖平台现有 `.env`。
- 健康检查若构建新组件镜像，放入其 Dockerfile；不把跳板状态变为平台全局 readiness 的硬依赖。
- 不新增 exporter、迁移容器、任意 tmpfs/cap/group-add/security-opt/read-only 等与本方案无直接依据的配置。
- 不修改默认 Runtime 网络与题目 Docker 随机映射机制。
- 如需新监听或 FRP 容器发布端口，必须明确这是公网跳板数据面的必要新增范围，由主 agent 按授权落实；不能顺带给平台数据库等服务 expose/ports。

### 14.4 既有站点唯一允许的变更

1. 保存该站点当前反代上游及可恢复配置副本，不备份/复制其他站点秘密。
2. 从 OpenResty 实际所在网络验证目标上游可达。
3. 通过 1Panel 支持的配置管理路径仅修改该站点上游，防止手改生成文件被面板覆盖。
4. 执行配置语法校验；失败则不生效。
5. 使用经确认的平滑加载方式，不重启整个 1Panel/OpenResty 服务。
6. 验证该站点并抽检既有服务；网络 ID、现有容器与证书保持不变。

Nginx 文档描述了 reload 时保留旧连接的机制，但不是零风险承诺：[Nginx 配置加载说明](https://nginx.org/en/docs/control.html)。若既有配置本身有无关错误导致无法校验，不顺手修复其他站点，应报告阻塞。

### 14.5 回滚

- 恢复本次记录的该站点原上游，并校验后平滑加载。
- 关闭 NoCTF 题目公网发布，确认本地撤销完成。
- 仅删除本次创建且身份清单匹配的代理、专属组件和临时测试资源。
- 不运行全局 Docker prune、Compose down -v、删除网络、清空防火墙或删除共享目录。
- 不因回滚显示功能执行破坏性数据库降级；默认保留新增设置列并关闭功能。
- 若主 agent 后续获准部署生产，必须另行手动执行；CI 不部署生产。

### 15.3 两台服务器上的端到端测试

1. 通过现有证书正常打开 `https://challenge.fa1lsnow.com`，不关闭证书校验。
2. 登录、刷新多次、令牌刷新、登出、重新登录正常。
3. 普通选手查看题面、附件、Hint、提交 Flag；状态自动刷新。
4. Patch 上传、较大附件下载、SignalR 消息在隧道中正常。
5. 从公网使用页面给出的命令连接测试题目；从直连入口获取原主机地址并连接。
6. 停止/Reset 后旧代理失效，新代理对应新实例。
7. 断开仅本次测试的隧道，确认内网访问、Checker 和评测照常工作。
8. 恢复隧道后自行对账，不要求选手必须刷新整页。
9. 测试前后检查既有站点响应、服务状态、证书、端口与 `1panel-network` 不变。

## 16. 主 agent 实施切分与交付物

### 阶段 A：安全原型，先决定能不能上线

### 阶段 B：后端与配置

交付：平台管理员设置、EF 生成迁移、强类型契约、原授权后的地址投影、独立公网状态、消息与缓存整合、本地撤销协同。

实施落点优先：

- `Domain/Platform`：持久设置与有限枚举。
- `Application/Administration/PlatformConfiguration`：管理员用例。
- `Application/Runtime`：窄职责的访问投影与发布决策。
- `Infrastructure/Administration`、`Infrastructure/Runtime`：现有数据库/缓存适配。
- `API/Endpoints/Administration/Platform`、现有 Runtime endpoints：传输契约。
- `Runner/Messages` 与实际资源销毁边界：必要的身份确认及撤销协调。

以上是功能归属，不要求照单创建大量接口/目录。不要新增通用 Services、Helpers、Models 转储层。

### 阶段 C：前端

交付：平台“公网访问”管理表单、诊断状态、Runtime 独立连接状态、自动刷新、错误本地化；同步生成 API 类型。

### 阶段 D：独立部署与联合验证

交付：固定镜像/版本的可选部署清单、配对说明、端口预算、站点单项变更、回滚清单、两机测试报告和性能对比。

优先按后端、前端、部署文档/测试辅助分别组织可审阅提交；每个提交保持可理解，不夹带其他任务改动。是否提交、推送、部署由主 agent 按当前用户授权执行，不由本设计文档自动触发。

## 18. 完成定义

只有同时满足以下条件，才可以向用户报告“可选公网跳板功能完成”：

- 默认关闭、无跳板部署继续正常使用。
- 管理员可配置日常策略，无需进入 Runner 容器手改 PublicHost。
- 公网平台与获准题目连接端到端通过，内网地址选择正确。
- Checker/验证 Target/平台基础设施没有新增公网暴露。
- 端口撤销、复用、消息重投和重启恢复的安全测试通过。
- 不把公网故障改写为题目平台错误，不改变已有计分语义。
- 性能数据满足约定预算，跳板原有业务和 `1panel-network` 未被破坏。
- 设置持久化、关闭、升级和回滚都有验证记录。
- 未支持的模式、管理外操作边界和公网 TCP 非身份认证属性已明确告知。

不能仅凭网站首页返回 200、后台出现 Ready、或者一次 `nc` 成功就认定设计目标全部达成。
