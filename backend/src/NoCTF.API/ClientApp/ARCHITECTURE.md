# 前端架构与本轮审计

## 分层契约

```text
pages / layouts / app.vue
  → features/<领域>/<Name>.vue        组合入口、props/emits/model
      → use<Name>.ts                 业务状态、API、校验、命令、订阅
      → components/views/**View.vue  渲染契约、绑定、事件转发
          → components/ui/**         共享交互原语
locales/zh-CN.ts + locales/en.ts       稳定 key、双语文案
```

视图的运行时依赖仅限 Vue。功能组件显式导入对应 View；View 可以引用控制器导出的 **类型**，不会加载控制器。子功能作为组件值传入 View，由功能入口拥有实例和生命周期，避免 Nuxt 自动导入掩盖业务依赖。只有 UI 原语自动导入。

`bindViewState` 只解包最外层 ref。表单通过 v-model 连接功能层拥有的模型；命令处理器负责额外转换、状态切换和业务操作。嵌套注入上下文中的 ref 保持不变，避免排行榜和竞赛上下文因递归解包失效。模板 ref 通过功能层回调连接；文件选择器回调取原生 `$el`，组件 ref 保留其公开方法。

普通布局元素（div、section、header、列表、文本、SVG、canvas）可以留在视图。按钮、输入框、文件选择器、表格、弹层等交互语义必须使用集中原语。原语允许实现密码显隐、键盘导航、焦点管理、受控输入、Markdown 渲染、图表挂载等通用展示行为；不得取业务数据或访问权限/会话。

## i18n

- 中文和英文使用相同的稳定 key。静态代码可使用类型约束的 `t(MessageKey)`；模板 `$t` 的字面量 key 由架构检查验证。
- 标签配置保存 key，在 render/computed 中翻译。修改文案只改资源值。
- placeholder、title、aria-label、alt、默认标签与错误反馈都属于文案。
- `$message` 将已知 API/客户端反馈在当前语种显示；未知文本保持不变，不把用户输入当翻译 key。
- 品牌名称、用户题目标题、队伍名和用户内容来自数据；协议枚举、路由、标识符和 CSS token 不属于文案。

## 审计结果与调整

1. 原有 i18n 使用中文原文作为 key，缺乏稳定标识；现有资源与调用已迁移为稳定 key，并补齐遗漏的英文和辅助文案。
2. 页面、业务组件混合取数、状态与渲染。51 个路由及其他组件/壳共 112 个入口已拆分为功能控制器、组合入口和 View。
3. 9 个通用控件从业务目录集中到 UI 原语目录；自行实现的按钮、文件输入、标签和外链改为共享控件。
4. 模板中的赋值、开关弹层、筛选重置和单位转换处理器迁入功能控制器；保留声明式表单绑定。
5. 组件目录内的非渲染业务工具迁入对应功能目录；路由元数据留在 Nuxt 路由文件。
6. 修复拆分涉及的异步初始化上下文、原生文件输入 ref、嵌套 ref 和延迟图表组件连接；更新已有源码契约测试以读取实际组成文件。
7. 修正通知容器的注册名称，并通过 shadcn-vue CLI 补齐管理页使用的 Collapsible 原语。检查所有视图的组件名，禁止引用未注册或未传入的组件。

## 防回退检查

`bun run audit:architecture` 与 `tests/architecture.test.ts` 对现有和新增文件使用同一规则，不设历史违规豁免。`build` 和 `generate` 也会先执行此检查，违规时停止构建。它们检查 SFC 语法、硬编码模板/辅助文案、中文字面量、无效资源 key、两种语言的 key/插值一致性、原生交互控件和渲染层业务代码。`tests/view-state.test.ts` 检查功能命令、表单模型与嵌套响应式上下文的连接行为。

自动扫描不能识别所有语义：例如协议字符串被误用为文案、复杂模板表达式的业务含义，以及服务端返回的任意文本。评审仍须检查新文案是否进入资源表、新逻辑是否属于控制器。新增业务交互优先补行为测试，不依赖源码字符串检查证明真实后端行为。

验证命令：`bun run audit:architecture`、`bun test`、`bun run typecheck`、`bun run generate`。浏览器检查覆盖当前本地预览下的首页与语言切换；真实后端写操作需在相应集成环境验证。
